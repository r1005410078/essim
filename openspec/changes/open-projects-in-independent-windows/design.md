## Context

现有桌面组装只创建一个 WorkspaceEngine，BatchCoordinator、ProjectSession、Subscriptions、PointFileJobs 和 ExitPermission 均为应用级状态。ProjectAccess 从应用状态取得引擎，菜单与退出事件硬编码发送到 main。工程 session 能拒绝旧请求，但不能独立证明调用来自哪个窗口。仅创建第二个 WebView 会共享工程并带来串写风险。

当前工程文件锁、保存／应用边界和后台核心实现已有回归，应复用而不是重写。用户已确认新窗口为默认、已打开工程直接激活。上一轮启动页固定尺寸及插画修正尚未提交，本提案不覆盖这些改动。

## Goals / Non-Goals

**Goals:** 同进程多工程并行；每个工程唯一窗口；完整命令、任务及事件隔离；单窗口关闭不停止其他工程；退出全应用安全；不改变工程格式。

**Non-Goals:** 多进程隔离、同工程多窗口编辑、恢复全部窗口、跨工程复制／拖放、全局运行监控、协议扩展、通用插件框架和应用日志实现。进程崩溃仍影响所有窗口，不宣称进程级故障隔离。

## Decisions

### 1. 以原生窗口身份寻址工程上下文

Tauri 组装层建立进程级 WindowRegistry，窗口使用稳定且唯一的动态 label（不直接拼接用户路径）。每项持有窗口状态及 Arc<ProjectContext>；上下文包含 Engine、批任务协调器、工程准备状态、任务与订阅注册表、退出保护、窗口边界。引导窗口无可编辑工程。core 与 infrastructure 不依赖窗口类型。

IPC 由 Tauri 注入的实际 WebView label 查上下文，再验证 projectSession 并获取现有请求租约；不信任请求体自报窗口 label。所有业务 IPC 使用同一解析入口，工程管理、文件读写、订阅取消及导入取消同样验证归属，不能仅迁移 execute_workspace。响应和推送只到所属窗口；相同资源 ID／任务 token 也不得跨上下文查询、取消或释放。

注册表锁只用于查找、预约和状态发布，不跨 await、系统选择器、磁盘加载、协议停机或窗口操作持有。关闭时上下文标记 closing，拒绝新业务请求；既有租约、任务和线程回收后才释放资源。销毁事件有幂等兜底，异常 WebView 销毁仅清理自身。

替代方案“一个全局引擎按前台窗口切换”无法支持并行通信；多进程虽隔离更强，但不符合本轮确认方案。

### 2. 默认打开语义和唯一性

有工程窗口：打开／新建／最近均默认请求新工程窗口；目标打开失败或用户取消，不创建可编辑空壳、不停止源工程。引导窗口：成功打开目标后承载该工程，避免留下多余启动窗口。显式菜单“在当前窗口打开工程”保留现有保护流程，不另加默认确认弹框。

注册表以存在的 project.workspace 规范路径作为键，解析相对路径与符号链接，平台路径比较规则需验证；同 ID 不同目录副本可分别打开。发布前再次核对占用：opening 预约使并发同路径请求复用同一打开任务；open 则恢复已最小化窗口、显示并聚焦；closing 不重复开，反馈正在关闭，可完成后重试。打开不同路径仍复用磁盘锁，其他进程占用按原错误反馈。硬链接别名若平台无法可靠识别，不绕过底层文件锁。

加载与持锁、准备前端状态、创建隐藏窗口、完成就绪握手后显示并发布 open。失败撤销预约、销毁新壳并释放锁，不遗留后台运行。新建用规范空目录预约，创建后映射到入口；同目录并发新建只允许一个执行，不为失败的新建自动删除已创建文件。

当前窗口显式打开一个已在别处打开的工程，只激活目标窗口，源窗口及草稿、通信不变；重复当前路径同样不重载。新打开的工程默认不启动通信。

### 3. 菜单、权限和窗口模式

动态窗口 label 纳入受控 capability 范围，仍保持最小窗口 API 权限。全局原生菜单保存／编辑／工程操作依据实际聚焦业务窗口路由；应用失焦保留最后活动且仍存活的窗口，无目标则禁用或无操作，不默认操作 main。应用退出单独路由全局协调器。

每窗口顶部显示自身工程名，布局、草稿和 Dockview 存于对应工程；项目命令保留统一适配层。引导窗口固定 960×720（小屏适配），工程窗口可缩放；关闭工程回引导时只调整该窗口。动态窗口不硬编码为 main，避免订阅及原生菜单仍落到旧窗口。

### 4. 关闭窗口与退出应用分开

关闭工程：保护并停止当前工程、刷新记录、释放锁，当前窗口转为引导。关闭窗口：同一保护完成后只销毁当前窗口。其他工程监听和任务不受影响；任一失败保留可访问窗口并显示错误。最后一个窗口关闭完成后正常退出应用，不隐式重开最近工程。

退出应用采用进程级唯一退出事务：冻结新开／切换／启动操作，收集窗口草稿与忙碌状态，依次在有需要的窗口中使用公共 WorkbenchDialog 确认并暂存草稿；全部确认后才开始停机和记录刷新。取消确认解除门禁，未进入停机；失败不设置全局允许退出标记，保留窗口与错误。若停机阶段部分成功后失败，已停止工程保持停止，不自动重启。重复 Cmd+Q／关闭请求加入同一协调过程，不重复弹框或重复停机。普通关闭在全局退出期间由该协调器接管。

项目数据保护不能依赖前端一定响应；崩溃／无响应窗口不得被当作已确认，提供错误并保留后端上下文，正常路径不强制退出。

### 5. 最近列表和启动恢复

进程内只有一个 RecentProject 设置服务，串行更新文件并广播 recent-changed 通知；每个窗口刷新列表，但不重挂载业务。列表最多十项、路径去重，不改变工程文件格式。

启动只恢复 lastOpened 的一个工程，无效则显示引导及错误。新窗口就绪或用户聚焦工程窗口后更新活动恢复入口；已打开项被再次选择也更新列表成功时间。关闭当前恢复目标时优先选择仍打开的最近活动工程，若无则置空；关闭非目标窗口不清空其他恢复目标。全应用正常退出保留最后活动工程路径，不因按顺序关闭上下文而写成 null。退出时引导窗口不覆盖最近活动工程。移出最近列表仍仅改设置，不关闭窗口、不删除文件。

### 6. 通信和资源隔离边界

独立工程使用各自 Engine、记录根目录及 SQLite。允许不同工程同时运行，不将端点 ID 当全局唯一。操作系统监听端口、串口设备仍是共享资源：第二工程占用失败时只反馈自身错误，第一工程继续工作；不自动改端口、断开他人连接或顺手停止其他工程。

## Risks / Trade-offs

- [遗漏全局状态导致串数据] → 实施前列出全部 IPC／任务／事件归属矩阵，测试相同 ID、伪造 session 与跨窗取消。
- [并发打开重复持锁／死锁] → 短锁预约、单路径打开任务、失败清理与并发测试。
- [关窗早于后台清理] → closing 门禁、请求租约和任务 join，窗口销毁幂等兜底。
- [全应用退出部分停机失败] → 所有确认前不停止，失败保留可操作窗口并如实展示停止状态。
- [共享菜单焦点与最近设置竞态] → 进程统一协调及原生多窗交替操作验收。
- [同进程内存增加] → 窗口关闭后验证订阅、线程、句柄及工程锁释放，不承诺未经测量的最大窗口数。

## Migration Plan

先用测试建立窗口注册及 IPC 路由契约，再迁移现有单窗口到注册表，原功能通过后接动态打开和退出协调。工程文件无需迁移，本机 recent 格式沿用；上一轮单窗口验收保留历史适用边界，实施时修订旧活跃提案默认打开语义。回退代码仍可逐个打开工程，不更改工程格式；不在本提案执行回退或提交代码。

## Open Questions

本轮无阻塞产品问题。原生多窗焦点、最小化激活与系统关闭行为必须在目标平台验收，未验证平台明确记录，不由浏览器测试替代。
