## Context

当前 `useProjectPersistence` 依赖工作台 view 和 Dockview 已初始化后才查询工程，启动无工程仍创建可编辑内存会话。`create_project` 会复制当前 catalog；关闭工程回到 MemoryRepository。最近设置只有一个入口。已确认的[设计稿](assets/project-entry-design.png)改为工程启动中心和三组标题栏，要求正式客户端必须绑定工程。

设计稿中的点表、协议示例值仅是视觉示意，不改实际协议地址规则、图标语义或其他工作台布局。只实施启动页和顶部布局，不照搬生成图中额外的“四遥”日志标签或非现有属性图标。

## Goals / Non-Goals

**Goals:** 无工程不能使用工作台；启动前完成工程判定；明确打开／新建／最近／关闭路径；保护现有草稿和运行任务；保留工程数据格式与独立应用快照。

**Non-Goals:** 多窗口工程管理、后台多工程同时运行、另存／克隆工程、任意单文件工作台、工程版本管理、协议能力扩展、应用日志实现和全盘工程扫描。浏览器预览不提供可编辑临时会话。

## Decisions

### 1. 独立工程入口状态，不依赖 Dockview

前端根部先查询工程状态，分为 checking、launcher、opening、workspace、switching／closing。checking 显示轻量加载；launcher 只挂载启动页，不创建 Dockview、WorkspaceStore 业务订阅、协议轮询、资源命令或草稿计时器。最近工程成功恢复并有有效 session 后才挂载工作台，然后恢复该工程布局与草稿。

启动恢复失败保留明确原因，回到 launcher；取消选择也留在原页面。未打开工程时不显示临时会话文字，不允许通过菜单／快捷键进入业务创建。内置帮助、窗口操作、退出及工程入口可用；浏览器无桌面后端显示需桌面打开工程的说明，允许视觉预览而不伪装文件成功。

替代方案“隐藏树但仍初始化业务”不能保证门禁，也容易恢复旧状态；因此拆开入口和工作台生命周期。

### 2. 后端同时执行门禁

正式桌面初始化选择 required-project 策略，启动前内部空仓储仅作待机载体，不对用户开放。无当前工程时，配置读写、资源创建／删除／导入、应用、分组、运行和批任务等业务 IPC 统一返回 PROJECT_REQUIRED；工程状态、最近列表、系统选择器、窗口和退出不受阻。门禁检查与实际执行在同一工程生命周期同步范围内，禁止只在 IPC 前读一次布尔值，避免关闭与命令竞态。

现有 session 令牌继续隔离旧前端异步请求；切换期间拒绝新业务写入和启动，等待／取消既有操作按现有协调器约束执行。实施中列出所有业务 IPC 的覆盖表，不能只保护创建按钮。core 的 MemoryRepository、无界面执行器和测试仍按显式非桌面策略可用，不把工程磁盘依赖推入核心。

### 3. 新建空工程，打开现有入口

启动页的打开工程直接进入原生文件选择器，选择 `project.workspace`；新建直接选择空文件夹，沿用目录名作为工程默认显示名，写入有效空清单成功后才进入工作台。选择取消、目录非空、不可写、文件损坏、占用／未来格式等不改变当前状态，不默认选临时目录。

从已有工程新建也创建空 catalog，不复制模型、模拟器、文档或实时值；当前复制 catalog 的行为须改为明确空工程创建路径。复制／导出已有业务命令不受影响。本轮不增加项目命名弹框。

### 4. 同一窗口切换，失败保留旧工程

本轮默认当前窗口替换工程，符合现有单窗口架构；工程下拉包含当前名称、打开工程、新建工程、最近工程子菜单和关闭工程，所有入口调用同一协调流程。

先选目标、完整预检和锁定，再确认必要的停止与草稿保护。无脏草稿且无运行任务时不加无意义的确认弹框；存在草稿／通信时使用公共 WorkbenchDialog。草稿保存到旧工程恢复区，不自动写成正式资源、不自动应用；必要的配置错误或恢复区不可写会阻止切换。用户取消确认不得停止当前通信。任务忙碌、安全停止或可靠记录刷新失败保留旧工程，不进入“已切换”假状态；已停止的端点如后续步骤失败保持停止，不擅自重启。

目标成功切换后销毁旧树／Tab／订阅／检索索引，再加载目标布局、草稿和文档。状态由后端最终工程 session 决定；不以最近设置写失败伪装切换失败。新工程／已打开工程通信均默认停止。重复打开当前规范路径只激活现有工程，不再拿锁、重复建 Tab 或停止通信。

关闭工程复用保护，释放资源锁，回到 launcher；当前恢复入口置空，但最近列表保留。退出应用则保留当前成功工程作为下次恢复目标。launcher 退出直接关闭，不弹临时会话放弃提示。

### 5. 最近列表与兼容迁移

继续本机 app data 的 `recent-project.json`，增加设置格式标记、lastOpened 及最多 10 条 entries（规范入口绝对路径、上次确认名称和最后成功打开时间）。从旧单路径记录迁移为一条列表；旧文件坏损时提示并显示空列表，不扫描磁盘、不删除工程。

每次打开／创建成功更新并按规范路径去重；同工程 ID 的副本位于不同目录时保留不同项。失败和取消不更新成功时间，恢复失败不偷偷删除条目。显式关闭只清空 lastOpened，保留列表，因此下次显示引导而不是又打开刚关闭工程。最近项可以移出列表，仅改本机设置，不删除工程。列表标题、时间和路径次级显示；点击后由后端重新校验路径、锁及格式，旧显示名不作为权威数据。

### 6. 视觉与窗口行为

启动页左右分区：左侧小标题和工程文件夹／点表／电池线稿，右侧“开始”、打开／新建操作、最近列表。沿用浅灰白、细边框与蓝色强调，不采用大卡片。生成图作为视觉参考，实施时把插画制作成独立无文字资产，中文内容由组件渲染。900×600 可用：降低插画占比或隐藏装饰，列表可滚动、操作可达；最近列表为空时保留打开／新建主入口，不放演示路径或假项目。

已打开工程标题栏：macOS 窗口控件后是最左工程选择器；中间历史后退／前进紧邻检索框；最右集中左导航／右属性／底部面板开关。Windows／Linux 工程选择器同样最左，原有窗口控制按钮仍在最右。历史是文档导航历史，独立于最近工程列表。

交互元素必须 no-drag，空白区域保留窗口拖动和双击行为；工程菜单使用现有菜单组件，hover 描述、键盘导航和 Esc／焦点恢复沿用既有规范。检索框随窗口缩窄收缩，工程名称截断但 tooltip 完整，不与右侧开关／窗口按钮重叠。启动页只保留必要窗口操作，不显示无效面板按钮。

## Risks / Trade-offs

- [去掉临时会话影响旧用例] → 正式桌面强制策略与核心内存测试适配分离；原生仅在自建测试目录验证。
- [旧工程草稿丢失／旧请求污染新工程] → 先可靠暂存，成功后销毁旧前端，继续 session 校验与同步门禁。
- [目标预检锁／停止失败] → 保留旧工程所有权并释放临时目标；停止结果如实展示，不擅自回启。
- [设置写失败与实际打开结果不一致] → 后端当前工程为准、单独显示最近保存失败，不丢已打开状态。
- [顶部拥挤或失去拖动] → 900×600 与多平台原生单独复核，保持控件与 drag 区边界。

## Migration Plan

先增加入口状态和后端策略及失败用例，再迁移最近设置和空工程新建，接入启动页／标题栏。实现时同步更新 `persist-project-files-and-runtime-data` 活跃提案中被取代的临时会话约定，旧测试记录保留为历史，不改写已发生事实。工程清单和资源文件无需迁移，最近设置读取旧单路径向前迁移；不增加配置历史功能。

## Open Questions

本轮采用当前窗口切换，不含另开窗口；若后续需要另开窗口另行提案。不阻塞当前设计。
