## Context

现有 inspector-edge 已是 Dockview right edge，但标题隐藏，仅一个 inspector 面板，在搜索框旁用 PropertyScope 切换。用户确认右侧竖向标签稿，并要求图标下无文字、其他布局不变。

## Goals / Non-Goals

Goals：右侧三个 Dockview 原生标签与对应属性范围，图标具有名称提示和选中态，保留默认 Unit 范围及顶部隐藏／恢复。

Non-Goals：不重绘顶部、左导航、中央 Tabs、底部或点表；不改协议运行、保存、应用及配置格式；不增加配置版本。

## Decisions

- 使用 right edge 的 setHeaderPosition('left')，创建三个稳定 ID 面板，params.scope 固定，各面板复用 InspectorPanel 与共享 PropertyPanel。自定义标签仅渲染图标，标签选中和键盘行为由 Dockview 管理。
- 点使用 ListTree、Unit 使用 Layers、端点使用 Server 图标，title 与 aria-label 提供名称。标签宽28px、高30px；选中使用与内容相同的浅灰底和深色图标，无圆角、蓝色底或边线，与内容连为一体。无关闭按钮。
- 属性搜索留在内容内，各范围仅搜索自己的属性；设备、模型和文档在点范围展示原有上下文属性；模型的Unit／端点范围显示对应当前配置引用入口，无关联时显示明确空态，其他非端点上下文显示范围选择提示。默认选中 Unit，切换不修改 store 的选中 Unit、点或草稿。
- 右侧组保持原有总宽度与停靠位置；移除针对属性面板隐藏整个 header 的旧 CSS，并仅对 inspector-edge 定位竖栏样式。
- 右侧顶部开关使用公开 setEdgeGroupVisible，避免测得竖栏宽度覆盖 collapsedSize 后残留空间。恢复保持原标签与尺寸。
- 三个 inspector 标签均排除在文档历史之外。现有校验定位按字段选择 Unit／端点标签，避免焦点落在隐藏内容。

## Risks / Trade-offs

- 原生竖向标签默认带文字布局 → 仅对该组覆盖样式，保留 Dockview 标签语义。
- 额外标签占用原属性内容宽度 → 保持原总宽度，复用共享面板窄屏退让，不改变其他组初始比例。
- 自动化浏览器无 Rust 后端 → 不造运行数据，端点真实字段与 WebView 验证单独记录边界。

位置修订：属性组仍停靠工作台右侧，三个纯图标标签移到属性内容左边；仅移动该组的标签位置和分隔线，其他布局不变。

## 紧凑版修订

公共 PropertyPanel 增加可选 density="compact"，仅右侧属性区启用。默认模式不变。紧凑模式头部24px、字段行22px、控件20px、分组头22px、分组无外边距。属性内容保留UE两列连续表格：字段名左对齐、细行线和完整列分隔线，控件同列等宽，保留列宽拖动与键盘调整；Blender参考仅用于外侧图标栏。

模型点字段分为点定义、数值解释、访问与采集三个折叠组；编码预览默认折叠。模型名称及引用保持，四遥分类和备注仍不显示。端点／Unit沿用既有业务分组，在相同密度下显示。

窄面板遇到复合控件或长标签允许自然增高，不裁切字段。主题变量在该Dockview组局部设置，使选中标签与属性内容同色；其他工作台组不受影响。
