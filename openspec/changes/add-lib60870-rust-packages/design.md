## Context

现有 libmodbus 三包独立于 ESSim/Tauri。lib60870 同时提供 101／104，104 复用 cs101 应用对象。用户已要求实施相同三包结构，当前不接工作台。

## Goals / Non-Goals

Goals：固定源码、可重复离线构建、唯一原生链接所有者、ASDU RAII、首批 104 服务端与真实通信测试。
Non-Goals：完整上游 API、101 安全通信封装、TLS、安全认证、生产运行调度、工作台与 Tokio 改造。

## Decisions

- src 保存完整官方 v2.4.1 归档与来源校验，构建修改仅发生在 OUT_DIR；默认静态，动态仅接受本构建器产物清单，不搜索系统库。首批拒绝交叉编译与未适配平台。
- sys 是唯一 links=60870 所有者；手写小范围不透明 FFI，与官方头文件一致，并通过编译探针验证 ABI／版本。
- rs 首批提供受校验的应用参数、ASDU／信息对象、104 无线程服务端及作用域内连接响应。句柄 !Send/!Sync；服务端在创建线程 tick，C 回调只同步执行已注册处理器，panic 捕获后转为可查询故障。
- 回调收到的 ASDU/连接仅能在借用作用域使用，需要保留的信息显式克隆。先停止所有连接再释放回调状态和服务端；不提供裸指针到安全 API。
- 所有地址与示例数据注明教学约定；协议业务响应由使用者决定。封装不内置 ESSim 设备、SOC 或自动控制状态机。

- 独立 Examples 使用 `rs` 公开 API，C句柄留在主线程，独立原始字节客户端只持有普通TCP连接；显式限制等待并在失败后停止服务、回收客户端。它是封装测试，不扩展产品级客户端功能。

## Risks / Trade-offs

- GPLv3／商业双许可 → 保留完整许可，记录发布方式待单独确定；不将本轮接入描述为已取得商业授权。
- C 回调重入与 Rust panic → 稳定堆地址、作用域借用、catch_unwind、显式错误状态与测试。
- 无线程不代表严格不阻塞 → 不承诺 tick 时延、规模或实时性；不接 Tokio。
- 上游平台支持不等于已验证 → 先验证 macOS 本机，Linux 构建路径保留未验边界。
