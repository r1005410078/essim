## Context

现有tcp_slave模块拥有映射、运行值、可靠文件、配置应用释放与查询，RTU主站已提供SerialPort独占RAII。正式从站尚未连接RTU运行。

## Goals / Non-Goals

目标：单串口单站真实收发、基础8功能码与权限、停止释放、软件互操作及原生入口。
非目标：多站总线仿真、自动重连、RS485方向控制、协议统计与完整诊断服务、物理时序合规。

## Decisions

- 保留历史tcp_slave目录名，复用固定所有者线程；每个RTU端点持有非阻塞SerialPort和私有RtuResponder。串口读取有界，不使用阻塞modbus_receive卡住其他端点。
- libmodbus在RTU上下文直接生成基础响应和CRC，经私有Unix socket排空后写真实串口；不将TCP帧转换成RTU。共享PDU业务校验，检查权限及完整业务点，再调用C映射。
- 软件缓冲基于已知长度处理基础请求；未知功能等安静边界后拒绝，短帧与CRC错误记录后静默。操作系统合并读取不能证明实际字节时序，PTY不证明严格RTU时序。
- 广播只执行权限合法且结构完整的05/06/0F/10，任何广播不响应；其他站号不执行不响应。
- 串口实际打开且可靠记录已建立才报告运行。发送准备与驱动完整写出分开，不能称远端接收。停止取消未发响应，保留不确定状态，先drop串口再报告停止。
- 07/其他08/0B/0C返回01并保留后续诊断阶段；08/0000通过libmodbus原始发送API生成回送，11使用上游身份（0xB4、FF及LMB版本字符串），不冒充真实设备。

## Risks / Trade-offs

- [驱动差异／读取合并] → 软件场景有界验证，硬件时序单列。
- [输出未完成或记录失败] → 关闭该端点、标记不确定；不自动重发。
- [同串口主从冲突] → 共享SerialPort进程占用表与OS独占；路径别名按已有边界。
- [移除旧占用] → 显式停机／应用／删除复用同一所有者，保留运行值迁移。
