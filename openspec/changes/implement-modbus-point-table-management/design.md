## Context

M01完成34项基础任务，当前`PointDefinition`只有Bool／U16，`initial`为u16、`scale`为f64，前端对应number。`SheetViews`按对象／分类／版本创建InMemoryDataSource，模型字段只读、运行草稿与定义混合展示；模型还没有完整编辑、复制、删除、文件交换和引用定位。M02以[实现地图](../../../docs/plans/modbus-simulator.md)已确认决策为依据，不重新建设协议栈。

## Goals / Non-Goals

**Goals:**

- 完成从树菜单创建／导入模型，经NovaSheet编辑、后端校验、覆盖保存当前模型、查询引用、显式应用配置的会话内闭环。
- 统一主从共用点定义、四遥用途和数据区约束，实现精确数值、编码及迁移规划的可测试纯逻辑。
- 所有确认规则可追溯到规格场景与任务；真实WebView操作留下证据。

**Non-Goals:**

- 不建设SQLite、自动恢复、完整项目文件、实时协议驱动、采集调度、可靠录制或回放，不新增运行历史面板。
- 不提供字符串／BCD／寄存器内位拆分、偏移量、64位任意字排列、自动覆盖合并导入、单独删除历史版本、设备物理响应。

## Decisions

### 1. 所有权和分层

核心保留Tauri无关。`core/domain`负责点值、编码、完整点表校验和迁移规划；`core/application`执行模型命令和查询。`infrastructure`负责会话目录和JSON／CSV／XLSX格式适配。文件系统选择、读取、写出在Tauri适配层组装，业务组件只调用统一客户端；不将Tauri API散入树、表格或属性组件。

前端新增按模型ID拥有的`ModelDraft`：规范字段、可保留非法文本的编辑字段、错误列表、dirty及撤销栈。四遥只生成行视图，四个数据源不得成为四份事实。稳定点ID贯穿排序、筛选、批量粘贴和错误定位；表格和Details发送同一编辑事务，不能互相重建覆盖草稿。模型定义草稿与单元运行置数／待发命令草稿分离。

现有统一命令增加复制、重命名、删除；查询提供引用与应用预览。保存／删除／应用在权威目录内校验当前配置与引用，不能先查询后无保护删除。错误结构包含code、pointId、field、源文件行列及关联冲突点，前端用稳定身份定位。

### 2. 类型与精确数值

| 区域 | 类型 | 地址占用 |
|---|---|---|
| coil／discrete | Bool | 1个位地址 |
| holding／input | Int16／Uint16 | 1个16位寄存器 |
| holding／input | Int32／Uint32／Float32 | 2个连续寄存器 |
| holding／input | Int64／Uint64／Float64 | 4个连续寄存器 |

点包含稳定ID、名称、分类、area、address、valueType、byteOrder、wordOrder、scale、unit、初始工程输入／规范原始值、slaveWritable、masterPeriodMs及备注。初始值在保存前由核心反算，规范原始值是编码依据；工程输入用于十进制精确解析及浮点舍入预览，后端不得信任客户端提供的不一致原始值。

DTO的整数值和十进制输入／倍率使用字符串，Bool用布尔值，浮点用带类型的有限数值文本；版本和事件序号继续用十进制字符串。禁止将Int64／Uint64经JS Number或XLSX数字单元格中转。核心内部使用带类型的原始值枚举，整型有符号／无符号分别存储；寄存器位型只在codec边界生成，不将寄存器数组作为业务值。

倍率按十进制文本解析为精确有理数，整数反算、范围比较和相邻可表示值在整数／有理数域完成，避免0.3÷0.1之类误差。采用`num-bigint`／`num-rational`处理大整数有理运算，解析长度和指数设置明确上限并返回结构化错误；实施时核实锁定版本、许可和MSRV。浮点在目标Float32／Float64精度完成编码舍入，再预览实际工程值；非有限输入和编码溢出拒绝。不能用统一epsilon将任意不整除值悄悄舍入。Bool的倍率固定1。

### 3. 编码、权限和完整校验

默认高字节在前＋高字在前；32位为ABCD，64位为ABCDEFGH。可按点交换各16位字的两个字节，以及反转全部16位字次序；64位倒字序为GHEFCDAB，二者均交换为HGFEDCBA。Bool不适用，16位无跨字次序。编码操作针对应用数值映射，Modbus单寄存器线上仍按高字节发送。

完整表按area建立占用区间索引，检查`start + width - 1 <= 65535`，跨四遥筛选检查重叠，不将不同area相同数字地址当冲突。错误给出双方点ID及地址；以排序区间扫描校验，不要求连续地址，不提前引入通用区间数据库。

控制／调节点只能保存为holding／coil；测量／状态点允许四区，但仍须满足类型约束。input／discrete外部只读；holding／coil允许外部写入默认false，字段只约束从站接收写请求，不用来授权主站访问远端。主站业务操作仅在遥控／遥调提供待发草稿，不能编辑采集结果；从站遥测／遥信提供置数，控制页不提供本地手动置数。真实执行能力为false时，提交按钮禁用并说明未接入，不伪造已写入或接收历史。

### 4. 模型目录、保存和应用

树根／目录菜单创建或导入；模型节点菜单打开、重命名、复制、删除、导入追加、导出。右键目标成为明确操作对象，不能误用上一次选中对象；键盘菜单键／Shift+F10提供等价入口。点增删和批量编辑留在表格，CRUD资源管理不再依赖单独管理页。

编辑现有点保留ID；新增／复制模型／导入生成新ID。复制和导出只取当前已保存内容，保存覆盖同一模型ID，不提供历史版本、选版或升级入口。属性栏保留模型引用数量与端点／Unit定位。

引用按配置与已应用两侧计算，提交删除时重新校验。已应用模型的完整快照放在UnitValues中，保存模型不改变该快照；显式应用时用快照与当前定义比较。未来历史记录自包含，不需要模型历史版本保留端口。

迁移规划按稳定点ID：同类型数值、仅地址／编码／分类变化保留值；整数之间按当前值能否被新类型表示判定；Float32→Float64兼容；其他浮点窄化、整数／浮点、Bool／数值变更不兼容。新增用初始值，删除移除，倍率变化保留原始数值并预览工程变化。主站映射／解释改变使结果失效。返回结构化计划，不直接修改状态。

显式应用继承M01：预览受影响端点／通道及迁移；运行时须用户选择“停止并应用”，停止完整端点／通道，成功确认后整组原子应用，其他端点不受影响。失败保留原配置并显示实际停机状态，成功后保持停止。M02验证迁移规划和会话内原子应用；实际停机由M04/M05执行器接入，用可控适配器验证调用顺序，不宣称真实I/O通过。

### 5. 草稿和Markdown帮助

切换分类、选择行或其他Tab不丢草稿、不弹窗；dirty标记跟随模型。关闭dirty模型提供保存并关闭／放弃／取消；保存失败不关闭。退出有未保存草稿时提醒本次会话退出即丢失并可取消；不把会话内保存说成已落盘。

复用共享Tooltip，`.md?raw`按字段ID导入统一帮助注册表，`react-markdown`＋`remark-gfm`渲染列表、强调、代码和表格，禁止原始HTML执行，避免为简单帮助加入完整文档站。表头帮助和Details字段采用相同内容，hover与键盘focus均可读；NovaSheet表头使用已公开扩展点或工作台覆盖帮助入口，不改vendor实现。

### 6. 文件交换与事务

JSON格式带`formatVersion: 1`和单个当前模型定义，身份为导出元数据，导入时重建；不携带端点、设备、运行值或真实通信记录。CSV为UTF-8、支持BOM识别；XLSX模板一个点表sheet，标准列与字段一致。用户可选择其他工作表及映射列，不猜多个表拼接规则；JSON使用字段验证预览，无需假装CSV式列映射。未知格式版本明确拒绝。

XLSX读取使用`calamine`、写出使用`rust_xlsxwriter`；CSV使用成熟`csv`解析器，JSON使用`serde_json`，均置于infrastructure；不是自写通用Office引擎。公式不执行、不依赖缓存公式值，导入预览将公式单元格标为需改成明确值。64位值／倍率／初始工程输入在XLSX以文本输出，已被Excel数值单元格提前损失的精度明确提示，不能声称可恢复原始整数。模型文本导出不产生可执行公式。

流程：文件读取→表／列映射→分类缺省选择→完整候选草稿→核心校验→用户确认→新模型草稿或原模型单次追加事务。新模型和新点生成身份；追加不合并、不覆盖既有点，按追加后的完整模型验证，错误不落入目标草稿，原草稿和撤销栈不变；成功一次撤销恢复原草稿。预览草稿可保留非法文本供修正，不等于允许非法数据提交导入。确认时若目标草稿已变更则重新校验，不使用过期预览覆盖编辑。

导出只读当前已保存模型。文件选择取消、写出失败不修改目录；写出经临时文件完成后替换，确认覆盖沿用系统保存行为。大文件解析在后台执行，设置文件字节／解压大小／行数的明确限额并可取消，超过限额返回原因，不能冻结UI或写入部分数据。限额是导入保护而非规模支持声明。

### 7. 验收策略

- 先写边界失败用例：各类型极值、正负倍率、精确整除、浮点舍入、四种排列已知字节向量；不能只做编码后由自己解码的往返测试。
- 覆盖65535边界、跨分类冲突、跨area同地址、控制点只读区、保存覆盖、引用竞态、旧应用保护、不可兼容迁移拒绝和部分应用防护。
- 文件夹具覆盖JSON／CSV／XLSX完整字段往返、64位极值、BOM、引号逗号换行、非法格式／公式／版本、错误行列、追加一次撤销、取消及写出失败。
- 前端现有Vitest与新增草稿／事务／客户端测试；真实macOS Tauri WebView验证右键及键盘、下拉、中文输入、粘贴、填充柄、边缘自动滚动、撤销及错误定位。大表记录实际点数、操作、环境、时间和内存，不以构建通过替代桌面验证。
- 验收命令使用现有`pnpm --filter @essim/workbench test/build`、`cargo test --workspace --offline`、必要的`cargo test --doc`及`cargo doc`，桌面沿用现有Tauri构建；首次新增依赖需先取得依赖再离线复测。真实互操作不属本轮测试证据。

## Risks / Trade-offs

- [NovaSheet公开扩展点尚未覆盖本轮全部交互] → 首任务核实本仓库tgz实际类型及现有编辑／事务API，使用应用适配层，发现能力缺口先记录，不静默重写或修改其他仓库。
- [64位／十进制经过JS和Excel易丢精度] → 字符串DTO、文本列及核心精确校验，文件原本已丢失的值不得自动修复。
- [无数据库时保存易被误解] → 明示本次会话，关闭草稿保护不替代M08；文件交换是用户显式备份手段。
- [运行功能尚缺] → 状态和按钮依能力门禁，迁移计划与可控执行器证据和实际协议证据分开，M01到M02不伪造运行交付。

## Migration Plan

先锁定公开API和依赖，再扩展领域值／测试，随后目录／DTO／文件适配，最后接入编辑器和帮助。前后端契约同批更新，旧M01会话通过重启清空；本仓库暂无已保存项目格式需要迁移。新增格式从v1开始显式版本化。回退代码时仍需重启会话，已导出的新格式不承诺旧版可读。第三方源码、历史验收记录和M01已完成勾选保持原含义。

## Open Questions

产品规则已讨论确认，无需再次逐项征求同一决策。实施前需核验NovaSheet事件／编辑器／事务扩展点、新增依赖许可和兼容性，并在任务1给出结果；导入限额、错误分页及具体模块拆分是实现参数，按实测记录。发现已确认交互无法由现有组件实现时，先给出能力差距与替代方案，不自行扩大范围或将其勾为完成。

## 简化决策（2026-10-16）

2026-10-16 用户要求移除配置版本管理：每个模型只保存一份当前配置，单元只引用稳定模型ID；保存覆盖当前内容，不保留历史版本，不提供选版、升级或expectedRevision。保存与应用仍分开，已应用模型按完整快照保存，待下次显式应用才改变；运行记录以后使用自包含配置快照，不依赖模型历史版本。通知序号与文件格式标记仅用于内部传输／解析，不是用户配置版本功能。此前版本管理约定由本条取代，历史验收记录保持原证据边界。
