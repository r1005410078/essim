## Context

M01 决策见 [总计划](../../../docs/plans/modbus-simulator.md#m01-基础模型与架构边界)，流程见 [事件风暴图](../../../docs/design/modbus-event-storming.md)，界面以 [v15](../../../docs/design/m01-workbench-v15.png) 为当前参考。旧图中的示例值、旧版本号及生成图片的排版误差不是产品数据或强制逐像素规范。

现有根 Cargo workspace 已有独立 libmodbus 三包，core 仍以 Soc/SimulatorPort/Snapshot 为中心，infrastructure 将 TCP 单元与 RTU 教学 SOC 绑定，Tauri 与 React 共享固定单点接口。最近拆分的 commands 及中文注释是现有工作区改动，不能通过恢复旧提交丢失。本提案替换其业务契约，保留按职责分文件的组织方式。

## Goals / Non-Goals

**Goals:**

- 建立可执行、可测试的核心模型和进程内 CQRS 契约，不依赖 Tauri 或 C 句柄。
- 支持独立模拟器、可选设备关联、模型版本引用、端点下多个单元及独立值的表示与校验。
- 在不新增完整协议运行系统的前提下，定义运行／录制／回放边界并以测试适配器覆盖关键状态机。
- 清理固定教学链路，交付可启动、能查询真实配置、能力状态明确的工作台骨架。

**Non-Goals:**

- 不一次交付 M02–M10：完整点表编辑／导入导出、设备行为、多实例通信、周期采集、可靠落盘、可操作回放和3D均另案。
- 不引入 Kafka、分布式事务、微服务、通用插件平台或任意脚本执行。
- 不把进程内事件通知当作持久化承诺，不以测试替身证明真实协议或硬件完成。
- 不强制迁移 prototype，不重写 NovaSheet、C 协议栈或第三方源码，不提交 Git 或自动归档旧提案。

## Decisions

### 1. 用强类型身份表达关联，不按表格位置定位

在现有 `crates/core/src/domain/` 按职责划分 `device`、`collection_model`、`communication`、`runtime` 和 `recording` 模块；application 按 command、query、ports 组织。目录可小幅调整，但不额外建立一组空 crate。

| 对象 | 身份与职责 |
| --- | --- |
| Device | 稳定 DeviceId、名称、可扩展设备类型；不是具体协议或必须存在的物理硬件 |
| CollectionModel | ModelId、递增版本、点定义集合及校验；保存产生不可变版本 |
| PointDefinition | 稳定 PointId、名称、四遥分类、Modbus 四区／零基地址／类型等映射与角色配置 |
| EndpointConfig | EndpointId、配置 revision、TCP从站／TCP主站／RTU从站／RTU主站之一，集中管理参数与下属单元 |
| UnitConfig | 稳定 UnitId实体身份、站号、启用标记、模型版本引用、可选 DeviceId；实体身份不同于可修改的线上站号 |
| RunSession | RunId、EndpointId、配置／模型版本快照、生命周期和录制状态；每次显式启动是新 RunId |
| ReplaySession | ReplayId、原 RunId、历史位置、隔离状态，不持有真实通信句柄 |

ID 用不可变不透明字符串在边界序列化，重命名、移动、排序不改变；线上站号另用受约束的数值类型，避免把站号与实体身份混为一谈。事件／版本的 u64 跨 IPC 使用十进制字符串。具体 ID 生成依赖以 workspace 可用性为准，不凭本设计引入大型基础框架。

替代方案“Unit ID 就是身份”会在改站号或不同端点相同站号时破坏引用，因此不采用。

### 2. 两个配置聚合，不构造全局巨型聚合

CollectionModel 聚合维护点定义和版本。EndpointConfig 聚合维护角色、参数及所有下属 UnitConfig，因此可在单次修改中拒绝同端点重复站号。设备是独立实体，不必为保存通信配置而同时修改设备聚合。

跨聚合模型引用由应用服务确认 ModelId/version 存在，再提交端点修改；首版进程内目录以短临界区保护完整提交和引用检查。不得持目录锁等待协议或录制。引用版本不可在仍被已保存／已应用配置或历史使用时删除；完整删除流程在 M02/M03/M08 细化。

一个模型一张表；主从使用不同字段，不建立全局公共点库或两套选点集合。四遥是点分类，Modbus 四区是协议映射，二者不强制一一对应。SOC、功率等仅是点名称或后续设备绑定，不作为通用 core 内置业务类型。M01 表达字段与基础不变量，完整编码、字序、舍入、类型兼容矩阵和地址占用规则由 M02 交付，不先支持未经校验的类型转换。

TCP 站号值的产品范围可暂保留旧配置1–247作为本阶段显式限制，不称为TCP标准上限；协议库原有0–255通用能力不变。RTU站号1–247、首版从站通道最多一个单元；主站允许多个目标。角色只能在端点／通道级确定，下属单元继承，不混放主从角色。

### 3. 配置权威状态、草稿和投影分开

配置命令从权威目录校验，接受 expectedRevision，冲突返回明确错误，不能根据可能滞后的界面快照覆盖配置。命令成功结果带对象ID、revision和变更序号；查询投影为只读副本，可重建，前端不直接持有权威对象。

M01 最小纵向用例为：创建空采集模型 → 创建端点／通道 → 添加单元并引用已保存模型版本 → 查询对象和关联。允许创建可选设备并关联／解除关联。只完成支撑模型验证的最小新增／保存／查询／关联，不在本案交付完整CRUD编辑器、点表数据导入或可用真实运行。默认目录为空；测试数据仅在测试构造，不能启动时自动放入设计稿示例并宣称已通信。

配置目录首版内存实现，UI 明确显示“本次会话”；“保存”不暗示已持久化到磁盘，退出即丢失的限制必须可见。M08 替换存储时保持应用契约。

草稿是编辑状态；保存产生版本，不改变 appliedRevision。应用在停止／无在途执行条件下整组校验并原子切换；校验失败不修改已应用配置或值。M01 可对静止的配置实例执行应用，生产运行入口在执行器／可靠录制未接入前拒绝。批量应用每实例分别返回结果，不承诺全局回滚。

### 4. 状态所有权与应用层端口

| 所有者 | 内容与边界 |
| --- | --- |
| 配置命令处理器＋配置聚合 | 权威模型、端点／单元配置与revision，不持C句柄 |
| 运行会话 | RunId、生命周期、应用版本、录制故障；不是所有协议点值的第二份可变权威副本 |
| 协议执行器 | 连接、C context/mapping、当前运行值；通过命令／确认反馈，不能跨线程借出句柄 |
| RecorderPort | 接收有序记录、返回可识别的可靠写入确认或故障，不把仅入队当确认 |
| 查询投影 | 状态副本、能力信息、最后观察到的序号，不执行通信 |
| 回放会话 | 独立历史状态和位置，不取得执行器访问权 |
| 前端 | 草稿、焦点、选区、分类和当前Unit选择，不修改后端权威运行状态 |

application 定义 ConfigRepository、ProtocolExecutorPort、RecorderPort、HistoryReaderPort 和 Clock 的窄接口；按实际测试所需最小实现，不提前建设通用事件总线。infrastructure 实现内存配置目录和未接入的生产能力边界；可控执行器、记录器和时钟替身仅供测试。Tauri 负责组装、DTO及命令／查询／订阅适配，前端通过 EssimClient，不直接 import Tauri 进入业务组件。

保留现有 !Send/!Sync 的 C句柄限制，不因引入异步接口而新增 unsafe impl。执行器可以内部固定线程，但 M01 不决定线程池或每实例线程；不在 async runtime 中直接执行长时间阻塞库调用。

### 5. 会话、事件与录制失败契约

命令按对象串行修改，事件保留对象ID、对象revision、schemaVersion、commandId／因果关联。运行记录另有 RunId、runSequence、相对单调时间和可展示的墙钟时间；同一运行序号严格递增，不能用墙钟排序代替。序号顺序表示被记录的事实顺序，不宣称跨端点存在全局物理因果顺序。

三类数据明确区分：配置领域事件（如模型版本已保存）、运行事实（如点值变化／采集完成）、通信记录（实际RX/TX及结果）。持久化确认是技术结果，不伪装成设备状态变化事件。投影恢复时可按序号幂等应用；缺口时明确请求全量快照，不静默跨过。界面批量合并不影响完整历史。

运行状态建议为 Stopped → Starting → Running → Stopping → Stopped，失败保留故障原因；录制状态单独为 Preparing/Recording/Finalized/Failed，避免把连接临时断开等同录制结束。主站连接状态独立表达。正在启动／停止时同一启停图标禁用并显示进度。

启动必须先成功建立本次记录（含实际配置版本、初始值），才允许打开通信；M01 的生产装配缺少可靠 Recorder 或 Executor 时直接返回 CapabilityUnavailable，不返回“已启动”。测试确认记录失败时执行器未被调用。

可能对外产生效果的操作采用：校验 → 可靠保存意图 → 执行 → 保存结果 → 返回确定结果／更新投影。协议成功但结果落盘失败不能返回确定成功，停止对应运行并保留未确认范围；不会重发写入。外部主站请求无法在接收之前记录意图，后续 M04/M08 必须设计收包、执行、应答与落盘门禁，不能套用为不可能的预记录承诺。

录制失败立即拒绝新的操作，停止该端点／通道及全部下属单元，释放资源。停机过程幂等，不能因记录“已停止”失败而再次递归触发停止。独立故障通道提供最后可靠序号与停机状态；若故障原因导致无法落盘不完整标记，下次打开时根据缺少可靠结束标记判为中断，不伪造正常完成。共享磁盘失效影响多运行时分别停止所有受影响运行，不能只停第一个。真实驱动停机期限由 M04–M06 量测；M01 通过受控时钟验证不无限等待确认的状态机，不宣称硬件期限已验。

### 6. 版本应用与值迁移契约

稳定点ID相同且类型兼容时保留原始值；新增用应用配置初始值，删除移除实例值。名称、地址变更不自动清零。倍率变化保持原始值，应用预览说明工程值可能改变。未建立类型兼容规则时只将完全相同类型认作兼容，其他转换明确拒绝或要求恢复初值，不能猜测字序和截断。

停启保留当前会话内从站值；主站最近读取值标记过期。显式复位：从站恢复当前应用版本初始值；主站清空结果和待写草稿，绝不隐式远端写入。配置／点定义结构变更与即时置数使用不同命令。完整编码和协议映射迁移由 M02/M04/M05 接入，在M01纯模型测试中验证这些规则。

### 7. 回放只读契约，不在 M01 交付播放引擎

HistoryReader 读取固定运行记录的起始配置、模型版本、检查点及事实。回放会话仅能接收历史，不注入 ProtocolExecutorPort；回放中应用状态事实，不重新发送原始命令。不完整／未知版本事件停止在最后可验证位置并返回原因。暂停、倍速、跳转、校验和、索引及崩溃恢复在 M08/M09 具体实现，M01定义隔离模型与拒绝未知版本／序号缺口的契约测试。

### 8. 工作台按 v15 落地骨架，不伪造完整功能

- Dockview保留可停靠布局，浅色、圆角外框和小间距；不是卡片式管理首页。紧凑编辑器Tab，端点／连接是主Tab，模型可独立开Tab。
- 左侧按“资源／模拟器”两个紧凑Tab组织，资源包含模型与设备，模拟器包含协议端点／通道和单元；设备下的协议入口是同一ID的关联快捷入口，不复制实例。用户自定义文件夹组织仍可后续接入，不把资源分类误作不可变存储目录。
- 设备／资源树及模拟器树统一使用 `@pierre/trees`，React 从 `@pierre/trees/react` 接入；不另写树引擎。Trees 的路径身份仅用于导航适配，显式维护路径到稳定 DeviceId／ModelId／EndpointId／UnitId 的映射，不将显示名称或可变路径写作领域引用。重命名、移动和同实例快捷入口均通过映射定位原对象；模型在组件生命周期内复用，数据更新使用库提供的方法，卸载时回收订阅。
- 顶部单行纯图标，悬停提示和 aria-label、键盘焦点齐备；保存、应用分开。启停同一按钮按实际状态变换，不把停止写作暂停；无运行能力时禁用并解释原因，不展示假的绿色运行状态。
- 右栏采用浅色UE5 Details结构：分类折叠、名称／值对齐、当前单元下拉及添加入口、设备关联可选、模型及版本、只读所属端点。单位选择切换视图，不修改配置或录制事件；只给真正可恢复默认的编辑字段提供重置。
- 四遥在点表内部底部用遥测／遥信／遥控／遥调紧凑导航，独立于外层Dockview Tab。按 UnitId＋分类保存草稿、选区和滚动位置；模型点集合不被四个标签复制。空类显示空态，不补假点。
- 真正运行／置数／采集／导出／录制／回放未接入前禁用。底部空状态明确“暂无运行记录”，不装载图中历史示例。未来能力有类型化 capabilities，不根据 `isTauri` 或库已编译就宣称应用引擎ready。
- M01 只需要最小配置创建／保存／应用入口和真实目录查询，完整表格编辑交互及 CRUD 在 M02/M03交付；NovaSheet既有组件继续复用，不手写替代。
- 点表统一使用仓库已接入的 `@zhiguang/novasheet-core` 与 `@zhiguang/novasheet-react`，保留现有 vendor 快照和 React 适配兼容模块。模型定义及单元运行表复用同一组件能力；四遥仅筛选视图，不复制点身份。不能为工作台骨架另写 HTML table 或引入第二套表格引擎。

## Risks / Trade-offs

- [M01变成一次实现全部十类] → 只交付基础模型、窄端口、测试契约和工作台配置骨架；各未来按钮禁用，完整能力另案。
- [内存配置保存被误认为磁盘持久化] → 清楚标注本次会话，不声称退出后保留；可靠录制未接入不得开始实际运行。
- [录制失败后仍有已发请求] → 明确操作ID、最后可靠序号和结果未知，不自动重试写入。
- [聚合／运行任务／投影多份状态相互覆盖] → 唯一修改入口、revision与确认，查询不驱动权威校验。
- [清理丢失协议回归要求] → 逐测试迁移索引和保留库验证，列出真实运行暂不可用范围。
