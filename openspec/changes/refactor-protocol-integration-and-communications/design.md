## Context

现有路径是 `WorkspaceClient → Tauri适配 → WorkspaceEngine → TcpSlaveRuntime / TcpMasterRuntime`。应用、删除、复位和退出分别调用具体运行服务；从站使用固定mio线程，主站使用既有端点所有者／通信桥。Modbus模型、结果和JSON事件承担了部分公共职责，不能直接作为104／61850接口。

本设计是拟实施方案，不是当前实现说明。上轮17项核心契约测试和既有TCP／PTY证据仅作为回归基线。详见[提案](proposal.md)、[审查](../../../docs/reviews/2026-10-25-protocol-integration.md)及同目录五组spec。

本次修订处理二次审查的六项问题：停止凭证、提交与审计确认点、StateScope暂停／排空、104原生队列排序、已保存／已应用校验依据、跨协议验证顺序。G0基线／受限设施及窄监控接口现已验证，见[G0记录](../../../docs/test-records/2026-10-25-protocol-g0.md)；公共生产接口和G_A／G_B／G_C尚未实施。

## Goals / Non-Goals

**Goals:**

- 统一工程级通信管理与生命周期分派，保留现有Modbus调度、默认值、控制不重发及可靠录制保证。
- 建立设备状态／远端观测／协议投影、设备动作、原生模型／Binding、操作结果和观测契约；以实际第二协议通信验证公共入口。
- 将104、61850模型与服务差异显式表达，后续协议适配器按规范装配，无需复制应用、删除、批量和退出编排。
- 保持无界面运行、精确值、现有工程及IPC兼容；明确哪些属于接口提取、哪些属于显式共享状态新增能力。

**Non-Goals:**

- 当前仅授权基线／G0验证设施与默认关闭的窄监控安全接口；不进入G_A生产迁移，不把契约测试profile注册为生产能力，不交付104／61850完整产品模拟器。
- 不切换mio／Tokio、不增加每连接任务／线程的统一要求，不包装所有协议为同一个Read／Write socket接口。
- 不建立动态插件、RPC微服务、通用表单引擎、全量事件总线或全部61850数据类型／服务实现。
- 不启用生产104延迟控制、101、TLS、MMS完整服务、GOOSE／SV通信、通用SCL编辑器、Setting Groups、文件服务或历史回放UI。
- 不自动把关联同一DeviceId的旧Unit合并，不提供配置版本管理，不承诺跨协议网络交付事务或跨进程exactly-once。

## Decisions

### D1. 系统分为状态、协议定义、通信管理和具体运行四个边界

```text
React / 无界面调用方
          ↓ 公共命令、查询及兼容旧IPC
Workspace应用服务（保存、影响规划、持久提交）
          ↓
ProtocolCommunicationManager（每工程一个）
  ├─ 能力／适配器静态表、操作目录、生命周期、只读状态
  ├─ 工程资源账本／进程通道租约／可靠记录服务
  └─ 协议适配器句柄
        ├─ Modbus TCP/RTU → 既有所有者、mio及libmodbus
        ├─ 104监控测试profile → 固定所有者驱动lib60870 tick
        └─ 后续61850 profile → 原生库模型／会话／报告机制
                 ↕ 有界自有消息、快照与投影回执
StateScope所有者 / 远端观测缓存 / DeviceCommand处理器
```

core只放纯类型、规则和必要窄端口；infrastructure实现管理器、队列、资源、库调用及存储。接口不要求每个适配器采用相同线程数量和C回调模型。服务相互引用通过明确注入，不创建拥有全部协议行为的全局单例。

考虑过直接将主从服务放入 `Box<dyn ProtocolExecutor>`：现有字符串execute和confirmed布尔值无法覆盖自发事件、原生模型和多阶段控制，因此不采用。已有RunCoordinator保留在契约测试用途，禁止与新管理器形成两套生产编排。

### D2. 协议实例、服务profile、通道与原生模型分别建模

| 概念 | 最小内容 | 边界 |
| --- | --- | --- |
| `ProtocolInstanceId` | 稳定身份，旧EndpointId保留一对一兼容映射 | 不等于设备、socket、CA或IED名 |
| `ServiceProfile` | 协议族、服务、角色、适用edition／库能力、实际装配状态 | Modbus主从、104服务端、MMS客户端／服务端、GOOSE／SV发布订阅分别声明 |
| `ChannelBinding` | TCP监听／拨号、串口或L2接口的有类型参数 | 不携带C句柄，不把RTU参数泛化为所有串行协议 |
| `NativeModelRef` | 原生模型资产稳定ID、协议种类、内容摘要及解析器标记 | 摘要用于有效计划核对，不提供历史选版 |
| `Binding` | Signal／控制目标与有类型协议引用、转换及访问规则 | 原生对象可不绑定业务Signal，保留结构、FC及集合关系 |

旧Unit只作为Modbus配置和查询兼容对象。104 CA及61850 LD／LN不强制伪装成Unit。61850字符串对象引用经解析并附带FC／类型上下文，DataSet引用保持成员顺序；不得使用所有协议通吃的address字符串或任意JSON字段包。

公共定义用有限有类型结构；具体协议payload由core内对应协议模块定义，适配器实现类型化访问。在只装配Modbus的生产构建中，未来profile描述可返回不可用原因，但不注册虚假的成功处理器。61850原生结构反例放测试fixture，正式类型和解析器随其协议提案接入。

### D3. 统一通信管理接口，只管理生命周期与可跟踪操作

下面是拟实现的契约签名，不是本轮新增的Rust代码。实例计划已通过core校验，管理器仍在受理和激活前重新核对工程、能力和依赖。

| 接口 | 含义 |
| --- | --- |
| `capabilities(profile) → CapabilityDescriptor` | 实际服务／操作、平台、限制、装配状态及不可用原因 |
| `start(instance, appliedPlanToken, invocation) → OperationId` | 由应用服务解析当前已应用快照；只核对该快照和运行能力，不用尚未应用的保存内容替换或否定它 |
| `submit(instance, ProtocolAction, invocation) → OperationId` | 有类型协议动作；不支持的动作在入队前拒绝 |
| `stop(instance, reason, lifecycleContext) → OperationId` | 由管理器验证工程／实例代际后设置停止栅栏，不申请普通业务操作门；重复请求关联同一停止过程 |
| `operation(id) → OperationView` | 当前结果／证据／未知范围；查询本身不发协议命令 |
| `cancel(id) → CancellationReceipt` | 取消可取消余项，说明已发出部分，不回滚外部效果 |
| `status(instance) → RuntimeStatus` | 缓存的运行、连接、数据就绪、记录和资源状态 |
| `sessions(instance, page) → SessionPage` | 连接／活动主站／订阅摘要，有界分页，不返回借用句柄 |
| `wait_released(instance, deadline) → ReleaseStatus` | 后台有限等待真实通信资源释放；另列未结束操作和记录收尾，不把Released当作全部业务已确定 |

适配器端口为 `prepare_owned(plan, services)`、`activate`、`submit`、`query_projection`、`request_stop`、`release_status`。管理器持有可跨线程的代理句柄，C所有者及借用对象留在适配器内部。纯规划不分配C句柄，原生分配与模型构造在资源准入后、所属线程内进行。

类型边界明确为 `SavedDefinition`（当前保存意图）、`AppliedSnapshot`（已应用定义及原生资产自包含副本）和 `RuntimeSnapshot`（本次运行固定输入）。`AppliedPlanToken`是工程内当前应用计划的内部身份／摘要，不是用户配置版本或客户端expectedRevision；外部不能通过传入任意plan绕过应用。只有显式应用替换AppliedSnapshot时，旧token才失效。保存新模型、Binding或资产而未应用，只影响下一次应用预览，不阻止启动合法旧应用。

管理器不处理帧编解码、总召内容、RCB触发或SBO协议状态机。选择静态装配表而非插件发现：第二协议只需增加对应工厂／payload／描述符，公共应用、删除、退出循环不新增具体协议分支。

### D4. 生命周期、连接和数据就绪分开

| 维度 | 样例状态／含义 |
| --- | --- |
| 运行资源 | idle、starting、running、stopping、stopped、failed；failed另有释放确认标志 |
| 会话／链路 | 未连接、连接中、连接、重连、关闭；无连接型服务返回notApplicable |
| 数据服务 | 未激活、同步中、就绪、失步、降级；附协议专属原因 |
| 记录 | 准备、可靠记录、待确认、故障、结束；捕获策略及完整性另列 |
| 操作 | accepted、running、completed、cancelled、unknown；已知失败在终态携带错误及执行范围 |

104监听、TCP连接、STARTDT激活分别观察；MMS连接与报告配置／启用／初次同步分别观察；GOOSE／SV不要求TCP连接，不能把缺少连接误报故障。

准备record或资源失败不发布running。运行中的单个peer错误按适配器策略隔离；存储故障按记录profile停止受影响运行或使非可靠投影降级，不能由管理器统一“所有错误重启”。资源释放证据包括监听、连接、句柄、回调和服务共享引用，无证据就保留stopping／failed，禁止新运行复用。

每次显式启动创建RunId；临时断连、重连、暂停和恢复沿用当前运行身份。共享模型服务分别有子会话／订阅身份，MMS断连不直接标记IED整体运行结束。

### D5. 重连、超时、取消和幂等归属

- 普通业务使用 `DataPermit`（兼容现有OperationPermit语义）；应用／删除／退出使用管理器持有的 `LifecycleLease`。停止和取消请求在授权后可先到达控制入口，不重新竞争尚未完成业务占用的DataPermit；禁止靠强行释放旧凭证达到“停止优先”。
- 收到stop先原子设置实例／代际停止栅栏，拒绝新业务受理，再向原生所有者发送幂等停止请求。已受理操作在安全切点取消余项或完成，已发生效果保留结果／未知范围；C正在执行、系统调用或磁盘未完成时不承诺强制立即中断。
- 适配器阶段为Requested、Draining、ResourcesReleased及Finalized。资源租约在ResourcesReleased且真实使用者结束后归还；记录写入及操作结果仍有未确认部分时保留完成句柄和相应额度，不把记录收尾或业务确定性冒充资源状态。应用新schema还必须满足D13的StateScope排空条件。
- 应用持有LifecycleLease时，内部停止复用该生命周期上下文，不再申请自己的门。凭证只能由所属工程管理器派生，不能接受调用方伪造或从其他工程／实例挪用；依赖集合按稳定身份取得生命周期租约，但不持配置锁等待。
- 每个profile声明唯一重连所有者：应用适配器、原生库或不支持；管理器只监督声明的策略，禁止双层各自重连。
- 操作身份是跟踪／会话内重复受理防护，不是协议传输序号。相同operation重复查询或等待不会再次投递；完成目录有数量／时间上限，淘汰后返回结果不可查，不能自动重发控制。
- 旧commandId不新增跨进程去重承诺。旧IPC适配到新OperationId，保留从站有限等待和主站立即返回投影的兼容行为；超时错误不得被转成确定未执行。
- 网络超时、调用方等待超时、录制等待超时和控制期限分开；期限使用单调时钟。调用方退出或取消不提前释放仍在执行操作的凭证、配额和回调状态。
- 重连可以恢复已声明的采集／订阅意图，不能重放结果未知的遥控、遥调或选择／执行命令；恢复RCB预留、总召、队列及状态重同步由协议profile明确安排。
- 所有普通请求和完成目录有界。停止的独立有界控制通道／原子标记同时绕过普通队列和业务门禁；查询读取缓存，不被业务队列满阻断，不增加无界等待线程。未确认释放仍不允许冲突启动。

### D6. 工程隔离、物理通道与预算

每个工程Context拥有一个管理器、操作目录、状态作用域和Record服务；IPC通过当前窗口和工程会话解析目标，不能信任请求体提供的窗口label。管理器与窗口无关，可直接由无界面入口构造。

既有工程资源账本继续管理内存、连接、端点和队列。进程装配层提供共享 `ChannelClaims` 窄服务用于跨工程通道冲突，不引入新的进程全局配置状态；只存通道租约。它是进程内预检，最终由真实OS打开／绑定结果确认，不冒充跨进程强锁。

| 通道 | 资源规则 |
| --- | --- |
| TCP监听 | 校验地址族、监听地址／端口及通配地址重叠策略；实际bind为最终依据，失败保留旧应用 |
| TCP拨号 | 远端地址不是独占资源，允许多个工程连接同一EMS；连接数仍计费 |
| 串口 | 根据已验证的平台身份规范化别名，独占租约覆盖真实使用期；OS打开失败如实报告 |
| L2接口 | 网卡可共享，按协议发布／订阅资源与过滤规则管理；实际平台和权限未验证时profile不可用，不沿用串口整网卡独占 |

租约与Reservation随真实资源结束归还，启动失败回收已获得部分；共享模型的最后使用者结束后才释放模型。profile计费可增加原生模型节点、订阅／RCB缓冲、事件字节及预计帧率／带宽；帧时序、CPU和RSS属于测量结果，不能由额度估计推导承诺。默认Modbus连接、队列、线程和轮询参数沿用现状。

### D7. 状态所有者、观测和投影是三种数据

公共 `StateScopeId` 有两种首批用途：

1. `LegacyRawScope`：按旧端点／Unit稳定身份独立定位，现有RawValue、倍率和停止保值行为不变。迁移不会按DeviceId或模型复用自动合并。
2. `DeviceSignalScope`：用户或无界面测试显式声明的共享设备Signal／控制目标，具有类型、单位和初值；各协议经Binding转换。首批只支持当前精确标量能力，原生61850结构保留在原生模型，未支持的共享转换明确拒绝。

StateScope由工程级 `StateRegistry` 拥有，其生命周期不依附某个协议RunId、连接或实例句柄。执行位置可以复用工程拥有的固定worker，但停止最后一个协议不销毁／复位作用域；仅显式删除、重置或关闭工程按规则处理。LegacyRawScope通过登记／委托兼容旧所有者，不借此搬迁原写路径或改变停止保值；新共享作用域由Registry直接管理。适配器只持带代际的作用域访问句柄。“独立所有权”不等于每设备新线程。远端采集默认进入观测缓存，只有显式来源绑定和仲裁策略才能改仿真设备值。

拟实现 `snapshot(scope) → StateSnapshot(cursor)`、`submit_patch(scope, patch, invocation) → CommitOperationId`、`commit_status(id) → CommitStatus`、`changes(scope, after, limit) → ChangeBatch / Gap`。提交受理异步返回身份，不能直接返回暗示成功的StateCommit。只有选定可靠屏障确认且权威值／游标作为一个可见批次发布后，结果才为 `Committed(StateCommit)`。配置迁移和状态提交使用不同端口，不把内部cursor当expectedRevision。补丁整批校验并预留发布所需内存，失败无部分可见状态。

#### 共享状态的唯一提交与审计确认点

每个DeviceSignalScope由状态所有者选择一个ScopeJournal，使用既有RecordingPool执行；流首条自包含已应用schema、作用域会话和初始值。即使没有协议运行，也不能因缺少端点Journal而跳过已声明的可靠提交保证。各协议Journal记录自身接纳／收发／失败并引用CommitId，不重复拥有业务提交决策。

1. 校验全部patch、权限、转换和作用域代际，预留内存／额度，按scope串行化提交。
2. 可靠记录CommitIntent，包含CommitId、输入、来源及预期内部游标；确认前无可见值、C投影或发送。
3. 可靠记录CommitDecided，包含完整批次和游标；确认后以预先准备的不可分批次发布权威值与游标，这是共享状态提交确认点。此时才生成StateCommit和变化批次，释放后续消费者。
4. 按每个Binding异步投影，分别记录ProjectionReceipt；源协议只有满足自身要求的投影／回复阶段才报告该协议操作成功。StateCommitted不等于任何协议已发送或远端动作完成。

| 故障切点 | 可见状态与处理 |
| --- | --- |
| 校验／预留或意图明确失败 | 保持旧可见值，无投影／成功响应；若Journal故障则阻止该scope后续写入并报告 |
| 决策记录待确认／回复丢失 | CommitOperation保持unknown／pending，仍显示最后确认快照并隔离该scope写入与新投影；不释放真实在途记录额度、不重发同一patch |
| 决策已可靠、发布前进程异常 | 记录保留已决事实；重开按恢复规则判定其范围，不自动重放网络或控制；此证据不能冒充已经投影 |
| 权威发布后某投影失败 | 提交不回滚，故障Binding／实例标记失步或失败，不发送虚假成功；其他已提交投影不撤销，故障范围按依赖明确 |

G0已验证：sync_data或结果确认报错不等于决策未落盘；只有明确在接纳／写入之前拒绝才可判定未提交，可能写入后的故障须标Unknown。未知决策未核清前不能为该scope迁移schema或接受冲突提交；有限等待超时返回未确认，不强行宣布失败。该ScopeJournal属于运行证据，不把实时值写入配置数据库，也不新增自动恢复运行值／通信的产品承诺。

记录的连续提交序号只在RecordingPool.append成功受理后推进，不能在尝试前递增；这也不等于可靠前缀或状态游标已推进。意图在受理前因临时队列额度不足被明确拒绝时，返回JournalRejected，无Pending／提交／投影且不消耗记录序号；额度释放后允许调用方显式发起新提交，不自动重发。CommitOperationId可以跳号，不作为连续记录位置。已受理后写入／同步失败、确认未知或永久Journal故障仍按原隔离规则处理，不因额度恢复解除门禁；决策记录受理失败同样不能消耗连续记录序号，但已有意图的操作仍按既定故障规则隔离，不自动恢复业务执行。

LegacyRawScope保持原所有者及Modbus原有请求／置数可靠屏障，不额外叠加共享ScopeJournal、不改变已执行后记录失败为未知的语义。其StateCommit门面只在原可靠结果屏障和可见缓存发布后返回，不能把C内部映射已变但记录未确认当作提交成功。兼容重构阶段保持旧写路径；后续显式共享路径须先准备并校验业务补丁，再按共享提交／协议投影规则接入，覆盖局部寄存器写、多寄存器合成及非法浮点等既有规则。

对显式共享作用域，已提交的权威状态不因某个协议后续投影失败而回滚；故障适配器标记lagging／failed，不发送虚假成功，保留提交与失败证据并按profile处理。跨协议网络交付不承诺原子。旧Modbus兼容路径必须保持成功／拒绝／未知的原有语义，不能让此新增机制改变默认Unit行为。

转换沿用后端精确数值规则；共享值是声明类型的业务值，不默认某协议raw就是物理量。比例、单位换算、浮点目标精度和失败策略在Binding中声明，不引入前端Number反算或默默舍入。初批未支持的转换直接拒绝，复杂单位系统另定。

### D8. 快照、变化与报告机制

StateCommit保留值变化、质量变化、同值再次更新及来源；游标按作用域严格递增，并包含所有者epoch，防止工程重开／所有者重建后误接旧流。快照和变化起点在同一所有者取得，游标过旧或epoch不匹配返回Gap和重同步要求；该游标不是配置版本。UI快照可合并；业务流是否允许合并取决于协议profile。

#### 104队列策略必须先经过原生可行性门槛

当前Request.send／confirm／finish进入C高优先级队列，Server.enqueue进入低优先级队列；现有安全API没有按游标撤回旧低优先级ASDU的能力。不能仅用StateCursor承诺总召后无旧值回退，也不能假定已经排空／丢弃的库队列可观测。

本提案选择受限的“当前状态监控”测试profile，首选策略为每个活动会话的单一应用发送FIFO：总召确认／数据／终止与自发值按同一队列顺序送入C高优先级发送通路，不使用Server.enqueue低优先级事件队列。总召请求取得固定快照切点并在会话发送调度器保留完整批次位置；切点前已接纳帧留在FIFO前段，总召批次接在其后，切点后变化再接续。尚未入队的旧投影按序归入前段，或按当前状态profile规则标为被快照替代；异步迟到的切点前变化不得插入总召之后。快照与changes订阅切点、批次位置保留在同一受控序列完成，并计入缓冲预算，保证不会在较新快照后补发旧的无时标状态值。

应用接纳边界采用完整 `ChangeBatch { epoch, after, through, frames }`：after必须等于该消费者最后接纳位置，有进展时through大于after；当前epoch／位置的空轮询（through=after且frames为空）不推进位置也不触发Gap；同一次提交的多帧一起准入，空载但推进游标的批次也保留范围。切点前完整批次可明确标为superseded；跨切点重叠、切点后乱序／重复／断档或epoch变化返回Gap，不自动重排或部分截断编码帧。总召快照的cut不得落后于任何已接纳位置；旧异步快照不能因为放入单FIFO就获得正确顺序。Gap后暂停投影、替代应用积压，重新从同一权威所有者捕获一致快照再恢复，不能将旧异步回复伪装为新快照。G0以真实TCP验证12→11和cut11→旧快照10均不会产生线上回退。

同一状态来源的已接纳(epoch, cursor)独立于待发帧保留，包含已经接纳但尚未发送的位置。Gap、FIFO替代、传输会话切换和连续重同步失败均不得清除它；每次候选重同步快照仍须先核对相同所有者epoch且cut不低于高水位，失败继续停发／拒绝变化，成功才恢复会话投影。G0同步捕获回调是所有者线程内的重新取样入口，不允许接入旧异步缓存；即使被误传旧结果，也由高水位拒绝。真正异步接口还须绑定捕获请求及来源身份，不把此同步设施当作已实现。状态所有者切换须按生命周期显式重新绑定并建立新投影，不由网络会话或任意快照擅自改epoch。

该策略需在G0先验证窄安全接口：所有者线程内的代际校验SessionToken、可复制的受限总召请求数据／响应构造，以及有背压的 `try_send_to`；Request／C连接借用不得逃逸，不能在回调内阻塞等待发送窗口。总召可跨tick分批推进，C队列拒绝时保留应用FIFO队首且不重复接纳，不能一次回调无限塞满高优先级队列。此次只规划这些监控接口验证；不因此启用延迟控制能力，不修改vendor。若不能用已验证的上游API实现，则G0不通过、停止冻结接口和后续生产迁移，先修订方案，禁止用简单fixture假装满足。

断连后该测试profile废弃旧代际未发送的当前状态投影并记录superseded／失步，新会话从新快照重同步；不把它宣称为历史事件／SOE或离线无损补送。原生缓冲已经接纳的内容不得靠不明清队列API丢弃；会话销毁和代际失效必须验证。G0额外确认：重复STARTDT清空上游高队列却不重复通知ACTIVATED，窄接口按固定源码handleMessage的长度检查和I帧→TESTFR_ACT→STARTDT优先级识别实际重置输入（包括上游接受的非标准帧），在tick返回前使旧token失效；这不是认可该类输入为合法104帧，且不得误伤TESTFR分支。固定单冗余组的新主站接管也立即撤销旧token，不等延后的CLOSED。公开 `Server::session_is_current(token)` 查询只检查所属Server及已观测代际，不发ASDU、不推进tick；每次tick后先查询旧凭证，再处理快照／changes回复和发送，即使FIFO为空也能发现重置。旧会话的异步结果拒绝；旧应用积压被替代，实际C缓冲情况仍为未知，新激活会话先捕获并排入当前完整快照，再接续新变化。受限监控设施以COT=3承载新会话的当前状态快照，显式总召仍使用ACT_CON／COT=20数据／ACT_TERM，不冒充历史SOE补送。应用须记录替代／缺口，不沿用旧游标宣称连续交付。应用FIFO满时拒绝继续接纳并标记失步，不能静默覆盖后继续声称完整。

当前封装及拟验证接口仍只能报告库接纳，不能伪造Sent／Acked；高／低优先级共存、发送窗口堵塞、重连和中途总召反例必须在阶段G0通过真实TCP验证，不能留到全部Modbus迁移以后。

61850契约fixture覆盖LD／LN／DO／DA、FC、结构／数组、DataSet有序成员、RCB引用与控制目标。正式适配器应使用原生模型更新API，由库处理报告触发；公共层不复制RCB引擎。MMS报告客户端更新只覆盖实际包含成员，保留可用的ConfRev、包含原因和分段信息；这些生产逻辑属于后续profile提案。

交付游标按接收范围定义：104按冗余组／活动连接策略，61850按RCB／订阅；库缓冲、ESSim变化缓冲和可靠文件位置分别记录。当前单冗余组允许多个TCP连接不代表每连接独立消费。

### D9. 设备动作与协议操作分开

`DeviceCommand`携带控制目标、动作／值、InvocationContext、期限及测试／检查要求。InvocationContext包含工程、来源协议实例／会话或本地发起者、方向、关联身份；远端命令不要求先存在前端commandId。选择序号、ctlNum等留在协议payload中，不冒充全局operation。

设备动作处理器负责业务许可、过程检查、目标仲裁和实际执行反馈；库处理其已实现的原生选择／执行状态机。无动作处理器、未知对象、未支持控制模型默认拒绝，不通过通用SetValues绕过。首批Modbus原始寄存器写行为保持兼容；104／61850实际过程控制不在本提案交付范围，端口和拒绝／延迟契约通过受限测试处理器验证。

状态置数、原生属性写、控制动作与反馈关联不作一对一假设。控制目标可影响多个Signal，选择不改变设备状态，测试操作不产生真实动作；跨协议对同一目标互斥。停止时不持配置锁等待回调，也不让回调同步等待自身所有者。

### D10. 样本、记录信封和保证等级

公共样本保留值、接入有效性、本地观测时间、可选源时标及质量／精度、来源和协议原生质量。通信失败保留最后成功值／时间，另更新有效性。未知源时标不补成本机墙钟；设备仿真对时不改宿主系统时钟，操作期限使用单调计时。

事件信封包含project、所属记录流身份、记录序号、相对／墙钟时间、类别、阶段及有类型载荷。协议流关联instance／run；ScopeJournal关联scope／scope session，不伪造协议RunId。Signal／operation／协议session及来源关联按实际存在填写。设备提交、协议接纳、实际写出、协议确认、命令终止和业务反馈是独立证据，缺少钩子时明确不可观测。一个业务提交可产生多帧，一个报告可包含多个Signal，一帧无需对应用户Operation。

| 记录profile | 设计保证 |
| --- | --- |
| Modbus兼容可靠记录 | 继续现有先可靠意图／请求、执行一次、可靠结果／响应屏障，失败按现状停止受影响运行 |
| 控制审计 | 实际动作前可靠意图、执行范围及结果记录；结果未知不重发；同步回调无法满足时拒绝该控制profile |
| 状态提交记录 | 声明状态提交／审计／投影顺序；不得把已排队当已交付，失败及失步范围可查 |
| 连续流捕获 | 有界批量／独立捕获，不逐帧SQLite／sync后才发送；声明完整／采样及缺口；预算不足时按已承诺profile拒绝或停止 |

可靠文件沿用RecordingPool，SQLite是独立查询投影，其失败不暗中改变可靠文件／协议原有策略。新信封使工程投影按类别处理报文、按真实运行释放事实结束记录，停止猜Modbus事件字符串；已有记录只读兼容，不批量重写历史文件。应用诊断日志仍独立可丢。

### D11. 原生库生命周期与共存作为明确接入门槛

lib60870句柄保持线程绑定，同步Request不逃逸；G0按D8验证监控发送所需的代际会话／总召数据自有副本和受限发送接口，不用裸指针补能力。它们可支持总召分批，不能推导为104过程控制已支持；将来延迟控制仍须单独核实业务与安全回复契约。

61850每类回调分别声明线程、模型锁、重入、返回期限、WAITING能力、借用生命周期和停止方法。官方在线1.6.0 API与审查用v1.6.2控制回调说明存在差异，不能用“所有回调持锁”或“全部在同一线程”代替契约。模型对象图须覆盖所有服务和回调的寿命，停机从外部安全上下文请求，先停止使用者再销毁模型。

同进程104／61850共存前优先评估唯一common／HAL提供者及兼容ABI；构建模式进入缓存、产物清单和唯一链接所有权。若版本不兼容，选择有实测证据的符号隔离方案或拒绝组合，不能靠链接顺序。当前仓库尚无61850三包，本提案不暗中添加它们；实际C级双库静态／动态测试在后续原生库接入前阻塞启用该profile。

### D12. 配置平面、工程兼容与前端

旧formatVersion=1工程按现状读取，内部规范化为Modbus定义和LegacyRawScope；只读／打开不落盘改写。仅包含旧能力的工程继续按格式1保存，保留模型、Unit、覆盖及已应用快照，重开不自动通信。

显式持久化新共享作用域／Binding／原生模型元数据时采用工程格式2，事务写入新的有类型资源和完整清单；升级只发生在用户显式保存新能力时（含应用流程明确包含的持久保存），之前显示兼容性影响并保留一次迁移备份。格式1客户端现有版本校验会明确拒绝2，避免忽略字段导致丢失。格式号不是配置版本；不提供历史选版／expectedRevision。降回旧客户端只能打开保留的旧格式副本，不把已发生通信／值提交当可回滚。

新资源计划使用 `stateDefinitions`／`protocolModels`／`bindings` 的逻辑资源类型及稳定ID，实际目录、引用和内容摘要随格式2规范统一验证；原生资产文件保留原始字节，解析结果与运行句柄不写回。此处计划须在实现任务中补完整schema／fixture再改存储代码，不复用普通Markdown附件来隐藏强类型业务配置。

远端RCB预留／启用、动态DataSet、控制选择、缓冲及协议序号属于运行平面，不能自动覆盖工程配置。ConfRev、EntryID、stNum／sqNum可保留，它们不是用户配置历史。

前端新增统一通信客户端和状态投影；旧executeSlave／Master、querySlave／Master在适配层委托同一管理器，不建立第二运行路径。公共UI按实际能力显示操作；原生模型分页／节点查询和Signal点表是不同投影，布局复用Dockview、property-panel、workbench-dialog和NovaSheet。当前不做完整设备／61850模型编辑器，显式共享配置至少能经受校验的无界面命令／工程fixture创建、查看和原样保存；UI未支持编辑的内容必须明确只读，不能静默丢失。

### D13. 应用影响与原子发布

`ApplyImpact`列出变更类型、所有依赖实例、状态作用域、待释放资源、值迁移及兼容性影响。协议映射变更只停相关实例；共享状态schema／原生模型变化覆盖其必要依赖闭包。依赖按稳定身份排序取得生命周期门，预留全部暂存及预算后才停机。

StateRegistry提供独立于协议实例的 `begin_quiesce(scopes, lifecycleLease) → ScopeFence`、`quiesce_status(fence)`、`final_snapshot(fence)`、`publish_migration(fence, plan)` 和 `abort_quiesce(fence)`。Scope状态为Active、Quiescing、Quiescent、RecoveryRequired和Closed；协议停止不改变其存在性。栅栏覆盖本地置数、采样来源绑定、协议写入及DeviceCommand，不只关闭网络入口。

ScopeFence绑定作用域、schema epoch和本轮独立quiesce身份；Registry只保存当前活动fence。所有查询、最终快照、abort及发布均先校验该身份；abort或发布后失效，下一轮即使schema epoch未变也必须生成新身份。过期凭证返回StaleFence，不得解除或读取后一次应用的栅栏。该身份用于操作生命周期隔离，不是配置版本；nonce溢出在开始排空前拒绝。

流程固定为：

1. 基于SavedDefinition做纯候选校验、ApplyImpact和迁移预览，预留全部暂存及预算，按稳定顺序取得依赖集合的LifecycleLease。
2. 原子关闭目标scopes的新提交／动作受理并记录ScopeFence；新请求明确返回ScopeQuiescing，不能静默排入旧schema队列。已受理操作保留真实凭证。
3. 经D5控制入口停止必要协议／订阅，同时排空已受理提交、投影和动作；不持配置锁等待。复制出来的回调数据可安全结束，原生借用必须先归还。动作已执行但结果未知或提交决策未确认时，不得假称已排空。
4. 仅在必要资源释放、作用域排空且决策均明确后，取得带最终游标的迁移快照；对这份最终快照规划值迁移，不能继续使用停机前的旧值预览。
5. 短锁复核SavedDefinition候选及依赖，可靠事务提交新当前定义／已应用快照，再按栅栏不可分地发布schema、迁移值和新epoch。所有写者重新取得新代际访问；协议仍停止，状态受理仅在提交与发布均确认后恢复。

栅栏前受理并明确提交的值必须进入最终快照，不能丢失；旧代际迟到消息被明确拒绝，不得写入新schema。普通取消、业务失败或明确无持久决策的迁移失败可abort并恢复旧schema受理，但已停止协议不自动启动；存在未知提交／持久决策时进入RecoveryRequired，继续只读／停止／恢复查询，不为图省事强行解除栅栏。跨工程没有配置事务，跨协议外部效果没有回滚。

应用候选的变化只使本次apply预览失效；启动校验针对当前AppliedSnapshot及其自包含资产，不检查未应用的SavedDefinition。显式应用成功后原AppliedPlanToken失效；保存未应用或编辑草稿不使合法旧应用失效。

## Risks / Trade-offs

- 状态与C Mapping迁移产生两份权威 → 先在同一所有者提取提交边界，标记Mapping为投影；远端写路径与故障必须有针对性测试。
- 改造跨度大 → G0先验证高风险假设，再冻结契约；G_A保持旧写路径和格式1独立交付，G_B和G_C分别验收。
- 停止仍被OperationGates挡住 → 区分DataPermit和可信LifecycleLease，先锁存停止再通知所有者；满队列与在途超时必须组合测试，不强行归还旧凭证。
- 持久提交未知或迁移期间仍有写入 → ScopeJournal唯一决策，确认后原子发布；ScopeFence覆盖全部写入口，未知决策进入RecoveryRequired，禁止强行迁移。
- 104高／低优先级队列打乱总召顺序 → G0验证每会话单一发送FIFO及窄安全API；无法满足则阻塞接口冻结，游标不能代替实际发送排序。
- 过早建设61850平台 → 只实现公共引用／计划能力及反例fixture，具体栈和服务另案；不为fixture添加生产成功能力。
- 异步完成目录、变化日志和订阅积压 → 明确配额、淘汰／Gap和停止优先通道，查询无网络等待，额度随真实结束归还。
- 原生库公共符号／回调规则不兼容 → 未具备证据前拒绝启用对应组合，不用unsafe跨线程或链接顺序掩盖。
- 格式2限制旧客户端读取 → 仅在显式保存新能力时升级，展示影响、保留迁移副本；旧工程默认保持格式1。
- 流捕获与可靠控制保证被混淆 → 每profile列保证矩阵和故障策略，保持Modbus现有保证不变，流时序单独实测。
- 跨工程通道误判 → 区分监听、拨号、独占串口和共享L2；进程租约只是预检，OS结果为准。

## Migration Plan

1. **兼容基线**：固定四种Modbus profile、格式1、旧IPC／UI、可靠记录、已应用资产与独立Unit值，列出当前平台／硬件覆盖；此时只列候选接口，不冻结。
2. **G0：先做受限验证**：用最小测试设施验证六项反例；104必须走实际lib60870／TCP，必要的窄监控安全接口纳入验证但不修改vendor、不启用控制；61850仅做原生模型／服务反例。形成通过或阻塞证据后再冻结签名、队列策略、错误码、保证矩阵和目录。
3. **G_A：通信管理兼容重构**：管理器、生命周期凭证、操作目录、通道租约包装既有Modbus主从服务，保持旧值／Journal／格式1／线程行为；贯通手动、批量、应用、删除、关工程、退出和旧客户端适配。独立TCP／PTY、故障、headless及macOS工作台回归通过后单独验收，才进入共享状态实现。
4. **G_B：共享状态及应用迁移**：建立项目StateRegistry、ScopeJournal异步提交与投影回执；显式共享才使用新路径，LegacyRawScope保持旧语义。实现ScopeFence排空／最终快照／原子迁移与动作仲裁；用真实Modbus＋104监控Example及61850反例验证公共编排和故障隔离。先用内存测试／Example验证，尚不保存新工程格式；通过后单独验收。
5. **G_C：格式与展示**：最后实现格式2显式保存／恢复、通用观测信封与只读原生元数据；保留旧记录、旧工程和旧UI行为。新格式能力可见后再运行全矩阵，阶段间失败不得被后续功能掩盖。
6. **完成与证据**：按validation逐项核对六项修订与原13项、全部生命周期和原生门槛，记录实测环境和未验范围；移除生产直连旧runtime旁路后才按已验范围标完成。G0、G_A、G_B、G_C通过均不等于完整104／61850产品完成。

实施阶段若回归失败，代码回退到上一已验阶段；未升级的旧工程仍可读。格式2工程从迁移前副本恢复供旧客户端使用，不反向覆盖当前工程。恢复备份只用于迁移／事务恢复，不变成配置历史功能。现有未提交改动、未验RTU硬件和既有未完成提案任务保持各自范围。
