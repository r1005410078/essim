## Context

RTU通道配置和同步主站API已存在。用户确认一个独占串口、多目标串行调度、基础8功能码、读取质量与写回验沿用TCP，并增加手动串行诊断。正式RTU从站仍归M04；不因本阶段完成而宣称从站或硬件已验。

## Goals / Non-Goals

交付RTU主站软件路径、独立PTY互操作及工作台入口。真实RS-485方向、电气、设备拔插及时序单独验收，不交付广播或改变通信模式的诊断。

## Decisions

- 复用现有主站所有者和命令／查询，增加RTU连接适配，不另写采集调度器。保留现有tcp_master模块路径以避免无关迁移，并在文档标明其主站共享职责。
- libmodbus处理基础8功能码的编码、响应校验及CRC。私有Unix通道承载RTU上下文，独占串口由透传线程中的RAII对象管理；不改第三方源码。实际RTU字节单独记录，不拼成虚构TCP帧。
- 官方raw receive不核对请求，且固定源码未完整解析08／0B／0C：诊断用官方send_raw_request生成CRC，安全封装仅补受限诊断响应长度／CRC／站号／功能码／回送校验。支持07、08子功能0000／0002／000B～0012、0B、0C、11；拒绝000A清零、0001重启、0004只听和其他未确认子功能。
- 首版响应超时默认1000ms，重开3000ms。单Unit超时／CRC／格式错误保留通道，阻止新发送并排空一个响应超时窗口，再等待至少3.5字符／高速1.75ms安静期；清理私有通道残留后继续其他Unit。清理超时或驱动故障升级为通道断开。安静清理本身有界，至多2倍响应超时加100ms，关闭取消可中断。
- RTU没有事务号，不能识别任意晚到且站号／功能／数据结构相同的旧响应。验收只声明已验证隔离窗口，超出窗口的设备需要配置更长响应超时或人工恢复，不能虚称绝对消除迟到歧义。
- 使用规范路径／设备身份的进程内占用表和Unix TIOCEXCL；macOS tty/cu同名端口归一化，未知别名显式保留驱动边界。关闭先恢复参数并释放fd，最后释放占用登记。
- 保存不影响运行；显式应用断开且保持关闭，串口路径／通信参数变化后全部缓存清空。录制优先、有限查询、32所有者及1024点手动批次边界沿用TCP。

## Risks / Trade-offs

- PTY不反映物理时序／方向控制 → 软件与硬件清单分开，硬件任务保留。
- 代理分帧不是硬件时间戳 → 展示实际字节与CRC，短帧／无法完整取字节明确标记，不宣称串口分析仪精度。
- 静默目标占用共享串口的等待时间 → 单在途、有界超时及恢复窗口、轮转其他Unit，不无限重试。
- 串行独占依赖OS驱动 → 测试符号链接及重开，保留其他平台和未知驱动别名的限制。
