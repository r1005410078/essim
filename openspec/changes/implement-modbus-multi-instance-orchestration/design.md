## Context

正式工程采用core领域与应用层、infrastructure运行适配器、Tauri通信层及React/Dockview。TCP从站使用最多4个mio所有者线程、每所有者256控制队列、每客户端16KiB缓冲及现有10000连接总限；TCP／RTU主站合计32个所有者槽，单端点独立运行值。串口独占由SerialPort共享进程占用表与OS独占实现。配置目录仍会复制模型／值；逐事件sync_data会阻塞所属执行路径。

已有规模证据仅分别覆盖1000端点的小表与单端点大表，不能相加成典型亿点能力。当前仓库尚无归档主规格，既有活动提案与实测边界保持独立。用户已逐项确认本设计中的编排规则，真实RS485暂跳过而不勾选。

## Goals / Non-Goals

**Goals:**
- 从一个已保存模型按完整点数量生成可独立管理的TCP从站分组模型／端点。
- 原子创建与逐端点生命周期任务分开；明确任务目标、进度、取消、结果未确认和重试。
- 基于固定线程与有界资源隔离慢实例，让运行与录制成本可见、可测。
- 形成可复现、完整录制开启的独立软件规模报告及原生操作证据。

**Non-Goals:**
- 不配置系统IP／网卡、虚拟IP或网络隔离，不做多机分布式作业平台、数据库项目恢复或任务跨进程重启恢复。
- 不修改NovaSheet外观与基础交互，不实现策略、历史回放或其余RTU诊断。
- 不增加配置版本／expectedRevision，不自动保存草稿、应用或启动，不自动重发控制请求。
- 不扩大当前32主站所有者上限，不用1000从站目标证明千主站调度能力；不以保护性拒绝替代目标档位通过。

## Decisions

### 1. 点位分组是独立的配置用例

输入：源模型稳定ID、每组点数（默认1000，正整数）、起始IPv4、统一端口、统一Unit站号（默认1）、命名前缀及目标文件夹。仅使用当前已保存模型；不读取编辑草稿或实时值，不静默丢点。空模型、无效点表、非正组大小及超限预估均在创建前拒绝。

固定数据区顺序coil→discrete→holding→input，再按零基地址及稳定ID排序。按业务点数切片，最后一组保留余数；u32/f32等多寄存器点完整保留。每组保留原数据区、零基地址、类型、字序、权限、初值与采集周期，空洞不消耗点数，不重编号或填洞。

每组生成普通独立模型（默认`前缀-分组001`等）、TCP从站端点和单Unit；模型／点／端点／Unit全部生成新稳定ID，源点到新点的对应关系仅作为本次结果追踪，不构建自动同步依赖。原模型不变，后续源模型保存不更新副本。生成配置保存到指定文件夹，未应用、未启动，初始运行值由后续显式应用建立。

预览查询返回分组摘要、各区地址范围（稀疏地址不能伪装为全部连续）、IP/端口/站号、数量和内存估计；大清单按需分页，不能给每组复制完整源模型。提交命令重新读取并核对源内容、文件夹、身份／名称及本机地址。预览后的变化使旧计划失效，要求重预览；本次任务身份／内容校验不是配置历史版本。

### 2. IP分配与原子提交

IPv4按32位数值递增，统一端口保持不变；不自动绕回、不跨越无效地址，首版要求每个目标为系统当前分配的具体本机IPv4，拒绝0.0.0.0／组播等不适用地址。用网络接口枚举适配器检查，不通过猜测127/8或网段存在来宣称IP已配置。

预检包括已有配置和运行中的绑定冲突、通配监听冲突、生成身份／名称冲突、目标文件夹有效性及资源预算。分组有效但IP未配置时仍返回有界清单和逐组原因，禁止确认创建，且不缓存可提交计划、不保留暂存额度；便于先检查分配。预览不实际bind，因此其他进程竞争仍须启动时处理。

原子创建使用一个批量领域命令及一次目录事务提交。先在隔离临时结构构造、校验所有模型和端点，提交前在短锁内重校验受影响内容，然后一次替换受影响索引并发出批量创建事实；不是循环发送多个可部分成功的CreateEndpoint。失败不改变配置／导航，不泄漏外部资源。取消在提交前生效；提交已发生后返回成功结果，不伪称回滚。

### 3. 生命周期任务的目标与语义

目标可为显式选中端点、递归文件夹或明确选择全部端点。开始前显示清单并去重；开始后固定ID集合，导航变化不改变范围。执行前重新校验实际目标及已预览内容；已删除／配置变化／草稿未处理均以可定位原因跳过或失败，不悄悄执行与预览不同的内容。

- 应用：统一预览单端点差异与将停止的实例；未保存配置草稿跳过，主站待写草稿逐端点明确保留（跳过）或丢弃。复用现有预校验→释放→迁移→原子提交，失败不半应用。成功保持停止，不回滚其他成功项。
- 启动：仅使用已应用快照；未应用／已运行项跳过，单项错误继续。主站沿用连接与采集分离：批量启动仅Connect／打开串口，不隐式开始采集；从站建立实际监听／串口应答。
- 停止：主站Disconnect并取消采集／重连，从站Stop并释放资源；已停止项跳过，保留配置和值。资源未确认释放不报告成功。

失败项可选择新建重试任务；结果未确认项必须先查询并确认前项结束，不能立即重发。启动、停止应具备基于实际状态的幂等处理，不能复用旧成功结果冒充新状态。

### 4. 固定调度与任务状态

首版仅一个活动批量任务，固定最多8个执行线程，任务并发配置1～8、默认4；不按目标数创建线程。目标清单／结果投影占用均计入有界内存，超过单任务目标／字节上限在开始前拒绝，数值从基线测量确定并写入可查询配置。单个大原子创建占一个任务，不把一次目录提交拆为并发小提交；并发参数用于可独立执行的生命周期端点项。

任务：待确认／运行中／取消请求中／仍有未确认项／已完成。条目：待调度／等待端点／执行中／成功／失败／跳过／取消未执行／结果未确认；总数必须与互斥条目计数一致，展示排队等待及执行耗时。任务处于未确认时仍占全局活动位置，不允许开启另一批任务绕开名额限制。进度通过只读投影查询／合并通知返回，不要求页面打开才能运行。

调用等待超时与实际执行分离：底层任务完成句柄未结束，槽位及端点互斥就不释放；只显示未确认，并由后台继续收集结果。不得用超时包装器放弃阻塞调用并开新线程补位。全部槽位被占时明确停滞原因。取消停止领取新项，已经开始的操作按其安全边界完成；不可取消的资源释放继续。手动操作与批量使用相同端点门；未确认时同端点写操作被拒绝，查询继续可用，避免全局大锁。

### 5. 资源预算与模型／值访问

资源管理为基础设施单一准入服务，核心定义预算和拒绝原因值对象；所有手动／批量启动都走相同预留入口，不能只在UI检查。分别统计已配置数量、运行端点、主站槽位、活动连接、共享模型、独立映射／缓存、控制／录制队列、正在创建与应用的暂存内存。

先原子预留，再分配资源；真实失败、停止及删除确认后释放预留。已预留不能被并发启动重复消费。应用重建要计算旧状态与新状态并存的瞬时峰值；停止未确认项不能提前退预算。限制上限可见并校验，启动前拒绝说明当前用量、请求增量、上限及预算范围。

内存估计是工程估计，须标明是否包括Tauri/WebView、配置目录、运行映射、队列；RSS／峰值由OS测量独立展示。默认预算／保护阈值在实施首项基线测量后固定于配置与报告，不以编译期猜值或假精确的点数换算替代。过阈值先阻止创建／应用／新启动等新增负载，保留现有实例及停止／查询入口；不承诺估算能阻止所有OS内存耗尽。

运行定义按已应用不可变内容共享，值由Unit所有者独立持有。分组副本是不同配置，不因内存去重变成联动编辑。工作区导航／进度／资源查询不深复制全部模型及点值，模型内容仅编辑时按需获取，运行点值延用有界可见行查询；无每点配置数据库写入。本批允许必要的查询契约调整，前端仍只依赖统一客户端，Tauri只在适配层。

### 6. 可靠录制背压

继续端点运行文件、自包含起始快照及可靠序号，不改为配置事件溯源。先测量目录复制、sync_data、请求与字节开销，再用固定录制线程和有界每端点／总字节队列消除运行所有者上的磁盘等待；运行所有者使用待持久化状态，等待时仍服务其他端点和查询。

同一端点保持事实因果顺序，只有对应文件完成sync_data的连续前缀才能推进lastReliable。可以在上限字节／等待时长内合批独立事实，但不能在动作发生前写“已完成”事实，不能跨依赖阶段合并以绕开已确认的持久化屏障。每个文件仍须各自确认，不能把其他文件的一次同步视为所有端点落盘。批次大小与等待时间通过基线选择并记录，未测前不宣称吞吐提升。

本地／外部写入及响应遵循现有意图→执行→结果／响应准备→发送的屏障；对外成功、操作成功与相关完成确认不能早于相应持久化确认。网络写入不等于物理动作完成。队列满或落盘失败停止受影响实例，lastReliable停止推进并标明未完成／不确定范围；控制停机不依赖给已满录制队列再塞一条命令。单文件慢／失败不能用一个全局互斥锁无限阻断其他端点，公共磁盘整体故障仍可能影响全部实例，须如实呈现。

### 7. 工作台组织

项目树提供批量创建、选中／文件夹／全部端点的应用／启停入口。一个Dockview批量任务Tab承载预览、目标清单、进度、原因、取消与安全重试；资源Tab展示预算／用量／预留／积压及观测时间。复用shadcn控件，表格继续遵循NovaSheet。离开Tab不取消后台任务，关闭应用仍走既有退出与释放路径；会话退出后不宣称任务配置可恢复。

### 8. 验收与规模边界

先纯逻辑失败用例覆盖分组／原子性／状态与资源预留，再独立协议与录制故障注入，最后原生操作和规模。保留既有TCP／RTU单端点回归。

阶梯10→100→1000 TCP从站，分开端点数量、连接数量、大点表和组合：端点数探测使用小表；连接探测逐步增加至每端点10连接；大点表探测每Unit1000／10000／100000业务点，但模型始终满足四区16位地址空间及类型宽度约束；组合目标约1000端点×10Unit×10000点×最多10连接／端点须单独测量，不能把三个探测结果相乘。

短探测确认资源可承载后，可承载档位持续30分钟，独立PyModbus驱动从10秒扫描周期到5秒、1秒，分别记录目标与实际完成周期／积压跳过；扫描由真实请求完成判定，不仅发送完判定。驱动器按预定节奏并发发请求，不把所有客户端顺序执行一轮当作持续并发。保持可靠录制开启，记录CPU时间序列、RSS采样峰值及方法、线程／fd、延迟P50/P95/P99、请求／超时／异常／录制错误和磁盘占用，区分核心、桌面和独立驱动器开销。

加入慢读、半帧、单端点断开、磁盘延迟／失败、队列满、取消与退出，比较健康实例在故障前后的延迟与成功率。无统一事先承诺的吞吐SLA，目标周期未满足／受保护拒绝／测试未跑必须分别报告；完成软件阶段不代表1000端点典型亿点达标。预览IP用纯逻辑／接口替身测试；实际多IP只使用已配置地址，不为测试私自改系统网络。

## Risks / Trade-offs

- [配置事务暂存峰值] → 提交前估算并预留，整批构建失败不影响目录；大批不可把源模型重复嵌入预览。
- [磁盘异步化改变顺序] → 显式持久化状态、序号屏障、失败用例先行；不提前确认或省略必需同步。
- [UI与后台完成竞态] → 以任务／端点真实操作句柄与只读投影为准，超时不释放槽位。
- [绑定预检存在时间竞争] → 创建不宣称监听成功，启动实际bind失败保留逐项错误。
- [本机18GiB不能承载典型组合] → 保持保护阈值，记录无法测得的档位及原因，不压垮系统或伪造完成。
- [主站每实例线程现状] → 保留32槽边界并测量线程；本阶段批量调度线程固定，不承诺把协议所有者一并改为统一事件循环。

## Migration Plan

1. 先记录基线与资源配置，新增核心用例／接口而不切换既有单操作。
2. 接入原子创建及批量任务，再统一手动／批量准入和查询投影。
3. 按失败测试切换录制适配器，保持现有运行事实可读取；如内部记录格式确需调整，增加明确格式标记并保留旧文件只读识别，这不是配置版本功能。
4. 完成GUI和独立回归后再做持续压测；只在相应阶段有真实证据时勾选任务。未达标优化依据测量，不迁移其他项目。

## Open Questions

无阻止形成提案的用户范围问题。工程数值（内存预算、单任务清单字节上限、录制批次／等待及公平性阈值）由基线实验决定，在实施中先记录再用于准入与验收；不凭当前提案宣称已经选定或通过。
