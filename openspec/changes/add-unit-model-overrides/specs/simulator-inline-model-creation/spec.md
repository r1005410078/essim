## ADDED Requirements

### Requirement: 创建时选择或新建采集模型

系统 SHALL 在新建模拟器的采集模型输入中提供搜索已有模型和显式“新建此名称并绑定”。已有模型按稳定 ID 选择，同名候选 SHALL 显示可区分的资源信息，不得按名称隐式覆盖或复用。新建 SHALL 保留角色、通信参数和默认首个 Unit 的既有约束。

#### Scenario: 无模型时直接创建
- **WHEN** 目录为空，用户输入模型名并选择新建后完成模拟器创建
- **THEN** 无需跳到独立模型页，创建的首个 Unit 引用新模型，模拟器进入配置编辑且保持未应用、未启动

#### Scenario: 名称与已有资源相同
- **WHEN** 输入匹配同名资源，用户明确选择已有项或新建项
- **THEN** 选择已有项按该 ID 绑定；选择新建项创建独立 ID，不覆盖已有模型

### Requirement: 模型端点和首个单元原子提交

核心 MUST 在一次配置事务内校验并创建新模型（若有）、端点、首个 Unit 及导航归属。失败或取消 MUST 不遗留任何部分资源；已有模型在提交前失效时 MUST 拒绝并保留可修正草稿，不自动替换引用。创建 MUST 不申请通信资源。

#### Scenario: 新模型合法但端点失败
- **WHEN** 新建候选模型有效，端点站号、通信参数、身份或资源预算检查失败
- **THEN** 模型、端点、Unit 和导航均不提交，返回定位错误并保留输入

#### Scenario: 已有引用被删除
- **WHEN** 所选模型在提交前被删除
- **THEN** 整次创建失败，不产生空模型替代品或无效绑定

### Requirement: 空模型可后续编辑但不能运行

系统 SHALL 允许新建空模型并保存配置，在模拟器内编辑点表；空有效表 MUST 不成为可启动 Unit，应用与启动由核心兜底校验。保存提示 SHALL 明确仍为会话内保存。

#### Scenario: 创建后补齐点表
- **WHEN** 用户创建空模型绑定的模拟器后新增点、保存实例修改
- **THEN** 点可作为该 Unit 的局部定义参与校验，并可回写模型；完成有效配置并显式应用前不能启动
