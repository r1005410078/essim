## Why

当前创建模拟器必须先有已保存采集模型，点表调整又需要切换到资源编辑，打断“先建立模拟器、再联调完善点表”的工作流。2026-10-22 用户确认采用创建时新建并绑定模型，以及模型到 Unit 的单层覆盖，让实例差异可保留、恢复或沉淀回共享模型。

## What Changes

- 新建模拟器时，采集模型输入同时支持搜索现有资源和显式“新建此名称并绑定”；模型、模拟器、首个 Unit 原子创建，取消或失败不产生孤立资源。
- Unit 通过稳定模型 ID 引用基础模型，并保存按稳定 PointId 定位的稀疏字段覆盖、局部新增点和隐藏点；有效配置由基础模型与单层覆盖合成，不建立模型之间的继承。
- 在模拟器内复用现有 NovaSheet 编辑点定义与默认初始值，展示继承／覆盖来源、差异和错误，保持配置草稿与运行值草稿分离。
- 提供保存实例修改、恢复模型配置、选择差异回写模型、另存为独立模型并绑定；共享修改展示引用影响并整批校验，失败无部分提交。
- 运行值不自动进入覆盖或模型；提供显式、可预览的“将所选运行值设为默认初始值”，主站不自动下发。
- 保存与运行应用继续分离；按完整端点应用合成配置，保留兼容值和独立已应用快照，复位使用该快照中的有效初始值。
- 扩展现有应用、复制、批量应用、资源预算、快照和交换兼容检查；继续保持会话内保存，不引入配置历史版本或 SQLite。

## Capabilities

### New Capabilities

- `simulator-inline-model-creation`: 创建时选择或新建模型、原子绑定与空模型后续编辑。
- `unit-model-overrides`: 单层差异合成、字段归属、稳定身份、草稿、恢复与基础模型变化校验。
- `unit-model-promotion`: 差异回写、独立模型提取、共享引用影响及并发保护。
- `unit-effective-configuration-runtime`: 合成配置的显式应用、运行值边界、初值捕获与兼容验证。

### Modified Capabilities

无已归档主规格可直接修改（当前仓库尚无 `openspec/specs/`）。本提案新增规格，作为未归档 M03 提案的后续修订：取代“无模型不能完成新建”和“不提供单 Unit 初值覆盖”的后续目标约束；原 M03 任务状态和验收证据不重写为本功能已完成。

## Impact

涉及 `crates/core` 的 Unit 聚合、点定义合成、命令／查询／事件和应用预览；`crates/infrastructure` 的工作区提交、TCP／RTU 主从应用、批量资源预检与自包含快照；`workbench` 的统一 API、创建流程、模拟器点表和差异交互。复用 Dockview、NovaSheet、现有校验及协议封装，不新增协议栈或通用继承平台。

M02／M03 增加后续配置范围，M04／M05／M06 回归现有运行边界，M08 后续持久化需保存模型引用及覆盖。本提案不提前完成上述阶段，不承诺典型亿点负载、新平台或真实 RS-485 验收。

## Non-goals

不做模型到模型的变体／多层继承、配置版本管理、自动共享运行值、隐式模型回写、自动应用或自动启动；不实现 SQLite、历史回放、策略、系统虚拟 IP 或新的协议功能。
