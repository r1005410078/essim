## Context

2026-10-22 用户确认“创建时选择或新建模型＋模型到 Unit 的单层覆盖”。本文件描述已确认设计；实施状态及证据以 tasks.md 和项目验收记录为准。

当前 `CreateDialog` 仅能选已保存模型；无模型时转入独立创建流程。`UnitConfig` 只有稳定模型引用，没有覆盖。模型保存只校验模型本身；应用预览读取基础模型，并在一次端点应用中按 ModelId 共享模型快照。加入覆盖后，同 ModelId 的不同 Unit 可能有不同有效定义，必须同时调整合成、共享、应用和预算，不能只改前端表格。

核心继续独立于 Tauri；前端通过统一业务接口调用，底层复用现有命令、查询、具体提交事件和工作区事务，不建设新总线。配置仍仅在本次会话保存；M08 负责未来持久化。

## Goals / Non-Goals

**Goals:** 创建不中断；模拟器内可编辑与保存独立差异；差异可恢复、回写或提取为独立资源；共享模型、实例配置、运行状态有明确所有权；整批失败不留下部分配置或半应用运行状态。

**Non-Goals:** 模型继承模型、多层变体、配置历史／版本号／expectedRevision、自动合并所有冲突、自动应用、跨 Unit 共享运行值、SQLite 或项目交换格式建设。不重写 NovaSheet、树组件或工业协议栈。

## Decisions

### 1. 模型名称输入是明确的新建选择，不以名称当身份

创建对话框用可搜索组合输入表达“选择现有模型”或“新建‘名称’并绑定”。匹配项展示资源位置以区分同名资源；名字相同不自动复用或覆盖，最终引用始终为稳定 ID。保留单模型默认选中及默认 Unit 1／站号 1，但用户可改为新建。

核心接受模型来源的联合输入（已有 ID／新模型草稿），在一次暂存与校验后提交模型、端点、首个 Unit 和导航归属。禁止前端连续发送独立的 saveModel 与 createEndpoint 冒充事务。新模型默认进入采集模型根目录；继承明确的创建上下文时使用该目录，不增加必填路径步骤。取消、重复 ID、资源预算或其他校验失败均不提交。

新建模型允许空点表，创建后在模拟器的“配置”视图内补点。空表可以保存但不能成为可启动的有效 Unit；后端应用／启动检查必须兜底。创建不打开端口或串口。

### 2. 单层稀疏覆盖，点身份稳定

Unit 保留 model.id，并新增默认空的覆盖对象，概念上包含：

- `pointOverrides`：以基础 PointId 定位的类型化字段补丁；缺省表示继承，空文本或 false 是实际值。
- `addedPoints`：当前 Unit 局部新增的完整点定义，生成新的稳定 PointId。
- `removedPointIds`：隐藏基础点的标记；恢复时移除标记，不能删除共享模型的点。

合成顺序为读取当前已保存模型、排除隐藏点、叠加字段补丁、追加局部点，再执行既有点表和角色校验。模型顺序作为基础顺序，局部点按其保存顺序追加；不提供排序继承覆盖。隐藏点首版不同时保留字段补丁，隐藏操作移除其补丁并支持草稿撤销；删除局部点直接移除局部定义。恢复全部清空这三类差异。

覆盖是用户明确的配置意图：基础字段后来与覆盖相同，也不自动清除其他 Unit 的覆盖。用户直接输入与继承值相同的内容可以视为无新增差异，但已经保存的覆盖只有显式恢复或源 Unit 成功回写时才清除。基础新增点由所有引用 Unit 继承；没有点集合白名单。

替代方案是每个 Unit 复制整张点表，虽然简单但会丢失继承关系并放大大表存储；因此只保存差异。完整合成内容只在校验、预览、应用等需要时生成。

### 3. 字段归属与成组校验

| 字段 | 归属与规则 |
| --- | --- |
| name、note、unit | 点展示字段可覆盖；保存可更新配置展示，不要求协议停机 |
| category、area、address、valueType、scale、byteOrder、wordOrder | 可覆盖；协议相关配置显式应用；复用既有类型／地址／精度规则 |
| initial、initialEngineering | 一个“默认初始值”语义字段，工程文本经现有精确转换生成原始值，不允许分别提交不一致内容 |
| slaveWritable、masterPeriodMs | 可覆盖，沿用主从各自的权限与采集规则 |
| 模型 ID／名称、点 ID | 不是可回写字段；模型重命名仍走资源编辑，点身份不可编辑 |
| endpoint／Unit 的通信参数、站号、启用、名称、设备关联 | 原有实例配置，不进入采集模型回写 |
| 当前原始值、确认值、质量、时间戳、待写值 | 运行状态，不属于覆盖 |

更改倍率或类型必须同时重新校验初值的工程表达和原始编码，不截断或猜测转换。部分回写若缺少关联字段会使目标模型非法，则返回字段定位，要求扩展选择或修正；不静默扩大回写范围。

### 4. 有效配置在核心统一解析，基础修改也校验引用

新增纯领域合成与校验入口，供 Unit 草稿检查、配置保存、模型保存／回写、应用预览、批量应用和预算使用。错误包含 EndpointId、UnitId、PointId 和字段。点名／地址／树路径不作为合并键。

所有修改基础模型的入口都校验候选模型和受影响的已保存 Unit 有效配置，包含禁用 Unit。若基础删除有字段覆盖的点、改变类型导致覆盖初值非法、增加点导致某个局部点地址冲突，整次模型保存拒绝并列出冲突引用；用户先恢复／调整该覆盖，或另存独立模型。基础删除已被某 Unit 隐藏的点可接受，同时清除该 Unit 冗余隐藏标记，纳入同一提交与预览。禁止静默丢弃字段覆盖或留下失效引用。

未保存 UI 草稿不属于权威目录，不阻止其他窗口的正常配置提交，但收到基础变化时必须保留草稿并重新检查，标明冲突；再次保存不得用旧整表覆盖新基础。源模型编辑器存在未保存草稿时，当前工作台的回写入口要求先处理该草稿，避免两个入口互相覆盖。

该选择比允许保存失效 Unit 更严格，但使所有已保存有效配置保持可解释，也简化应用失败定位；不引入后台自动冲突合并。

### 5. 回写是可预览的原子配置事务

先保存当前实例配置，再基于已保存覆盖预览选定差异；回写入口遇到未保存源实例草稿时提供“保存并预览”或取消，保存失败保留草稿。预览列出旧值、新值、目标模型、引用 Unit 数、相关运行端点及冲突。

成功提交同时完成：更新基础模型当前内容、清除源 Unit 中已回写的差异、清理可安全移除的冗余隐藏标记，并发布具体配置事实。未选差异和其他 Unit 的显式字段覆盖保持。字段补丁回写保留基础 PointId；局部新增点回写保留其 PointId 并移出源局部集合；隐藏点回写等价于删除基础点，必须显示共享删除影响并通过所有引用检查。

预览保存短生命周期的实际输入内容／差异基线；提交在现有工作区提交边界重读模型、源 Unit、引用集合及相关覆盖。若相关内容已变则拒绝旧预览并要求刷新，不盲目覆盖；无关目录或端点编辑不应导致失败。这是一次操作的并发校验，不增加模型历史、expectedRevision 或用户选版功能。

配置保存不会改已应用快照、运行值或其他实例的启停状态。涉及协议字段的引用端点标记待应用，展示字段沿用已有直接更新规则。

### 6. 另存为独立模型及模型切换

“另存为新模型并绑定”把当前已保存有效点表展平，分配新 ModelId 和全新的 PointId，原子创建资源、重绑当前 Unit 并清空覆盖。旧模型和其他 Unit 不变，新模型不含父模型链接。这延续已有独立复制的身份规则；下次应用视为模型身份变化，不把相同地址的旧值自动迁移为新模型值，预览必须提示。

手动更换引用模型时不能把旧 PointId 补丁套到新模型：有覆盖则提供取消、明确丢弃覆盖后切换，或先另存为独立模型。切换仍为配置草稿，保存前不改运行。

复制模拟器时保留模型引用和覆盖内容，生成新的端点／Unit 身份；局部新增点也生成新 PointId，基础点补丁保持基础 PointId。复制不带运行值，删除 Unit 不删共享模型。模型复制／分组现有入口仍以所选模型资源为源，不暗中读某 Unit 的有效表；需要以有效表分组时先另存为独立模型。

### 7. 工作台内编辑及运行值捕获

模拟器点表提供清晰的“配置／运行”视图，复用 NovaSheet，保留紧凑亮色 Dockview 风格。配置视图展示有效点表、来源及覆盖数量；继承字段、覆盖字段、局部新增和隐藏点有文字或图标标识，颜色不作为唯一提示。隐藏点在差异列表中可恢复。配置批量粘贴／填充使用现有草稿与撤销，切 Unit 不丢草稿，关闭有修改页签继续保存／放弃／取消。

“保存实例修改”“回写模型”“恢复模型配置”“另存为新模型并绑定”和“应用到模拟器”采用不同名称。恢复所选／全部先进入可撤销草稿，保存后才改变权威配置；不直接改运行值。配置视图显示候选定义，运行视图始终按已应用映射展示实际值，不能用待应用倍率解释旧确认值。

运行值捕获是独立显式动作：从当前 Unit 已应用视图读取选定点的已确认原始值和取样时间，固定为预览；排除未提交置数／待写草稿。主站仅允许已成功读取且未过期／质量有效的值，显示为采样所得默认值，不触发远端写入。要求选定点在当前保存有效表与已应用表之间的地址、类型、倍率和编码一致，否则要求先处理待应用变更；任何非法点导致本批不写入草稿。确认后只更新默认初始值覆盖草稿，可撤销，再由用户保存、回写或应用。持续实时刷新不改变已确认的捕获候选。

### 8. 应用、缓存、预算与运行所有权

应用前按完整端点合成全部 Unit，再复用已有迁移、停止确认、录制及提交门禁。即使只有一个 Unit 改变，通信资源停止边界仍是端点；失败保留旧应用和值，如实反映已经停止的状态。禁用 Unit 的配置也校验并保留其覆盖和值。

从站首次应用／新增点用有效初值，再次应用兼容点保留原始值；只改默认初值不会立即复位，显式恢复初值使用已应用有效快照。主站映射或解释规则改变使旧结果失效；初值不能伪装成采集结果，主站复位不写远端。

当前应用预览以 ModelId 去重，必须改为按有效内容身份共享：同模型无覆盖或有效内容相同可以共享不可变定义，内容不同不能共享同一布局／映射缓存。可用内容摘要加相等性核实或等价内部键，但不是配置版本；缓存依赖包含基础内容和覆盖，基础保存及时失效。运行值始终按 Unit 独立。所有 TCP／RTU 主从路径、批量预检和资源账本使用相同的有效点数、布局及分配预算，避免覆盖后绕过上限或重复估算。

录制起始／应用记录和无界面 Snapshot 携带自包含的有效配置，不能运行时再查最新基础模型补齐。已发布的模型 JSON／CSV／XLSX 仍表示单个完整模型，不私加隐式覆盖格式；Unit 当前有效表通过明确的展平导出复用该格式，导出不自动创建资源或绑定。未来 M08 的项目格式必须同时保存基础引用与覆盖，旧消费者遇到不支持的覆盖不得静默忽略。

## Risks / Trade-offs

- [共享模型变更被某个 Unit 的覆盖阻塞] → 返回引用和字段定位，提供恢复或另存为独立模型；首版接受显式处理成本。
- [同模型不同覆盖被缓存串用] → 将相同 ModelId、不同地址／初值的两个 Unit 作为必须先失败的回归用例，检查运行与预算。
- [大表覆盖膨胀或批量回写影响大量引用] → 稀疏存储、依赖索引、按需查询，预览和应用纳入现有暂存预算；报告实际测量，不把结构优化当规模验收。
- [回写时共享编辑变化] → 内容基线复核、事务提交、保留失败草稿，不新增版本系统。
- [初值和实时值混淆] → 独立视图／动作、固定捕获预览、明确保存与应用状态，补主站无写入断言。
- [运行执行器只接了 TCP 一条路径] → TCP 主从及 RTU 主从软件回归矩阵；PTY 与真实 RS-485 证据分开。

## Migration Plan

先建立现状测试和行为失败用例，再实现合成与事务，随后接入应用／资源和统一 API，最后完成工作台及真实软件验证。旧 Unit 缺少覆盖字段时默认空覆盖，保持原有行为；基础模型格式不变。所有手工构造的 Unit、示例和 Snapshot 测试数据需检查，不能只靠 serde 默认通过编译。

前后端配套更新，不自动重启用户现有会话。当前无 SQLite 项目数据迁移；回退到旧代码前需先显式导出需要保留的有效模型，不能承诺旧代码读懂覆盖。实施进度由 tasks.md 按实际验证勾选；M03 原有证据和未验项保持原范围。

## Open Questions

用户已确认单层覆盖及创建流程，无需重复征求范围授权。覆盖字段的 DTO 命名、组合输入组件和有效内容缓存键由实施时按现有接口选择；若发现必须新增持久化、模型继承链或改变协议行为，单独提出范围变更。首版点增删以“局部新增／隐藏”表达，是让新建空模型能在模拟器内完成编辑的具体设计选择。
