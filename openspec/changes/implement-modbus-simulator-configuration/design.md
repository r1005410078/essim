## Context

范围衔接（2026-10-22）：本设计描述原 M03 无覆盖基线。创建时新建并绑定、Unit 单层覆盖、有效配置应用及回写按[后续设计](../add-unit-model-overrides/design.md)实施；下文“不提供 Unit 初始值覆盖”等只限定原批次。原验收证据不扩展到尚未实现的新范围。

现有`EndpointConfig`包含稳定ID、名称、角色、传输参数和Unit集合；`SaveEndpoint`可保存完整聚合，已有单端点应用预览及`ApplyBoundary`。当前前端新建空端点、添加Unit时默认引用第一张模型，缺少模拟器复制／删除和文件夹目录，关闭保护主要面向模型。`isEndpointApplied`及`resolveUnitSheet`使用完整对象比较，名称或设备关联也会被判为需要应用，须按本轮决策调整。

M02点表已接入，2026-10-16取消配置版本管理。每个模型只留当前配置，Unit仅引用模型ID；实际应用的模型定义由`UnitValues.model`快照保留。模拟器点表预览使用当前引用模型，不能再回退为旧应用空快照；未保存模型编辑有提示。M02还有未关闭的原生验收项，本提案不替其验收。

## Goals / Non-Goals

**Goals:**

- 实现新建默认Unit、固定类型、复制／删除、启用／禁用、命名及文件夹管理的会话内闭环。
- 保持草稿、保存配置、已应用协议快照和独立值的所有权清晰，展示修改无须停机。
- 以可控适配器验证整组应用、资源释放后删除及失败不半提交，给M04／M05提供窄接入边界。
- 每项已确认决策对应规格场景、实施任务和验收证据。

**Non-Goals:**

- 不接实际TCP／RTU执行器、主站采集或暂停，不实现可靠录制／回放、设备物理行为、SQLite、项目交换或规模调度。
- 不重新增加配置版本、expectedRevision、选版、升级、回滚、Unit初始值覆盖、标签或规则分组。
- 不更换Dockview、树、点表组件，不改变协议库、Turborepo或原型工具链。

## Decisions

### 1. 端点作为配置聚合，固定创建类型

继续使用`EndpointConfig`拥有Unit集合。新建入口提交完整端点与一个Unit，核心校验后一次提交，不能先留下一半空配置再追加。默认Unit 1、站号1；单模型自动选择，多模型必须明确选择，无模型时保留创建表单并提供模型创建入口，返回后刷新可选项。只使用已保存模型；提交时重新检查引用，处理选择后模型被删除的竞态。

端点创建后核心比较既存`role`和`transport.kind`，禁止直接命令绕过UI修改。TCP主／从及RTU主站可多Unit，RTU从站最多一个；新建恰有一个，后续删除最后一个允许保存空端点。站号继续采用本项目已确认的1–247，自动分配最小可用值，无可用值明确拒绝。TCP地址和串口参数沿用现有领域校验范围，不凭提案扩展平台支持。

新建使用独立`CreateEndpoint`命令，拒绝已存在ID并校验恰有一个Unit；保留整组`SaveEndpoint`更新既存对象，目标已删除时拒绝，避免迟到保存重新创建对象。Unit编辑不拆成独立资源服务；另增复制、删除和选定Unit复位命令。复制已有空端点仍按源配置复制，不冒充首次新建流程。名称／备注等文本字段按需新增并对旧会话DTO缺省为空；字段与Unit身份错误必须带`endpointId`、`unitId`、`field`及必要的`relatedUnitId`，前端可定位。错误为本项目业务结构，不照搬协议异常码。

### 2. 复制配置而不复制运行上下文

复制读取权威目录中当前已保存端点，源有草稿时明确提示不包含未保存修改，用户可先保存。生成新的EndpointId和全部UnitId，保留站号、启用状态、通信参数、设备关联和模型ID，名称默认加“副本”。源与副本均可重名，但业务身份独立；副本在当前文件夹创建，冲突时不改变源配置。

提交时校验源仍存在、目标ID未使用以及所有模型／设备引用有效；复制失败不留下部分Unit。副本没有已应用映射、会话值、连接、录制或历史关联，保持停止；后续首次应用按角色建立独立值。相同通信参数允许保存，不为复制自动改端口或串口。

### 3. 展示信息与协议应用差异分离

以显式字段白名单比较协议相关配置，不使用完整对象JSON相等判断是否待应用：

| 信息 | 保存后行为 |
| --- | --- |
| 端点／Unit名称、备注、可选设备关联、导航位置 | 立即更新展示与引用查询，不停止、不迁移值 |
| 地址、端口、串口参数；Unit增删、站号、enabled、model.id | 保存为当前配置，显式应用才影响实例 |
| 模型点增删、分类、地址、类型、编码、倍率、初始值、权限、采集周期 | 以当前已保存定义与应用快照比较，需显式应用 |
| 模型／点名称、备注、单位显示文本 | 更新展示，不改变实际协议映射或原始值 |

比较器属于核心纯逻辑；查询提供应用差异或待应用状态，前端不另维护一套规则。同步调整`isEndpointApplied`和`resolveUnitSheet`，展示改名后不能误清空确认列或丢失本地草稿；协议配置不一致时不把旧值当作新映射确认值。点表结构仍展示当前引用的已保存模型，保存模型不隐式应用运行实例。

界面只表达未保存／已保存、未应用／待应用／已应用和实际运行状态。通知sequence只排序，不作为用户配置版本。保存始终整组校验、单次权威提交，不打开通信资源；错误保留全部输入，不自动修正站号、模型或参数。

### 4. 应用和删除共用确认释放的窄边界

复用并按需扩展现有`ApplyBoundary`，提供“已停止／运行中／释放中／失败”的真实查询及幂等停止请求、资源释放确认，不提前建通用执行平台。无执行器装配时如实表示没有运行资源；真实启动与协议操作保持能力门禁。

应用顺序为：读取当前保存配置和全部引用模型 → 校验并纯预览全部Unit迁移 → 运行中确认“停止并应用” → 等待完整端点／通道停止和资源释放确认 → 重新核对权威内容 → 原子替换已应用快照和值。停止失败不替换；停机后提交失败保持原应用和值并显示已停止，不自动启动、不伪造恢复运行。等待期间不得持有全局目录锁阻塞其他端点，实施时据现有装配选择最小的分段操作方式。

删除整个模拟器同样先确认，运行中使用“停止并删除”，释放确认后原子清理端点保存配置、应用快照、所属Unit值及导航成员。模型、设备和历史存储不级联删除。等待期间权威配置发生变化则中止并让用户重新确认，不能依据旧内容扩大删除范围；不引入修订号实现该检查。释放失败保留对象并给出诊断，已实际停止的状态不回滚。

删除单个Unit仅修改草稿；保存后仍保留原已应用Unit及其值，直到整组应用成功才清理。空端点和全部Unit禁用可保存，启动前必须至少一个启用Unit。

### 5. 独立值与选定Unit复位

运行值以稳定UnitId和PointId寻址，不以表格行号或站号寻址。禁用Unit继续保留已应用快照和值，只改变参与协议活动的状态；应用禁用配置不得把该Unit当删除，重新启用按已有兼容迁移规则保留值。类型不兼容必须明确确认重置；新增点采用模型初值；模型身份改变不把旧模型同名PointId当作可保留值。

M03接入停止状态的“恢复初值”命令并带选定Unit确认：从站根据已应用快照恢复初值，主站清空本地缓存并标记过期；未应用Unit提示先应用。操作不保存／应用草稿，不影响其他Unit。M04／M05接入运行时后，复位须投递给值所有者串行处理；没有相应执行器能力时不允许前端直接改共享值。站内真实主站写入与本地缓存清除始终分开。

首次应用与重新应用继续复用M02精确值迁移。兼容规则和寄存器编码不在此重新定义，测试须保留M02的范围／符号／浮点及失败原子性分支。

### 6. 导航组织独立于协议聚合

会话目录增加轻量导航状态：FolderId、名称、父FolderId及EndpointId到父FolderId的成员关系；根用空父引用表示。文件夹不放进EndpointConfig，不参与协议应用差异。命令只提供创建／改名／移动／删除空文件夹和移动模拟器；禁止孤儿、循环、移动到后代或不存在的目标。禁止删除非空文件夹，不提供级联批量删除。

`@pierre/trees`路径是显示适配结果，双向映射稳定ID。模拟器树主名称使用自定义名称，通信地址／端口和Unit站号作为辅助信息，同名同地址时使用稳定身份作最小消歧；重命名或移动同步更新路径映射，不重建模拟器文档或改变选中Unit。复用树现有公开接口；若无合适拖放接口，使用明确的“移动到”菜单，不重写树组件。

文件夹操作即提交本次会话导航状态，不要求应用模拟器；导航已提交变更不等同于保存其他未保存配置草稿。退出仍明确全部会话内容丢失，持久化归M08。

### 7. 草稿和工作台操作

`WorkspaceStore`继续按EndpointId维护完整配置草稿。切换文档／Unit保留草稿，关闭dirty模拟器复用“保存并关闭／放弃修改／取消”，保存失败保留页面。放弃恢复最后已保存配置，不改变已应用快照和值；删除整个模拟器则关闭对应文档、清理本地草稿和导航选择。

统一保存命令同时服务文件菜单、⌘S／Ctrl+S及工具栏；先提交当前编辑器文字，按最近活动的文档保存，属性栏获得焦点不丢目标。可见模态框拥有焦点时不保存后台文档；隐藏组件dialog不能吞快捷键；等待保存期间的新编辑保留dirty。新增枚举选择使用已有shadcn Select，保持选项定义顺序，不将勾选项置顶；表格选中后不自动改行序、切页或滚动。

未保存模型不进入模拟器点定义预览，界面提示先保存模型；不会把模型草稿或初值伪装成主站采集结果。Unit切换仍只改变视图；置数／遥控权限沿用角色和四遥规则，无执行能力时保持禁用。

### 8. 资源冲突契约与跨阶段验收

保存只验证参数和Unit约束，不绑定监听端口或打开串口。复制或多个停止端点允许相同参数。M03以可控资源适配器验证申请成功／失败、内部占用者定位、外部占用通用错误、部分获取清理、等待释放及超时；TCP主站连接同一远端不是监听冲突。

内部占用信息必须来自实际持有资源的执行器／记录，不能仅扫描保存配置判定“正在占用”。串口路径别名、通配监听地址重叠及系统占用最终以目标平台真实获取结果为准。M03不实现或声称真实网络与串口诊断；M04／M05必须用独立工具占用／释放资源复测，实施前先确定M06的并发与资源所有权约束。

## Risks / Trade-offs

- [元数据被误判为协议变更] → 核心维护字段明确的比较器，覆盖改名／备注／设备关联不待应用、地址／站号／模型结构需应用的对照用例。
- [停机等待与目录更新竞态] → 先规划、释放全局锁等待、提交前重读内容，失败保留应用和值及真实停止状态。
- [禁用Unit的值被当删除清理] → 显式区分disabled和removed，用启用→禁用→启用及删除前后测试证明。
- [树路径变化误触发业务删除／丢草稿] → 独立导航身份与成员关系，只空文件夹可删，移动不改变EndpointId／UnitId。
- [无执行器时把契约当运行交付] → 测试证据分配置、可控适配器和真实I/O三层，后者留M04／M05，地图不提前打勾。
- [遗留改动和M02未验事项混入本轮] → 开工记录当前差异，保留用户修改；M02剩余项目独立跟踪，完整workspace若缺autoconf记录具体限制。

## Migration Plan

先建立基线及失败用例，扩展核心命令／错误／导航和DTO，再完成应用边界及前端流程。现有已保存空端点允许继续编辑，不强制补Unit；“新建必须一个Unit”仅约束新建操作。新增备注等字段默认空，旧目录没有导航成员时展示在根目录。

无SQLite或已发布项目格式需要迁移；点表JSON／CSV／XLSX格式保持M02规则。前后端更新同批运行，重启开发会话前明确数据仅在内存，可显式导出模型；不自动退出或清空用户当前会话。回退代码不自动迁移会话数据。本轮不自动提交、归档或部署。

## Open Questions

产品规则已逐项确认，无须重复征求同一决定。实施时核实树组件的移动接口、Dockview关闭回调和停止边界的最小装配方式，选择不改变既定交互的实现参数；若必须扩大为真实执行器、持久化或新的产品行为，则另行提出范围变更。


## 实施细节（2026-10-17）

核心只读`inspect_endpoint`同时服务查询投影与端点草稿比较；未保存草稿不进入权威目录，不在前端重写协议差异规则。比较结果以草稿对象及通知sequence防止异步旧结果覆盖新输入。`ReleasePlan`读取目标、依赖、应用和值后放锁等待，确认后在最新目录上提交，允许无关端点／导航操作并发而不丢失其修改。`ReleaseDriver`／`ConfirmedBoundary`只适配请求停止与有界释放确认，未引入生产执行器或通用插件。Tauri命令在后台任务执行。原生dialog内Select使用所属dialog作为Portal容器；提交中Escape不关闭确认框。
