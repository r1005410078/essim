## Why

当前模型、模拟器及资源树只保留本次会话，退出后丢失，无法形成可携带的 EMS 联调工程。需要以工程文件组织静态资源，以 SQLite 保存执行记录，并在启动时恢复最近工程。

## What Changes

- 新建／打开／关闭工程，以根目录 `project.workspace` 为唯一工程入口，内容采用 JSON，不绑定产品名称。
- 工程清单管理稳定资源 ID、显示名称、类型、相对路径、虚拟文件夹层级和图标颜色；界面不暴露存储后缀。模型、模拟器、文档分别保存为文件。
- 保存继续覆盖当前配置，显式应用使用独立快照；持久化 Unit 稳定引用和覆盖，禁止配置版本管理。
- 执行上下文和实际应用快照使用文件，执行事件／操作写入运行目录的 SQLite；现有通信录制文件保持独立，不新增历史回放界面。
- `.local/` 保存布局和草稿恢复，本机应用设置记录最近工程；启动恢复工程与界面，不自动启动通信。
- 建立跨文件提交恢复、工程写入占用、格式校验和错误保护；异常不能使原工程被半写或静默覆盖。

## Capabilities

### New Capabilities

- `project-file-storage`: 工程入口、资源清单、静态文件和可靠保存。
- `project-session-restore`: 最近工程恢复、工程切换、布局及草稿恢复。
- `runtime-data-storage`: 执行上下文、应用快照及有界 SQLite 运行记录。

### Modified Capabilities

无。当前仓库尚无已归档的主规格；本提案扩展既有实现，保留原保存／应用契约。

## Impact

涉及 core 应用存储端口、infrastructure 文件及 SQLite 适配器、Tauri 工程生命周期与系统文件选择、前端工程命令及退出保护。新增 SQLite Rust 依赖需在实施时核实维护状态、许可、平台构建及线程使用方式。同步维护 M08 计划、项目目标、README 和存储设计；不实现配置历史版本、协作编辑、工程打包导出、自动运行或 M07 历史查看／回放。
