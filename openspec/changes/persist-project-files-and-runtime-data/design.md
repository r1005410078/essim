## Context

当前 `Catalog` 同时包含 models、endpoints、devices、applied、values、navigation；`MemoryRepository` 通过整体替换实现原子提交，`WorkspaceEngine` 具体绑定该仓储。持久化不能直接将完整 Catalog 写入文件或数据库，否则会混合配置与运行值，也不能破坏现有原子提交、资源预算和保存／应用分离。

## Goals / Non-Goals

**Goals:** 工程可关闭重开、复制目录迁移；资源按文件保存；虚拟树不受磁盘目录约束；运行记录独立落库；启动恢复最近工程；失败不半提交。

**Non-Goals:** 配置版本管理、多进程协作、自动启停、工程压缩包、历史查询／离线回放 UI、全量高频点值历史、改造现有交换格式及全部录制格式。

## Decisions

### 1. 工程目录与唯一入口

```text
工程目录/
├── project.workspace            # JSON 工程清单，唯一打开入口
├── resources/
│   ├── models/<ID>.json
│   ├── simulators/<ID>.json
│   ├── devices/<ID>.json        # 已有设备实体，按需创建
│   ├── documents/<ID>.md
│   └── applied/<端点ID>.json    # 当前已应用配置及所需有效定义
├── assets/<ID>.<原始后缀>
├── runs/<运行ID>/
│   ├── context.json
│   ├── applied.json
│   ├── runtime.sqlite
│   └── recordings/
└── .local/
    ├── workspace.json
    ├── recovery/<资源ID>.json
    ├── transactions/           # 提交恢复暂存，正常完成后清理
    └── project.lock
```

固定入口名及扩展名不绑定产品名称。新建工程选择空目录，打开工程选择 `project.workspace`；不覆盖非空目标。所有内容路径相对于工程根目录；内部路径由存储适配器生成。拒绝绝对路径、越界 `..` 和符号链接逃逸。首版以本机文件系统为验收范围，不承诺网络盘／云同步同时编辑安全性。

### 2. 清单是资源目录的权威

清单包含 formatVersion（仅文件格式）、projectId、displayName、folders、resources。文件夹有稳定 ID、parentId、scope、名称、图标、颜色；资源有稳定 ID、kind、displayName、folderId、相对 path。保存现有模型／模拟器树的分类边界和顺序规则，不新增手动排序。重命名／移动仅修改清单，文件继续用稳定 ID 命名，业务引用继续按 ID。

资源文件只保存对应业务定义；显示名称以清单为准，载入时映射到现有领域对象，不在两处维护可独立修改的名称。文档保留原始 Markdown，内置只读协议文档仍来自应用包，不复制为可编辑资源。UI 不显示内部文件名或 JSON 后缀。

### 3. 文件事务与存储端口

core 保持不依赖文件系统、SQLite、Tauri。infrastructure 新增工程仓储与加载器，适配现有提交契约；装配层移除对 MemoryRepository 的硬绑定，内存仓储继续用于隔离测试。比较提交前后内容，只写变化资源，不能每次保存重写整个大表工程。

多文件提交使用单写入者与可恢复事务：预检和完整校验 → 在同一文件系统写暂存及必要旧文件备份 → flush/sync 数据与事务清单 → 标记 durable commit 决策 → 幂等安装资源并最后替换工程清单 → 同步目录后发布内存状态／成功通知 → 清理。未决事务回滚，已决事务前滚；加载前先恢复，禁止混合状态进入业务。提交决策后安装失败须进入恢复阻塞状态，不能当作普通失败继续编辑。备份只是短期故障恢复，不是用户配置历史。

删除同样参与事务；确认没有保存配置及已应用快照引用后才清理文件，不能仅依据树节点消失删除。保存失败不清除前端脏标记。

### 4. 保存、应用与运行分别持久化

模型／模拟器保存仍覆盖当前内容，Unit 引用、覆盖、设备实体一起按现有命令事务处理；文件夹 CRUD 和移动成功即持久化。`resources/applied` 只保留每个端点当前已应用快照，须能在模型随后变化后独立重建旧映射，不持久化运行实时值。打开后配置与应用快照分别恢复，差异仍显示待应用，端点一律停止。

应用依旧先确认停机和校验，再提交应用快照；持久化失败不得报告应用成功或自行重启。运行开始前将实际执行配置和上下文固化到 runs；每次独立启动建立运行 ID，多个端点关联实际稳定 ID，不复制整个工程。运行目录是执行证据，不提供配置选版。

### 5. SQLite 只保存执行记录

首版保存运行生命周期、连接状态变化、错误和用户控制操作；使用运行 ID、端点／Unit／点稳定 ID、时间及单调顺序定位记录。SQLite 不作为配置权威，不将实时值更新逐条写库；完整点值历史另提案。专用有界写入队列批量事务提交，协议线程不等待数据库 IO；停止时有限时刷新。故障、队列满、磁盘满时明确标记记录不完整并告警，不静默丢弃，也不在记录故障时擅自停止协议通信。

运行库单写者，启用外键和明确持久性设置；具体 WAL／同步参数通过本机崩溃、关闭及性能测试确定，不能将活跃数据库单文件复制当完整备份。现有可靠 JSONL 录制继续保留，其原有故障策略不改变。暂不接历史查看与回放 UI。

### 6. 最近工程、布局、草稿与切换

最近成功打开的工程入口及至多十条列表存于应用设置目录；显式关闭清空自动恢复入口但保留列表，打开失败不覆盖成功记录。启动尝试恢复，路径缺失、工程损坏、格式过新或占用时显示可理解错误及新建／打开入口，不自动创建同名空工程。无最近工程显示工程引导，必须打开或新建工程后才进入工作台；本项由后续 [工程入口提案](../require-project-startup-and-switcher/proposal.md)收紧。

`.local/workspace.json` 保存 Dockview 文档布局、稳定资源身份、活动 Tab、面板状态；恢复时过滤删除资源和非法布局，失败回到默认布局而不影响配置。`.local/recovery` 以工程／资源 ID 关联草稿，防抖暂存、显式保存成功清理；异常退出后提示恢复或丢弃，不覆盖正式资源。若正式资源已变化，提示冲突并保留恢复副本。

切换／关闭先处理脏草稿，再确认停止运行并刷新记录，成功加载新工程后才切换界面和最近路径。目标工程预检失败保持当前工程；已停止的通信不因失败自动重启。工程写锁由进程持有；第二个写入者被拒绝，崩溃遗留锁须经实际持锁状态确认，不能仅看文件存在。`.local` 不参与正常工程交换；有未决事务时禁止宣称可安全复制工程。

### 7. UI 与实施分段

工程命令进入现有命令注册体系，顶部资源检索仅检索当前工程。继续使用公共 WorkbenchDialog，系统路径选择保持原生；不改变现有 Dockview 风格。第一段完成文件工程闭环，第二段接 SQLite 记录，第三段完成真实冷启动、故障注入和原生验收；本提案全部任务完成才算交付。

## Risks / Trade-offs

- 多文件崩溃一致性复杂 → 单写者、事务恢复协议、每个落盘阶段故障注入，不能只验证正常保存。
- 大工程整体克隆与索引重建 → 保留预算准入、增量落盘和现有按需读取；测量保存耗时及 RSS，不虚报容量。
- 用户外部编辑或同步软件改写 → 检测已加载文件的外部变化，拒绝静默覆盖并要求重新加载；首版不做自动合并。
- SQLite 写入阻塞 → 独立有界批处理、故障可见、真实通信回归；不以数据库记录成功冒充协议成功。
- 工程资源与本机串口等不匹配 → 恢复配置而不自动运行，启动前沿用现有能力检查。

## Migration Plan

当前无正式持久化工程格式，无历史工程迁移。首版格式号为 1；后续工程入口提案取消正式客户端临时会话；新建始终创建空工程，当前工程的脏草稿留在原工程恢复区，不迁移到新工程。旧模型导入／导出能力保持，不能将展平模型当完整工程。遇到未来格式拒绝写入，后续格式迁移需独立备份与验证。实施前不更改当前“会话内保存”的产品说明为已交付。

## Open Questions

无阻塞提案的产品问题。SQLite 库、平台锁和目录同步 API 在实施前依本地依赖及官方文档核实；Windows／Linux 未实测时明确记录待验，不外推 macOS 证据。
