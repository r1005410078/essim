## ADDED Requirements

### Requirement: 执行证据分离存储

系统 SHALL 在 runs 下以独立运行 ID 保存上下文、实际应用配置及 SQLite 执行记录，不将配置或实时内存值作为数据库权威。

#### Scenario: 运行开始与结束

- **WHEN** 启动端点、产生状态和控制操作后停止
- **THEN** 上下文和实际应用快照可核对，生命周期、错误及操作按稳定身份和顺序落库，停止刷新完成状态可辨认

### Requirement: 有界异步写入与故障可见

系统 MUST 通过有界队列批量记录，不在协议线程执行数据库 IO；异常不得静默丢失或冒充完整记录。

#### Scenario: 写入故障

- **WHEN** 数据库写入失败或队列达到上限
- **THEN** 展示记录故障并标记不完整，不因数据库故障擅自停止通信，正常协议结果仍独立报告

#### Scenario: 退出与异常终止

- **WHEN** 执行中退出或进程异常终止
- **THEN** 正常退出有限时刷新，异常终止后能识别未正常结束的运行；不自动启动恢复运行

### Requirement: 既有录制兼容

系统 SHALL 保留现有通信录制文件与可靠性行为，不将本次落库等同于历史回放或全量点值历史。

#### Scenario: 开启通信录制

- **WHEN** 运行期间启用原有录制
- **THEN** 生成可校验的录制文件，SQLite 接入不改变原有录制故障策略或协议报文
