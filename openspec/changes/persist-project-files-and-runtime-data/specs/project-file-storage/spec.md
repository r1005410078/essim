## ADDED Requirements

### Requirement: 工程入口与资源文件

系统 SHALL 通过 project.workspace 新建和打开工程，将静态定义保存为独立文件；清单管理虚拟目录和稳定资源映射，界面不显示存储后缀。

#### Scenario: 重命名和跨层级移动

- **WHEN** 用户重命名模型并将它拖入虚拟文件夹
- **THEN** 只更新清单名称与归属，资源文件路径和 ID 不变，引用仍有效

#### Scenario: 完整重开

- **WHEN** 关闭并重新打开包含模型、模拟器、设备、Unit 覆盖、文档及附件的工程
- **THEN** 恢复全部已保存定义、虚拟层级、图标颜色和稳定引用

### Requirement: 保存原子性与恢复

系统 MUST 在多文件保存中保持崩溃后可恢复的一致状态，成功通知仅在持久提交完成后发布。

#### Scenario: 中断提交

- **WHEN** 提交在暂存、决策或安装阶段被终止
- **THEN** 下次加载先回滚未决事务或前滚已决事务，不向业务暴露半份配置

#### Scenario: 存储失败

- **WHEN** 提交遇到磁盘满或权限错误
- **THEN** 不虚报保存成功，不清除脏状态；决策后失败进入恢复阻塞状态

### Requirement: 保存应用分离

系统 SHALL 分开持久化当前配置与当前已应用快照，保留 Unit 覆盖和有效定义；不得增加配置历史版本。

#### Scenario: 保存后重开

- **WHEN** 模型保存变化但未应用，随后重开工程
- **THEN** 新配置及旧应用快照分别恢复，显示待应用且端点停止

### Requirement: 加载与写入保护

系统 MUST 校验格式、ID、引用、树环路及根目录内路径；拒绝并发写入和外部改写覆盖。

#### Scenario: 不合法工程

- **WHEN** 清单包含越界路径、重复 ID、缺失引用或未来格式
- **THEN** 拒绝打开并说明问题，不修成空工程或覆盖源文件

#### Scenario: 已占用或外部变化

- **WHEN** 另一进程持有写锁或资源在加载后被外部修改
- **THEN** 拒绝竞争写入或静默覆盖，原文件保持可恢复
