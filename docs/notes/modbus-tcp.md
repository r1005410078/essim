# Modbus TCP 学习笔记

这次笔记按提问顺序整理。例子用两处材料：第一课的 SOC 读取，以及一份 PCS 点表里的额定功率（地址 `0xA106`）。

## 一次问答应是什么样

Modbus TCP 上一轮交互是：客户端发一个请求帧，服务端回一个响应帧。服务端不主动先说话。第一课里 EMS 是客户端，BMS 是服务端，地址 0 的保持寄存器里放着 SOC 原始值 650。

EMS 发出的第一句是：第 1 次询问，请读设备 1 的保持寄存器，从地址 0 开始，读 1 个。

```text
00 01  00 00  00 06      01     03      00 00  00 01
第1次  协议0  后面6字节  设备1  读保持  地址0  读1个
```

BMS 查到 650，回答：这是第 1 次询问的回答，结果 2 个字节，值是 650。

```text
00 01  00 00  00 05      01     03      02     02 8A
第1次  协议0  后面5字节  设备1  读保持  2字节  值650
```

事务号 `00 01` 由客户端编，服务端原样抄回，用来把答配回这一问。点表再把 650 × 0.1% 换成 SOC = 65.0%。协议只负责把寄存器里的数送回来。

## 帧由哪两段组成

前 7 字节是 MBAP，负责在 TCP 上投递。从功能码起是 PDU，才是 Modbus 命令。

| 字节 | 字段 | SOC 这一问 | 含义 |
| --- | --- | --- | --- |
| `00 01` | 事务标识 | 1 | 询问号。允许 0～65535，不必从 1 开始 |
| `00 00` | 协议标识 | 0 | 0 表示 Modbus |
| `00 06` | 长度 | 6 | 这个字段之后还剩多少字节，从 Unit ID 算起 |
| `01` | Unit ID | 1 | 要访问的设备。直连时服务端接受并回显；有网关时用来选下游设备 |
| `03` | 功能码 | 3 | 读保持寄存器 |
| `00 00` | 起始地址 | 0 | 报文地址从 0 起算 |
| `00 01` | 数量 | 1 | 功能码 03 一次允许读 1～125 个寄存器 |

长度字段用来切帧。TCP 是字节流，一次读取可能只有半帧，也可能一次拿到两帧。长度是 6 时，长度字段之前还有 6 字节，这一帧一共 12 字节。

## 服务端怎么处理

收齐一帧之后：

1. 协议标识是 0，按 Modbus 处理。
2. 功能码 03，进入读保持寄存器。
3. 数量落在 1～125。
4. 起始地址加上数量，都在这台设备的寄存器表里。
5. 组正常响应，写回同一条连接。

成功时响应功能码与请求相同。字节数字段是后面寄存器数据的字节数：1 个寄存器是 2，连续读 2 个就是 4。每个寄存器两个字节，高字节在前。

地址、数量或功能码不被接受时，仍然要回复，格式换成异常帧。读一个不存在的地址 1：

```text
请求  00 01  00 00  00 06  01  03  00 01  00 01
响应  00 01  00 00  00 03  01  83  02
```

`83` 是功能码加上 128，表示这次失败。`02` 是异常码。功能码 03 里常见的三个是：

| 异常码 | 名称 | 何时回复 |
| --- | --- | --- |
| `01` | 非法功能 | 不支持这个功能码 |
| `02` | 非法数据地址 | 起始地址加上数量，超出设备实际有的寄存器 |
| `03` | 非法数据值 | 数量不是 1～125，或请求里的值不合法 |

一直没有字节回来，协议里没有对应的帧。那是 TCP 这一层的结果，客户端按自己的等待时间判定超时。

## 功能码和四个数据区

| 功能码 | 作用 | 数据区 | 每个地址的宽度 |
| --- | --- | --- | --- |
| `01` | 读线圈 | 线圈，可读可写 | 1 位 |
| `02` | 读离散输入 | 离散输入，只读 | 1 位 |
| `03` | 读保持寄存器 | 保持寄存器，可读可写 | 16 位 |
| `04` | 读输入寄存器 | 输入寄存器，只读 | 16 位 |
| `05` | 写单个线圈 | 线圈 | 1 位 |
| `06` | 写单个寄存器 | 保持寄存器 | 16 位 |
| `15` | 写多个线圈 | 线圈 | 1 位 |
| `16` | 写多个寄存器 | 保持寄存器 | 16 位 |

四个数据区各自从地址 0 编起。第一课把 SOC 放在保持寄存器地址 0，并规定外部不能写。不能写是教学点表的规定。协议本身允许用功能码 06 写保持寄存器。

## 字节、高位和低位

一个字节有 8 个比特，每个比特是 0 或 1，一共 256 种排法，数值从 0 到 255。十六进制用两位表示一个字节：`00` 是 0，`FF` 是 255。

高位是权值大的一侧，低位是权值小的一侧。写下来时高位在左，和十进制同一个习惯。两个字节拼一个 16 位整数时：

```text
值 = 左边的字节 × 256 + 右边的字节
```

SOC 响应里的 `02 8A`：

```text
2 × 256 + 138 = 650
```

`02` 是高字节，`8A` 是低字节。Modbus 在线路上先发送高字节。一个字节内部也是左边权值大：`8A` 的二进制是 `1000 1010`，等于 128 + 8 + 2 = 138。

## 校验

Modbus TCP 这 12 个字节里没有校验字段。字节在传输中有没有损坏，由 TCP 检查。TCP 头部里有一个 16 位校验和，覆盖头部和 Modbus 载荷。校验失败时，字节不会交给 Modbus 程序，发送端按 TCP 的规则重传。网卡还会用以太网帧尾的帧校验再查一次链路。

因此校验失败不会变成 `83 02`。异常帧只回答功能码、地址或数量不合法。

同一句问话改走 RTU 时，帧尾才有两个 CRC 字节，低字节在前：

```text
TCP   00 01  00 00  00 06  01  03  00 00  00 01
RTU               01  03  00 00  00 01  84 0A
```

RTU 从站发现 CRC 不符就丢掉这一帧，不回复。主站只能等到超时。串口参数里的奇偶校验位是 UART 的线路格式，不是报文里的字段。8N1 的 N 表示不附加奇偶位。TCP 连接上没有它。

## TCP 和 RTU

两边的 PDU 相同，差别在外面的封装，以及靠什么把一帧切出来。

| | Modbus TCP | Modbus RTU |
| --- | --- | --- |
| 传输 | TCP，默认端口 502 | 串口，常见是 RS-485 |
| 帧 | 7 字节 MBAP + PDU | 1 字节站号 + PDU + 2 字节 CRC |
| 切帧 | 长度字段 | 帧间静默。波特率高于 19200 时，规范把间隔固定为 1.750 ms |
| 校验 | TCP 校验和 | CRC-16 |
| 地址字节 | Unit ID | 站号。1～247 是单台从站，0 是广播且从站不回答 |
| 请求怎么对上响应 | 事务标识 | 没有事务号。这次询问之后回来的那一帧就是答案 |
| 角色 | 一个连接里客户端发问；一台机器可以有多条连接 | 一条总线上一个主站轮询多个从站 |

TCP 可以连续发出事务 1 和事务 2，响应乱序也能配回去。RTU 发完要等。超时后重发时，迟到的旧响应没有事务号可丢弃。

学习顺序是先 TCP。PDU、功能码、异常帧和点表换算先在本机对打中看清楚。RTU 再加上波特率、CRC、帧间静默和多从站。

## 串口能不能在系统里模拟

可以模拟到「两个程序通过一个串口形状的设备文件收发字节」。Linux 或 macOS 上：

```bash
socat -d -d \
  pty,raw,echo=0,link=/tmp/ttyV0 \
  pty,raw,echo=0,link=/tmp/ttyV1
```

一边打开 `/tmp/ttyV0`，另一边打开 `/tmp/ttyV1`。写进一边的字节从另一边读出。这里可以验证打开串口、8N1、站号、CRC 和整帧问答。

虚拟端口上，波特率不会真正放慢字节。9600、8N1 下 8 个字节大约要 8 毫秒，3.5 个字符的帧间静默大约 3.6 毫秒；伪终端上这些字节几乎立刻到齐。练习时一整帧一次写入，再用十几毫秒的空闲超时判断帧结束。

RS-485 上同一时刻只允许一个发送器驱动总线。伪终端是两台全双工对连。多从站冲突和方向控制要到真实串口上才能看到。

## 电力通信里的主站和从站

现场口头里，主站和从站很常见。它描述传统远动和串行轮询：主站发问或下命令，从站保存数据并回答。调度主站、集控主站里的「主站」，指的是系统侧那一端。各协议文本里的角色不同：

| 协议 | 两边的称呼 | 谁先开口 |
| --- | --- | --- |
| Modbus RTU | 主站 / 从站 | 主站轮询。从站只在被问到时回答 |
| Modbus TCP | 规范写客户端 / 服务端，现场仍常叫主站 / 从站 | 客户端发请求 |
| IEC 60870-5-104 | 控制站 / 被控站，工程上也叫主站 / 子站 | 控制站发起 TCP。启动数据传输后，被控站会主动上送 |
| IEC 61850 MMS | 客户端 / 服务端 | 客户端读取模型、下发控制 |
| IEC 61850 GOOSE、采样值 | 发布者 / 订阅者 | 报文组播出去，没有问询 |
| MQTT | 客户端 + 代理 | 设备和 EMS 都去连代理，靠主题区分上报和下发 |
| 电池内部 CAN | 总线上的节点 | 各节点按帧 ID 周期发送 |

储能现场常见的接法，是 EMS 当 Modbus 主站，BMS 和 PCS 当从站。这是工程安排。同一台 BMS 对内可以走 CAN，对外对 EMS 做 Modbus 从站，对云平台再以 TCP 客户端连上去。设备身份和通信角色分开看。

## 从代码开始时先写什么

先写「读保持寄存器并回答」的 Modbus 服务端，而不是一个通用 TCP 回显。寄存器在服务端手里。建议分三层，用标准库的 `TcpListener`，绑定 `127.0.0.1:5502` 这类非特权端口：

1. 两个纯函数，先不碰网络。`parse_request` 把 12 个字节读成事务号、Unit ID、功能码、地址和数量。`build_response` 按点表组出响应字节，地址越界时组出异常帧。用第一课的字节做单元测试。
2. TCP 接受一条连接，按长度字段读满一帧，交给这两个函数，把响应写回去，并打印两边的原始字节。
3. 服务端稳定之后再写 EMS 客户端，把 650 显示成 SOC = 65.0%。

纯函数就是普通函数：输入字节数组，返回结构体或响应字节。测试直接调用它们，不监听端口。端口、连接和读写留在第 2 层。这一步先不做写入、多连接和断线重连。

## 点表：以额定功率为例

下面这一行来自一份 PCS 查询参数表，不是协议正文。

| 点表栏 | 额定功率这一行 | 发报文时怎么用 |
| --- | --- | --- |
| 地址 | `0xA106` | 放进起始地址，两个字节是 `A1 06` |
| 属性 | RO | 只读，这一问用读功能码 |
| 数据类型 | U16 | 占 1 个寄存器、2 个字节 |
| 数据范围 | 500～2000 | 这个点认定的有效额定功率，单位是 kW |
| 单位 | 1 kW | 工程值 = 原始值 × 1 kW |

读多少不看数据范围，看数据类型占几个寄存器。U16 的数量是 1。`500～2000` 是读回来的那个数该落在哪一段。

截图那一页没有写功能码。这类查询参数多数用功能码 `03`。若文档总则写的是 `04`，只改功能码那一个字节。Unit ID 来自通信参数，下面沿用 `01`。假如额定功率是 1000 kW：

```text
请求  00 01  00 00  00 06  01  03  A1 06  00 01
响应  00 01  00 00  00 05  01  03  02  03 E8
```

`03 E8` 是 1000。乘单位 1 kW，得到额定功率 = 1000 kW。500 kW 是 `01 F4`，2000 kW 是 `07 D0`。同一页里软件版本号的单位是 `0.01`，原始值要再乘 `0.01`。额定功率的单位是 1，原始值就是千瓦数。

从 `0xA106` 起连续还有额定电压、额定电流、额定频率，到 `0xA109`。数量填 4，可以一帧读回这四项。功能码 03 一次最多 125 个寄存器。

## 数据类型是谁规定的

U16、S16、U32、S32、F32 不是 Modbus 规定的。协议只规定寄存器是 16 位，一格两个字节、高字节在前。这些名字是点表和嵌入式文档的习惯写法：U 是无符号，S 是有符号，数字是比特数。没有单独一个人发明 S16 这个名字。Rust 里用另一套名字：

| 点表 | Rust | 占几个寄存器 | 原始值范围 |
| --- | --- | --- | --- |
| U16 | `u16` | 1 | 0 ～ 65535 |
| S16 | `i16` | 1 | −32768 ～ 32767 |
| U32 | `u32` | 2 | 0 ～ 4294967295 |
| S32 | `i32` | 2 | −2147483648 ～ 2147483647 |
| F32 | `f32` | 2 | 单精度浮点数 |
| 位 | 一个 `u16` 里的某一位 | 1 个寄存器常放 16 个位 | 每一位是 0 或 1 |

类型范围和点表的数据范围不是一回事。额定功率按 U16 最多能表示 65535，这份点表把它的有效值划在 500～2000 kW。

同一页的半母线偏差保护值是 S16，同样读 1 个寄存器。S16 把最高位当作符号，所以 `FF FF` 在 `u16` 里是 65535，在 `i16` 里是 −1：

```rust
let power = u16::from_be_bytes([0x03, 0xE8]); // 1000，单位 1 kW
let delta = i16::from_be_bytes([0xFF, 0xFF]); // -1
```

`from_be_bytes` 就是高字节在前。U32、S32、F32 要连续读 2 个寄存器。哪一个寄存器在前，看厂商对字序的约定，Modbus 没有规定。
