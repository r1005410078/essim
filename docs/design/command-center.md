# 顶部检索的前端基础

基础重构后已接入顶部检索、公共命令弹层、键盘入口与会话内文档历史；实现与当前验收边界见[实施记录](../test-records/2026-10-23-command-center-ui.md)。

## 资源文件检索

`ResourceSearchIndex` 使用当前导航目录和内置文档的稳定身份，覆盖采集模型、模拟器、Unit、设备和文档。仅检索名称与目录路径，不读取磁盘任意文件、点表正文或运行值。同名资源不合并；同一目标的设备引用路径与模拟器路径去重，优先保留首次出现的路径。

支持中文、英文大小写、拼音全拼前缀／片段、首字母和空格分词查询。名称匹配优先于目录路径匹配，默认返回最多100项。重命名、删除、路径或Unit变更后更新索引，目录元数据不变时复用拼音结果。拼音按 `pinyin-pro` 默认词语读音生成，不保证任意多音字读法或任意全拼／首字母交错输入；不引入自制拼音字典。

`pinyin-pro` 固定3.29.5、MIT许可。拼音库及索引按首次资源查询动态加载。`searchResources(query)`返回Promise，检索弹层处理失效响应与加载状态。

## 命令模式

借鉴 [VS Code命令注册与执行机制](https://code.visualstudio.com/api/extension-guides/command)，使用项目内的轻量 `CommandRegistry`，不安装VS Code扩展宿主或插件系统。

- 每个命令有稳定ID、标题、可选分类与关键词、可用条件、执行回调。
- `register`拒绝重复ID并返回注销函数；`list`只检索元数据，不执行命令，保留不可用状态。
- `execute`按ID查找，并在执行时再次检查可用条件；同步或异步错误交给调用层处理。
- 命令定义不依赖React、DOM或Tauri。App作为组装层将命令接到既有新建弹框、打开文档和Dockview工具页；原有菜单的新建与工具入口也通过相同命令路由。
- 当前注册新建模型／模拟器／设备、打开批量任务／运行资源／Modbus指南、保存当前配置，以及左／右／底部布局开关，共十条命令。保存复用既有保存入口，在命令弹层退出后请求动画帧执行，不冒充后端保存已完成。应用和启停未命令化，不宣称全部菜单均已迁移。
- 创建能力通过当前工作台服务状态在执行时读取，禁用命令不会打开创建弹框。

`parseQuickQuery`识别前导 `>`：有此前缀进入命令模式，否则进入资源模式。顶部UI分别消费 `searchResources`、`searchCommands`、`executeCommand`，资源结果沿既有 `open(Target)`打开。

## 交互与验证边界

顶部已提供资源／命令两模式、方向键与Enter、Esc焦点恢复；Ctrl/Cmd+K或Ctrl/Cmd+P打开资源，Ctrl/Cmd+Shift+P或F1打开命令。弹框打开或IME组合时不抢占全局快捷键。浏览器交互已检查，macOS已检查原生检索、Esc焦点恢复及缩放；自动化工具恢复最小化窗口时超时，拖动位置、最小化恢复和退出保护尚待补验。Windows/Linux仍待目标平台验收。后续命令面板必须遵循项目公共弹框规范，不另造原生dialog或遮罩框架。顶部空白区拖动与检索输入区必须分开。现有保存快捷键与协议运行逻辑保持原流程。
