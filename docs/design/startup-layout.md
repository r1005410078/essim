# 首开窗口与初始布局

首开目标为1280×800逻辑像素，正常最小尺寸继续为900×600。首次显示前，由Tauri组装层读取当前显示器的工作区（无当前显示器时回退主显示器），按缩放因子转换为逻辑尺寸。若工作区不足，窗口缩小；每个方向预留64逻辑像素，用于窗口装饰与屏幕边缘。再按窗口外框在工作区内居中，支持副屏负坐标。

窗口配置先隐藏，完成初始边界设置与核心组装后显示，避免先以过大的旧尺寸出现再跳动。若读取或设置边界失败，记录错误并继续显示配置窗口，不因尺寸优化而留下隐藏进程。极小工作区下，最小尺寸同步限制到实际首开尺寸。

`initialWorkbenchLayout`只在Dockview创建时计算一次：

| 区域 | 初始占比 | 初始尺寸范围 |
| --- | --- | --- |
| 导航 | 可用宽度18% | 180～248px |
| 属性 | 可用宽度22% | 220～300px |
| 底部输出 | 可用高度26% | 208～240px |

尺寸按4px取整；Dockview在这些布局参数内处理间距与实际内容尺寸。中央区使用余下空间，底部仍默认展开并选中通信报文。后续移动、缩放、最大化及用户拖动分隔线由原生窗口和Dockview处理，不重复套用首屏比例，也未新增窗口位置持久化。

原生边界适配在`workbench/src-tauri/src/initial_window.rs`，不进入仿真核心或业务组件；前端比例在`workbench/src/features/workspace/initialLayout.ts`。界面插画、协议语义与会话保存规则不随此次调整改变。
