# M06 固定范围与固定线程调度组件

日期：2026-10-20。承接[分组创建与原生验证](2026-10-19-m06-orchestration.md)，关联[任务3.3／3.4](../../openspec/changes/implement-modbus-multi-instance-orchestration/tasks.md)。本轮是后端组件及受控测试，不是工作台真实批量应用／启停交付。

## 实现范围

- `core/application/commands/batch_targets.rs`：显式选中端点、递归文件夹、明确全部端点；选中范围去重并保持首次出现顺序，文件夹／全部按当前目录顺序固定。仅接收稳定端点身份，不接受Unit或点表选区。空范围、缺失对象、循环目录、超过1024目标及非法并发拒绝。
- `BatchRequest`缺省并发4，可设1～8。全部范围使用显式`{"kind":"all"}`；多余`ids`等字段拒绝，防止含糊输入被解析为全部范围。该分支曾在回归中发现Serde单元变体忽略未知字段，已改为严格的空结构变体并保留失败用例。
- `BatchPlan`保存固定ID及相关内容，后续新增、移动或删除文件夹不重新解析范围。执行前按项复核：删除目标单独报错；应用核对保存端点、源模型及原应用定义；启动核对应用快照，源模型的后续保存不替代已应用内容；停止不因点值或源模型变化而失效。运行值和质量变化不参与定义比较。
- 相同当前模型内容只保留一份`Arc`比较副本，不复制运行值。不同Unit已应用内容可以不同，即使模型ID相同也分别保留其实际内容。该暂存仅为当前任务内容复核，不是历史版本管理；运行模型全局共享仍属任务4.6。
- `queries/batch_plan.rs`只输出端点身份、名称、角色、单元数、已应用标志及任务参数，不发送模型点表。`Workspace::prepare_batch`和`revalidate_batch`借用当前投影，不通过完整工作区查询获取深复制目录。
- `infrastructure/batch_runner.rs`创建8个固定线程，一次只接受一个活动任务；按本次并发数领取，其余等待条件变量。清单数量／流式序列化字节在提交前限制，不按目标数、慢项或panic创建替补线程。
- 各操作分别提供观察等待阈值`WaitLimits`。查询或调度恢复时将等待超时项标为未确认；实际执行函数未结束前保留任务槽。取消只取消未领取项；一项失败不停止其他项。适配器panic无法证明动作结束，保留未确认槽而不宣称失败已完成。
- `request_shutdown`只停止领取及取消未开始项，不宣称资源释放成功；销毁等待已开始的执行函数实际返回。控制／查询不持有执行函数的网络或磁盘等待锁。

## 分层与调用

`BatchRequest.prepare`／`Workspace::prepare_batch` → 固定`BatchPlan` → `BatchRunner.submit` → `BatchService`处理Start／Claim → `BatchTask`转换 → `BatchEvent` → `BatchProjectionListener`。

固定工作线程取得条目后调用`BatchExecutor.execute(plan, endpoint)`；适配器实际返回后才交付Complete，查询经同一服务读取有界结果。执行端口必须在公共端点门内复核计划并等待真实完成；当前仅装配测试适配器，尚未将该组件接到真实TCP／RTU生命周期。

新增6项固定线程测试：

1. 12条目、并发2，两个受控执行函数等待完成信号；查询后两项未确认仍占2槽、其余10项等待，第二任务拒绝。取消后10项取消未执行，原2项继续，完成信号到达后才结算。
2. 100个受控条目、并发4，复用固定线程，记录执行函数峰值不超过4及实际使用线程不超过8；1项注入失败、99项成功。后续任务复用同一线程集合。这里不是100个真实TCP端点，也不是吞吐测量。
3. 清单数／字节超限在执行前拒绝，执行次数0，不创建活动任务。
4. 并发8时真实阻塞8个受控执行函数，第9项等待。退出请求取消第9项，销毁等待前8项完成信号后返回。
5. 注入适配器panic，条目未确认、槽保留，不领取下一项或创建替补线程，第二任务拒绝。
6. 两个线程同时提交任务，只有一个进入活动状态，另一个得到BATCH_BUSY。

所有等待使用受控信号与有限测试期限；没有用固定睡眠推断协议动作完成。环境沿用[本机基线](assets/m06/environment.json)，debug构建、离线依赖。
