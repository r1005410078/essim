# M04 RTU从站首批软件验收

日期：2026-10-19。环境：macOS 26.5.2、Apple Silicon、libmodbus 3.2.0、独立PyModbus 3.11.3／pyserial 3.5。该阶段补齐正式工作台RTU从站运行路径，保留单串口单站限制。

## 软件互操作

脚本：`scripts/verify_rtu_slave_runtime.py`，独立PyModbus主站通过两个PTY及透明转发连接正式无界面运行服务。一个Unit，四区模型：基础点、100～103范围内coil／holding测试点、holding[200]只读点；这些地址均是测试约定。

[原始摘要](assets/m04-rtu/interop.json)记录如下通过场景：

- 基础FC01/02/03/04/05/06/0F/10实际读写；四点批量写全部可被运行查询及独立读取观察。
- 未定义地址及外部只读点被异常02拒绝，原值不变。
- 本地置数后独立主站可读取；含不存在点的本地批次整批拒绝，合法点也不改变。
- 08/0000回送与11服务器标识成功；07及08清零请求返回异常01。
- 广播06合法写入但不响应；广播读、非本站写、错误CRC和短帧不执行、不响应；随后正常请求成功。
- 分段请求与合并请求，实际返回完整CRC响应。
- 停止／重开保留值，恢复初值后独立读回正确。

资源测试使用serialport公开PTY pair接口：串口别名重复启动失败且原实例继续应答，应用运行配置先释放并保持停止，其他端点能打开；删除运行端点后可再次打开。不存在路径返回失败，驱动断开被报告为失败；不自动循环重开。

- [x] 用户确认启动后完成原生核心流程。新建模型含holding[0] u16初值0，RTU从站配置为Unit 1、19200/N/8/1、测试PTY `/dev/ttys004`（本次临时路径）。应用后打开串口，状态“串口应答中”。独立PyModbus读到0，写42后读回42，运行表同步显示42。界面置数55并提交后独立读取55；复位当前Unit后独立读取0。通信面板区分实际RX、TX准备及本机驱动写出；点击准备响应正确解析holding[0]、原始值0与CRC。关闭后状态“已停止”，独立pyserial进程重新打开同一PTY成功，确认释放。测试客户端及PTY已清理，窗口保留已停止状态。

- [ ] 其他串行诊断服务：07状态位、其他08子功能、0B/0C统计与协议日志，尚未实现。

RTU从站使用libmodbus RTU上下文直接生成基础响应及CRC，不把TCP帧改写后冒充RTU。回送通过上游原始发送API补CRC。11返回上游模拟身份0xB4、运行标志FF及LMB版本字符串，不是实际设备身份或动作状态。07／其他08／0B／0C统一异常01，不提供虚构计数。

观测区分received、prepared及driverWritten：最后者仅表示完整响应交给本机驱动，不保证远端接收或总线发送完成。CRC错／短帧保留实际观测但不进入映射；非本站与广播读静默。串口读写有界，发送未完成时停止会取消剩余输出并保留结果不确定标记；无重发。

软件短帧清理使用20ms安静观察边界；操作系统可能合并字节读取，软件场景不证明物理字符间隔合规。记录遵循已有完整性优先策略，写入记录失败停止该端点；运行值仍由固定线程独占。串口独占不能驱逐外部已持有句柄，未知路径别名及驱动行为仍有原有边界。

此记录不是吞吐量、长稳、完整标准符合性或真实EMS验收。M04总体仍包含未验完整TCP规模、后续诊断及真实RTU硬件范围，不勾选总项。

## 复现

```sh
cargo build -p essim-infrastructure --features tcp-runtime,vendored --example tcp_slave --offline
python scripts/verify_rtu_slave_runtime.py
cargo test -p essim-infrastructure --features tcp-runtime,vendored --test rtu_slave --offline
```

Python依赖PyModbus 3.11.3、pyserial 3.5；脚本仅操作自身创建的PTY、进程和临时记录目录，并在结束时清理。

依据：[libmodbus应答API](https://libmodbus.org/reference/modbus_reply/)、[Modbus应用协议V1.1b3](https://www.modbus.org/file/secure/modbusprotocolspecification.pdf)及仓库固定3.2.0源码。基础8功能由上游处理，产品侧负责映射完整性、权限及生命周期。
