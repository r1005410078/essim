# M05 RTU 主站软件验收记录

日期：2026-10-19。环境：macOS 26.5.2、Apple Silicon；正式 Rust 主站运行时、libmodbus 3.2.0；独立服务端 PyModbus 3.11.3、pyserial 3.5。

## 已完成的验证

- `cargo test --workspace --offline`：139 个测试通过，包含文档测试，无失败。覆盖串口别名占用与释放、诊断白名单、异常响应、错误 CRC、错误回显及既有 TCP 回归。
- 前端：18 个测试文件、89 个测试通过，包含 RTU 请求、响应、诊断、CRC 和短帧解析。
- `python3 scripts/bundle_macos.py static`：构建成功；测试副本已重新生成并通过 ad-hoc 签名校验。
- `cargo doc` 对 core、infrastructure、libmodbus 封装生成成功。
- 独立 PTY 互操作脚本：`scripts/verify_rtu_master_runtime.py` 通过。原始摘要见 [interop.json](assets/m05-rtu/interop.json)。

PTY 场景有两个有效 Unit（1、2），每个 16 点，另有不存在的 Unit 3。覆盖 FC01/02/03/04/05/06/0F/10，以及手动 FC07/08/0B/0C/11。诊断响应原始字节保存在摘要中。受限子功能与不支持异常由封装测试验证，未声称所有实际设备都支持这些诊断。

故障验证包括错误 CRC、短帧、迟到响应、缺失 Unit、写确认超时、通道断开后按原配置路径重开、显式关闭后重开。写超时未自动重发，未执行的后续写项保持未执行；独立读取确认远端实际写入值。停止采集无积压补发，单 Unit 失败不阻断健康 Unit。

## 复现

```sh
cargo build -p essim-infrastructure --features tcp-runtime,vendored --example tcp_master --offline
python scripts/verify_rtu_master_runtime.py
```

Python 环境需安装 PyModbus 3.11.3 与 pyserial 3.5。本次使用独立临时虚拟环境 `/tmp/essim-rtu-env`，未改变系统 Python。测试会创建 PTY 并启动本地独立服务端，结束时释放资源。

此记录为功能场景测试，不是吞吐量或长稳测试。串口独占可拒绝进程内已识别别名及之后的非特权系统打开，不能驱逐外部程序已经持有的串口。RTU 没有事务 ID，隔离窗口之外的同 Unit／功能码迟到响应仍存在固有歧义；没有承诺任意延迟下绝对关联。TX 观测表示发送准备，不表示远端接收确认。M05 总项保持未验收状态。
