## 实现边界

`src → 原生构建`、`sys → 链接与原始 FFI`、`rs → 安全 API`；三包不依赖 core、Tauri、Tokio。默认 vendored 静态，动态必须显式指定自建前缀，不搜索系统库。平台、模式、来源及库／头文件摘要不匹配拒绝。

安全层首批覆盖固定标准104应用参数、ASDU RAII、无时标单点／短浮点、总召回调读取与响应、无线程服务端 tick／stop、受控低优先级上送。C句柄线程绑定，借用连接不逃逸；所有控制业务仍由调用方实现。

## 已执行检查

- `cargo test --workspace --offline`：63组测试结果，共297项测试／文档用例通过，零失败、零忽略。
- 三包静态 `cargo test`：10项测试及2项文档测试通过。
- 显式动态 `cargo test -p lib60870-sys -p lib60870-rs --no-default-features`：7项测试及2项文档测试通过，使用独立 `target/lib60870-dynamic`。
- `cargo clippy -p lib60870-src -p lib60870-sys -p lib60870-rs --all-targets --offline -- -D warnings` 通过。
- 三包 `cargo doc --no-deps --offline` 及格式检查通过。
- `otool -L`：静态示例仅依赖系统库；动态示例依赖 `@rpath/liblib60870.dylib`，证明两种实际链接模式不同。
- 新增示例使用 `build-60870-shared`／`iec104-server` 独立目标名，解决与现有 Modbus 示例的输出名冲突。
- 静态与动态示例均由独立 Python 字节级客户端验证通过：STARTDT、分段总召、ACT_CON、M_ME_NC_1、ACT_TERM、合并 TESTFR／STOPDT、quit／端口重绑。

以下数据均为教学约定：CA=47、IOA=100、值12.5。实际解析的三条 ASDU：

```text
64 01 07 00 2f 00 00 00 00 14
0d 01 14 00 2f 00 64 00 00 00 00 48 41 00
64 01 0a 00 2f 00 00 00 00 14
```

行为测试还覆盖混合类型拒绝且无追加、序列 IOA、质量与有限浮点、容量上限、构建来源冲突、错误目标、产物／头文件篡改、端口冲突、Drop释放、回调panic转错误和队列满拒绝。

首次网络测试被沙箱拒绝本地监听，未把该次失败算作协议失败或通过；在允许回环监听的环境重跑。回调panic用例最初用固定次数tick后同步等待握手，暴露测试驱动不足；改为独立客户端和持续tick后通过。真实总召和回调故障均通过实际TCP触发。

## 追加：可直接运行的 Rust Examples

新增 `lib60870-rs/examples/smoke.rs`，Cargo 目标名 `iec104-smoke`，只使用公开安全 API 和标准库，无新增依赖。服务端与 C 句柄在主线程，原始字节客户端在独立线程；不启动工作台。

本机分别执行以下命令，两种模式均输出11条 `PASS` 并以退出码0结束：

```sh
cargo run -p lib60870-rs --example iec104-smoke --offline
LIB60870_DIR=/absolute/generated/install CARGO_TARGET_DIR=target/lib60870-dynamic \
  cargo run -p lib60870-rs --example iec104-smoke --no-default-features --offline
```

动态前缀复用本记录上文已验证的自建产物，实际运行时使用绝对路径。验证 STARTDT、分段总召、ACT_CON、单点 true、遥测12.5、ACT_TERM、自发单点 false、自发遥测14.0、不支持的分组总召负确认、TESTFR、STOPDT、释放后重绑；总召响应和上送载荷均与独立常量字节比较。单点 IOA=200，其他地址延续上文教学约定。

追加示例后 `cargo clippy -p lib60870-rs --all-targets --offline -- -D warnings` 通过。上文297项工作区测试是三包初次实现的检查记录，本次新增示例未重新运行整个工作区测试。该示例不是通用104客户端，也不增加完整标准符合性或独立成熟协议栈互操作证据。
