# RTU 串口从站软件验收（2026-10-15）

## 环境与覆盖边界

- macOS 26.4.1 (25E253)，arm64 / aarch64-apple-darwin；Rust 1.96.0。
- 固定 libmodbus 3.2.0，无 vendor 修改；默认 vendored 静态和显式自行编译动态两种模式。
- 独立客户端：PyModbus 3.11.3、pyserial 3.5；临时环境 `/private/tmp/essim-pymodbus-314`。
- 软件链路：两对 Unix PTY，由 `scripts/verify_rtu.py` 转发 master 端，ESSim 与 PyModbus 分别打开 slave 端。
- 实测参数：19200/N/8/2，站号 7，请求/忽略确认等待 50ms，字节间等待 2ms，一个 SOC 点。

地址 100、初值 650、更新 700 和倍率 0.1 均为教学约定。本轮没有真实串口或 RS-485 适配器，接线、方向控制、驱动、电气与时序任务 9.9 保持未完成；Linux/Windows、其他参数组合、主站、多站总线及性能规模不在实测结论内。

## 实现

`libmodbus-sys` 增加官方 RTU API 与常量、编译/链接探针；`libmodbus-rs` 增加不可变 RtuConfig、RtuContext 和独立 RtuRequest，复用四区 Mapping。配置支持 9600/19200/38400/57600/115200、8 数据位、N/E/O、1/2 停止位、站号 1–247；接收等待限 10–100ms、字节间等待限 1–2ms，以限制单次库接收的阻塞预算。支持列表只代表软件接受范围，不证明各组合在真实驱动工作。

RTU context 由 worker 创建和独占；C 打开串口，RAII 按实际获取状态 close → free。固定 Unix 上游以 O_NONBLOCK 打开，默认 RTS_NONE；封装不开启无限链路重试、自动重连或自定义 RTS。串口发送受阻返回错误。RTU 与 TCP 请求不允许混用，receive 的 0 返回区分为 None。CRC 和接收分帧由上游库处理，私有请求再校验功能码结构。

广播正常应答沿用上游静默行为；异常应答在 Rust 侧拦截，因为上游 modbus_reply_exception 会直接发送。通用 Mapping 可处理合法广播写入，ESSim 的 SOC 策略在调用会改映射的 reply 前拒绝写入，对所有广播静默忽略、不改变 SOC。

core 的 Communication 区分 TCP 与 RTU；配置仅停止后整组应用，失败不半应用。RTU SOC 不与 TCP 单元共享。统一客户端与 Tauri DTO 使用带 transport 的通信类型；前端 UnitSocSheets 以 transport + Unit ID 隔离草稿。无界面与桌面使用同一应用服务。

RTU 日志中的 RX 来自实际 receive（包含 CRC），TX 只记写入字节数和结果；本轮未在产品中捕获原始 TX，以下实际 TX/RX 由独立客户端取得，未用构造报文伪装抓包。

## 自动检查

两种模式分别执行：

```sh
cargo test --workspace --offline
LIBMODBUS_DIR="$PWD/target/libmodbus-shared/aarch64-apple-darwin-Dynamic-debug/install" cargo test --workspace --no-default-features --offline
cargo doc -p libmodbus-rs -p libmodbus-sys -p essim-core -p essim-infrastructure --no-deps --offline
pnpm --filter @essim/workbench test
pnpm --filter @essim/workbench build
openspec validate extract-libmodbus-workspace --strict
```

静态/动态各 31 个 Rust 单元/集成测试及 8 个文档测试通过；前端 11 个测试通过。文档构建、修改的 Rust 文件格式检查、前端构建及 OpenSpec 严格校验通过。Vite 仍提示现有大 chunk，没有在本轮顺手拆包。

新增 RTU 用例先在 API 不存在时失败，再实施。覆盖：非法配置/设备、打开部分失败、打开后失败注入及清理、termios 的规范/回显/信号标志恢复、禁止跨协议与跨线程、四区真实读写、跨字节线圈、正常分段/连续帧、CRC 错误/截断恢复、非本站、广播正常/异常静默、只读 SOC、不影响 TCP 值、停启保留、PTY master 关闭、慢速最长请求及持续错误流量停机。通用库发送队列填满后返回错误且释放在 1s 内；worker 的空闲、半帧、慢帧和持续错误帧停机断言在 1s 内。以上均只约束已验 PTY 场景。

调试中，完整 termios 标志比较受 macOS PTY 动态 EXTPROC 位影响，测试改为验证与串口模式恢复有关的 ICANON/ECHO/ISIG 标志；没有为满足断言改写上游。TCP 回归首次受沙箱端口权限限制，允许本地回环后完整测试通过。

## 桌面闭环

两种模式构建命令：

```sh
pnpm --filter @essim/workbench tauri build --debug --bundles app --config '{"bundle":{"active":true}}'
LIBMODBUS_DIR="$PWD/target/libmodbus-shared/aarch64-apple-darwin-Dynamic-debug/install" pnpm --filter @essim/workbench tauri build --debug --bundles app --config '{"bundle":{"active":true}}' -- --no-default-features
/private/tmp/essim-pymodbus-314/bin/python scripts/verify_rtu.py --desktop
```

本机验证副本位于 target/rtu-static/ESSim.app 和 target/rtu-dynamic/ESSim.app。动态二进制由 otool 确认依赖 @rpath/libmodbus.5.dylib，测试使用本次显式开发前缀；本轮未重新执行随包 dylib 重定位、签名、公证或公开分发验收。

两模式均在系统 WebView 实际选择 RTU、填写脚本提供的路径（本次 /dev/ttys008，属临时路径，不可照抄为真实设备）及站号 7，打开串口；运行中通信方式、路径及参数锁定。PyModbus 输入 650 读回初值；双击运行值草稿，改为 700，Enter 确认，再点 ✓ 应用；PyModbus 输入 700 读回更新值，异常与广播仍符合预期；停止后状态恢复且参数可编辑。静态模式另检查切回 TCP 并整组应用，TCP 原单元配置仍保留。

动态桌面首次编辑操作被 UI 自动化的状态变化检查中断，客户端仍读到 650，使期望 700 的断言失败。随后逐步确认编辑器值、Enter 和应用后读回 700；验证脚本中断关闭 PTY 时，界面报告串口断开，停止后重新打开恢复。该失败没有被写成初次通过。

## 后续硬件与协议边界

上游在收到非本站帧后会等待并忽略对应 confirmation；用例在该有限等待窗口结束后验证恢复，不承诺在窗口内立即接收另一条本站请求。PTY 不验证校验位的真实电气效果、帧间静默、USB 驱动、RS-485 方向切换或真实拔插。首版仅单串口单从站，未增加主站、同串口多站仿真、端口自动枚举、低波特率、自定义 RTS 或磁盘持久化。任务 9.9 因未连接适用硬件而保留未完成，不能归档为全部验收完成。
