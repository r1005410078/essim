## 维护与打勾规则

- 每项分别跟踪“讨论确认、提案、实现、验收”，不能以讨论结束或文档写完代替功能交付。
- 讨论确认：记录用户确认的范围、数据模型、交互和待解决问题。
- 提案：链接对应 OpenSpec 变更，包含可独立实施、验证的任务；一个大类可以拆成多个提案。
- 实现：对应范围的代码及必要文档全部完成后打勾。
- 验收：完成约定检查，链接测试或互操作记录，注明未验证平台、硬件和规模后打勾。
- 总览仅在该类已确认范围全部实现并验收后打勾；部分完成继续保持未勾选，在对应提案中记录具体进展。
- 需求改变时同步调整计划和提案；已完成项重新出现未满足条件时重新打开，保留变更原因和历史证据。
- 每次推进相关功能时同步更新本计划，不自动提交 Git 或归档提案。

### 已确认：采集模型与主从角色（2026-10-15）

- [x] 一个采集模型使用一张点表，包含公共协议字段和主从各自需要的配置字段；不额外建立“公共点库”，不维护主从两套点集合或模型内分别选点配置。
- [x] 同一个点的名称、数据区、零基地址、类型、字序、倍率和单位只定义一次；从站据此建立本地映射，主站据此访问和解释远端数据。
- [x] 角色指模拟器的通信角色，配置在 TCP 从站端点／主站连接或 RTU 通道上，下属单元沿用该角色；同一端点或通道不混放主站和从站。
- [x] 应用模型时按角色使用对应字段：从站使用默认初始值、外部写入权限等，主站使用默认采集周期等。具体字段、实例覆盖和采集分组规则在 M02/M03/M05 细化；运行时选择行手动读取不等于维护另一套模型点集合。
- [x] 多个主从站模拟器可引用同一个采集模型，各实例的运行值独立；引用相同模型不自动建立通信连接，目标端点和站号仍由实例配置。

### 已确认：逻辑从站、共享 TCP 端点与模型引用（2026-10-15）

- [x] 每个逻辑从站拥有稳定且独立的身份、采集模型引用和运行值；多个逻辑从站可以共享一个 TCP 监听端点，由 Unit ID 区分。
- [x] 同一 TCP 端点下，不同 Unit ID 可以引用不同采集模型，也可以复用同一模型；模型引用属于逻辑从站，不绑定到整个监听端点。
- [x] 主站访问多个 Unit ID 时，允许按目标分别关联采集模型，以正确解释各目标的数据；Unit ID 本身不携带模型信息，不自动识别采集表。
- [x] 共享监听资源不合并各逻辑从站的点定义或运行值；修改一个单元的运行值不影响其他单元。

协议依据：[Modbus TCP 实现指南](https://www.modbus.org/docs/Modbus_Messaging_Implementation_Guide_V1_0b.pdf)第23页说明 Unit ID 的网关目标路由用途；[Modbus 应用协议 V1.1b3](https://modbus.org/docs/Modbus_Application_Protocol_V1_1b3.pdf)第7页说明设备应用与寄存器的映射由设备厂商决定。上述规则用于本项目明确按 Unit ID 路由的共享端点，不假定所有直接连接的 TCP 设备都实现多单元路由。

### 已确认：TCP 从站端点与单元管理（2026-10-15）

- [x] TCP 监听端点作为显式、独立的配置对象，集中保存监听 IP 和端口；用户先创建端点，再添加逻辑从站单元。
- [x] 端点提供统一启动／停止；各单元分别启用／禁用，并各自引用采集模型、持有独立运行值。
- [x] 多个单元不各自修改同一监听参数，避免共享端点的配置所有权不清。

会话内停启运行值保留规则见下文；禁用／未知 Unit ID 的请求行为、重复 Unit ID 的校验时机，留到对应配置和从站运行讨论中明确。该决定不等于采用此前“最后一个单元停止自动释放端口”的备选方案，也不自动推广到 RTU 串口。

### 已确认：TCP 主站连接与目标单元（2026-10-15）

- [x] TCP 主站按“连接＋目标单元”组织；连接集中管理目标 IP、端口、连接／断开、超时和重连配置。
- [x] 每条连接下可配置多个目标单元，各自保存 Unit ID、采集模型主站配置引用、采集任务和独立读取结果。
- [x] 连接建立后可仅采集部分目标；暂停一个目标的采集不要求断开整条连接。访问另一个目标 IP 或端口时创建另一条主站连接。

连接内请求的并发／串行策略、实际 socket 生命周期和资源优化在 M05/M06 中细化；RTU 通道组织见下文，不直接套用 TCP 连接模型。

### 已确认：模型保存与配置生效（2026-10-16 修订）

- [x] 每个模型仅一份当前已保存配置；保存覆盖同一稳定ID，单元引用模型ID，不提供版本列表、选版、升级、回滚或期望版本。
- [x] 编辑草稿、已保存配置和已应用快照分开，保存不自动应用；界面仅显示未保存／已保存、未应用／待应用／已应用。
- [x] 应用前整组校验，失败保留原应用和运行值；共享端点的停止边界保留。
- [x] 运行值修改与模型结构修改分开，运行记录使用自包含模型快照。

### 已确认：会话内运行值、配置更新与复位（2026-10-15）

- [x] 同一次应用会话中，从站停止后重新启动保留本地运行值；主站保留最近读取结果，但标记未采集／过期，成功读取后再更新有效状态。
- [x] 从站应用模型当前配置时，以稳定点 ID 匹配：类型兼容的点保留原始运行值，名称或地址变化不自动重置；新增点使用新配置初始值，删除点移除对应实例运行值。
- [x] 类型不兼容时在应用前提示并要求明确选择恢复初始值，不静默截断；具体类型兼容判定在 M02 中定义。
- [x] 倍率变化时首版保留原始值，按新倍率计算工程值，并在应用预览中提示显示值变化。
- [x] 主站应用新版本后，映射改变的点清除有效状态，等待重新读取，不将旧结果当作新映射的有效数据。
- [x] 显式复位与停启分开：从站恢复当前应用配置的初始值；主站清空读取结果和待写草稿，不自动向远端写值。

以上仅约定会话内行为；退出软件后是否恢复运行值、运行中复位与采集／在途请求的协调规则，分别在 M08 和对应运行提案中细化。

### 已确认：RTU 通道与首版范围（2026-10-15）

- [x] 串口作为独立 RTU 通道，集中管理路径、波特率、校验位等参数及打开／关闭；同一物理串口在本程序中只允许一个运行通道拥有。
- [x] RTU 主站通道下允许多个目标站号，各自引用采集模型主站配置并保存独立读取结果；通道统一调度请求，暂停单个目标不关闭整个串口。
- [x] RTU 从站首版一个串口通道模拟一个站号并引用一个采集模型；多个从站分别使用不同串口。单串口多站号列为后续扩展，先验证库接入方式、总线时序和硬件行为，不直接照搬 TCP 多单元实现。
- [x] 主从互测使用不同串口或虚拟串口对，不让两个运行通道争用同一串口。

### 已确认：设备与协议模拟器的可选关联（2026-10-15）

- [x] 设备表示业务对象，例如 PCS-01，可以是模拟设备，不要求存在对应真实硬件；设备身份与协议通信角色分开建模。
- [x] 协议模拟器可独立创建、配置和运行，不强制先创建设备；也可从设备下添加并关联协议模拟器。
- [x] 一台设备可关联多个协议模拟器；一个协议模拟器首版可不关联设备，关联时只归属一台设备。
- [x] 设备身份、3D 外观和空间位置归设备；角色、采集模型引用和协议映射归具体协议实例，TCP 端点／连接和 RTU 通道按此前确认的规则管理通信资源。共享监听端点不代表多个逻辑从站归属同一设备。
- [x] 关联设备不自动修改寄存器值，不自动增加 PCS 控制或物理行为；多个协议实例共享设备业务状态须通过明确的点绑定，不能因关联同一设备而直接共享全部运行值。

### 已确认：仿真历史与回放需求（2026-10-15）

- [x] 需要保存完整事件历史，并支持回放一次仿真过程；不能仅保留实时通知或有界界面日志。
- [x] 首版范围包括完整录制、历史查看和离线状态回放；支持按时间重现状态和报文，不重新执行仿真或向外部设备重发请求。
- [x] 离线回放不打开真实通信连接，使用独立回放状态，不覆盖正在运行的实例；点表、拓扑和3D按各自交付阶段接入回放展示。
- [x] 以一次仿真运行为记录和状态重建边界，保存起始配置、实际应用的模型版本、初始运行值、状态变化事件、实际通信记录及用于跳转的状态检查点；不要求整个软件的 CRUD 全部采用事件溯源。
- [x] 采用 CQRS 区分执行操作的命令侧与展示状态的查询侧，回放依据已记录事实重建状态；记录须区分请求提交、执行确认和结果未知，不能把发送成功当作远端执行成功。
- [x] 界面通知可以批量合并；用于回放的持久化事件历史不能静默丢失，不能以有界界面日志代替完整录制。

### 已确定：字节序与字序默认规则（2026-10-16）

- [x] 字节序可选每个16位寄存器内高字节／低字节在前；字序可选多个16位寄存器按高字／低字在前。64位低字在前为四个16位字整体倒序，首版不支持任意字排列。

- [x] 默认不交换字节或字序；允许按设备资料修改。字节交换属于应用数值映射，不改变Modbus报文中单个寄存器高字节先发送的规则。

## M04 Modbus 从站运行

### 已确认：TCP规模与客户端连接上限（2026-10-18）

- 设计目标约1000个TCP端点同时运行，每端点约10个Unit，合计约10000个Unit；这是待实测目标，不是已验证容量。
- 同一TCP端点允许多个主站同时连接；每端点默认最多10个主站连接，上限允许配置。
- 达到该端点连接上限时拒绝新连接，保持现有连接。
- 所有端点均达到默认上限时约有10000条客户端连接；这是容量规划边界，不代表典型负载或验收通过。
- 每Unit约1000～100000个点，大部分约10000个点。按约10000个Unit均配置10000点计算，典型规划总量约1亿个点；不能将所有Unit均达到单Unit上限视为已确认的同时负载。
- 点定义数量不等于Modbus地址占用量；不同数据区及多寄存器类型的可映射性须在提案中依据协议和模型校验确定，不因规模目标放宽地址规则。
- 大量Unit复用少数几套采集模型；设计时共享相同已应用内容的不可变模型定义，每Unit运行值独立。模型保存不得修改仍被运行实例引用的已应用快照；具体共享及内存布局待提案确定，当前实现不据此宣称已完成规模优化。
- 典型实际连接数、请求频率、延迟目标、全局资源上限及过载策略仍待讨论。线程与I/O方案须结合现有库能力及实测确定，不在本次确认中固定实现。

### 已确认：全量读取与本地运行值修改（2026-10-18）

- EMS每轮读取Unit全部点；扫描间隔尚不确定，不设已承诺的吞吐或延迟指标。候选压测档位为1秒、5秒、10秒一轮，以及读完立即开始下一轮；具体测试负载及达标条件待提案确定，不表示所有规模均可达到这些周期。
- 从站支持单点修改、选中行批量修改，以及恢复当前已应用模型的初始值；成功提交后，主站后续读取可见新值。
- 本地修改针对运行值，不修改采集模型定义或其他Unit的值。
- 当前Unit内的本地批量修改先整批校验，全部合法才一次原子提交；任意一项非法则整批保持原值，反馈并定位错误行。成功提交前后，主站单次读取不得观察该批修改的中间状态；不承诺跨多个读取请求的快照一致性。
- 本地提交与多个主站写入统一交给同一Unit的运行值所有者，按其接收顺序串行处理；对同一点，后成功提交的值覆盖先成功提交的值。不同连接的发送时间不构成全局顺序保证，具体队列与所有者实现待提案确定。
- 本地编辑草稿不锁住运行值；点击提交后才进入统一排序，不同Unit的运行值保持独立。
- 上述排序不取消点定义的外部写入权限校验。
- 恢复初始值分为“恢复选中点”和“复位当前Unit”：前者只恢复当前Unit选中点，后者恢复该Unit全部点且执行前确认。两者均使用当前已应用模型的初始值，允许运行时执行，进入同一写入队列，并按整批成功或整批不修改处理，不影响其他Unit。
- 此项为M04运行用例的已确认目标，不代表M03既有停止Unit复位接口已支持运行中操作；实施时须通过运行值所有者接入，不能直接修改配置目录代替运行值更新。

### 已确认：启动与配置生效边界（2026-10-18）

- 启动使用当前已应用快照；尚未应用时拒绝启动并提示，不自动保存或应用。
- 有未保存草稿或已保存但未应用的修改时，提示仍使用已应用内容；不得将草稿或当前保存内容混入该次运行。
- 启动成功必须表示实际监听已建立；端口占用等失败须显示具体原因，不以命令已接收代替运行成功。
- 停止后重新启动保留该应用会话的运行值，恢复初始值由独立操作完成。
- TCP真实执行器、启动清理及失败恢复已接入下述子提案并有软件回归；RTU和未覆盖的OS故障场景仍待实施／验证。

### 已确认：停止与在途请求（2026-10-18）

- 点击停止后进入Stopping，停止接受新连接和新操作。
- 已开始处理的请求允许在限定时间内结束；超时后关闭连接，明确标记结果不确定的请求，不把关闭连接解释成写入必然未发生。
- 关闭该端点全部客户端连接，释放监听资源；确认释放后才显示Stopped。释放未确认不能提前报告停止成功。
- 停止只影响当前端点，其他端点继续运行。
- TCP所有者在当前同步处理完成后执行停止，关闭尚未发出的响应并保留不确定标记；真实端口释放已有软件回归。具体边界及未覆盖故障见下述提案与记录，RTU仍待实施。

### 已确认：启动失败与重试（2026-10-18）

- 启动中任一步失败，清理本次已获取的资源，保留配置及运行值，并显示具体错误。
- 用户修正问题后手动重试，不自动循环启动。
- 若资源释放尚未确认，显示清理失败并阻止再次启动，避免重复占用；不能将启动失败视为资源已释放。
- 一个端点启动失败不影响其他端点。
- TCP已接入真实启动、失败清理及手动重试；通用句柄释放未确认、OS资源耗尽等故障仍需专项验收，不能以端口冲突用例代替全部场景。

### 已确认：M04分阶段交付顺序（2026-10-18）

### 已确认方向：增加串行线路诊断（2026-10-18）

用户要求将串行线路功能纳入排障范围，归入RTU子提案，不将串行专用功能直接列为TCP标准功能。

- 纳入范围讨论：0x07读取异常状态、0x08诊断、0x0B通信事件计数、0x0C通信事件日志、0x11服务器标识；各功能及子功能的具体首批支持集合须在RTU提案中明确，不以此声明已全量支持。
- 0x08优先评估回送测试、读取诊断寄存器、查询通信／异常等计数及清零。重启通信和只听模式会改变通信行为，须单独定义状态转换、恢复和验收；仅适用于ASCII的分隔符子功能不纳入RTU。
- 诊断统计来自真实协议接收、处理与发送路径；对库或驱动未暴露的CRC、字符溢出等信息，明确不可观测边界，不生成虚构计数。接入前核实官方库API能力，缺口纳入提案取舍。
- 0x07状态位、0x08诊断寄存器位及0x11身份内容须明确本模拟器定义，不能将其解释成通用设备告警模型。
- 协议通信事件日志与工作台应用事件、可靠运行历史分别建模，不以协议短日志替代完整录制。TCP排障通过工作台观测能力单独确定，不直接套用串口诊断语义。

依据：[Modbus应用协议V1.1b3](https://www.modbus.org/file/secure/modbusprotocolspecification.pdf)第6.7～6.10及6.13节；本次仅更新规划，不代表协议或界面实现完成。

## M05 Modbus 主站运行

### 已确认：TCP主站首阶段（2026-10-19）

- 一个模拟器对应一个目标IPv4／端口，多个Unit共享连接并独立引用已应用模型。连接、开始采集、停止采集及断开分别操作；支持暂停单个目标，不关闭共享连接。
