## 场景与约定

SOC（State of Charge）表示电池荷电状态，可以先理解为剩余电量的百分比。本课用一个模拟 EMS 发起读取，用一个模拟 BMS 回答。

为了学习 Modbus TCP，我们人为约定如下点表。**这个地址、倍率和数据区只属于本课，不是 Modbus 规定的通用 SOC 定义，也不是实际厂商点表。**

| 项目 | 教学约定 |
| --- | --- |
| 数据名称 | SOC |
| 数据区 | 保持寄存器；本教学点由设备模型更新，不允许外部写入 |
| 报文中的起始地址 | 0 |
| 寄存器数量 | 1 |
| 数据类型 | 无符号 16 位整数 |
| 工程值换算 | 原始值 × 0.1% |
| 当前原始值 | 650，即十六进制 `0x028A` |
| 当前工程值 | 65.0% |

寄存器可以先理解为设备里的一个可寻址数据格。Modbus 的一个寄存器有 16 位，也就是两个字节。知道地址和原始值以后，还必须根据点表解释它。

本课 EMS 是 Modbus 客户端，BMS 是 Modbus 服务端，因为前者发起请求，后者回答。这个分工是本课的通信安排，不是所有 EMS/BMS 接口固定的分工。

## 请求：请读地址 0 的一个保持寄存器

十六进制请求：

```text
00 01  00 00  00 06  01  03  00 00  00 01
```

| 字节 | 含义 | 本次值 |
| --- | --- | --- |
| `00 01` | 事务标识，用于匹配请求和响应 | 1 |
| `00 00` | 协议标识 | Modbus 的协议标识为 0 |
| `00 06` | 后续字节长度，包括 Unit ID 和 PDU | 6 字节 |
| `01` | Unit ID | 本课约定 1；服务端接受此值，响应回显。它不是 IP 地址，网关场景下还需要用于下游设备路由 |
| `03` | 功能码 | 读取保持寄存器 |
| `00 00` | 起始地址 | 0 |
| `00 01` | 读取数量 | 1 个寄存器 |

前 7 字节构成 MBAP 头；后面是功能码及其参数，即 PDU。长度字段计数从 Unit ID 开始，所以本请求总长为 `6 + 6 = 12` 字节。这里两个“6”的含义不同：前一个是长度字段之前的字节数，后一个是长度字段的数值。

需要按协议长度从 TCP 字节流中提取完整报文。一次发送不能保证对应服务端的一次读取。

## 响应：这个寄存器的原始值是 650

十六进制响应：

```text
00 01  00 00  00 05  01  03  02  02 8A
```

| 字节 | 含义 | 本次值 |
| --- | --- | --- |
| `00 01` | 对应请求的事务标识 | 1 |
| `00 00` | 协议标识 | 0 |
| `00 05` | 后续字节长度 | 5 字节 |
| `01` | 对应请求的 Unit ID | 1 |
| `03` | 正常响应功能码 | 读取保持寄存器 |
| `02` | 寄存器数据字节数 | 2 字节，不是寄存器数量 |
| `02 8A` | 寄存器内容，高字节在前 | `2 × 256 + 138 = 650` |

最终显示的 `65.0%` 来自：

```text
协议读数 650 × 教学点表倍率 0.1% = SOC 65.0%
```

Modbus 负责读到寄存器内容；点表赋予内容 SOC 的含义。换一份设备点表，地址 0 可能根本不是 SOC。

## 第一轮验证题

先预测，再查看答案：

1. SOC 变成 72.5%，按照本课约定，原始值是多少？响应的数据字节是什么？
2. 响应的 `02` 为什么表示两个字节，而不是两个寄存器？
3. 请求地址改成 1，而设备只定义了地址 0，会发生什么？
4. 如果始终没有响应，能直接断定是地址错误吗？

<details>
<summary>参考答案</summary>

1. 原始值为 725，即 `0x02D5`；数据字节为 `02 D5`。
2. 功能码 03 的响应字段定义为数据字节数，一个 16 位寄存器占两个字节。
3. 在有效请求到达且服务端正常运行的教学模型中，应返回非法数据地址异常。示例完整响应为 `00 01 00 00 00 03 01 83 02`，其中 `83` 是带异常标记的功能码，`02` 是非法数据地址异常码。
4. 不能。未响应可能源于连接问题、设备离线、请求未被接受、响应延迟等。收到明确的协议异常与超时是两类不同证据。

</details>

## 后续代码实验的通过条件
