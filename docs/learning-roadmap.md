# 用 ESSim 学习储能通信协议

产品目标与交付范围见 [项目目标与使用场景](project-goals.md)。本路线包含拓展学习专题，不代表所有专题都属于产品计划。Rust 用于学习实验；产品方案暂定为 Rust + Tauri + React，协议层优先封装成熟 C 库；学习原型与产品实现的覆盖范围分别记录。

## 学习目标

通过这个项目，逐步做到：能读设备协议文档，能解释原始报文，能实现通信两端，能验证多设备行为，能定位通信故障，能接入一份此前没有见过的设备点表。

“掌握”以这些可验证的能力为准。储能设备并没有统一的一套协议；具体支持哪些协议、哪些数据和控制流程，需要看设备、固件版本及项目接口要求。下面是建议的学习顺序，不是所有设备都必须支持的协议清单。

## 先区分三个层次

1. **传输与链路**：数据通过什么方式传递，例如 TCP、串口、CAN 总线。RS-485 是电气接口规范，不能直接等同于 Modbus。
2. **通信规则**：怎样组织报文、发起请求、响应、上报、确认和处理异常，例如 Modbus、IEC 104、MQTT。
3. **设备数据与行为**：地址或标识符对应什么数据，如何换算单位，哪些值能写，控制有什么前提。通常由设备点表、应用协议或标准数据模型描述。

同一种通信协议可以承载不同设备的数据。收到格式正确的报文，不代表已经正确理解数据，更不代表设备已经完成控制动作。

## 储能角色入门

先用下面三个角色构造教学场景，再加入电表、温控和其他辅助设备。

| 角色 | 教学中的职责 | 首批教学数据 |
| --- | --- | --- |
| BMS（电池管理系统） | 监测电池状态、报告限制与告警 | SOC、电压、电流、温度、允许充放电状态 |
| PCS（储能变流器） | 执行交直流功率变换与运行控制 | 工作状态、实际功率、目标功率、故障状态 |
| EMS（能量管理系统） | 获取状态，按策略协调设备 | 数据采集、控制请求、结果确认 |

这些是教学模型的职责安排，真实系统的控制边界与拓扑需要依据设备资料确定。通信客户端/服务端与 BMS/PCS/EMS 身份应分别建模；MQTT 还需要区分设备客户端与消息代理，CAN 通信也不宜强行套用 TCP 的连接角色。

## 分阶段学习与实现

| 阶段 | 学习内容 | ESSim 实验目标 | 通过条件 |
| --- | --- | --- | --- |
| 0：数据基础 | 字节、十六进制、整数、符号、大小端、倍率、单位；储能角色 | 建立教学点表，将原始整数换算为工程值 | 能解释 SOC=65.0% 如何表示为原始值 650，并明确这是点表约定 |
| 1：Modbus TCP 读取 | 客户端/服务端、四类数据区、MBAP、功能码、零起始地址 | 模拟 EMS 读取一个 BMS 的 SOC，打印发送与接收报文 | 能逐字段解释请求与响应，修改 SOC 后能正确读取 |
| 2：写入与异常 | 单寄存器/多寄存器写入、范围校验、协议异常、超时 | 增加教学 PCS 目标功率及读回验证；触发非法地址 | 能区分收到异常响应、没有响应和业务拒绝；不把写入成功等同于功率已达到 |
| 3：多设备 | 独立数据、连接生命周期、事务匹配、并发 | 一个 EMS 连接多个独立 TCP 端点；另做网关 Unit ID 实验 | 各设备数据互不污染，一个设备断线不阻塞其他设备；能说明 IP/端口与 Unit ID 的区别 |
| 4：通信故障 | TCP 字节流分帧、超时、重连、过期响应、重试影响 | 分段送达、合并送达、延迟响应、断连、恢复 | 能处理一次读取只收到半帧、一次收到多帧；能解释控制请求重试的业务后果 |
| 5：Modbus RTU | 站号、串口参数、CRC、帧间隔、共享总线、广播 | 先做字节编解码与虚拟串口实验，再做真实串口验证 | 能解释 TCP 与 RTU 的相同 PDU 及不同封装；明确虚拟串口不能验证全部电气与时序行为 |
| 6：设备点表与 SunSpec | 数据类型、多寄存器字序、比例因子、状态位、标准模型 | 接入一份实际设备点表，再增加 SunSpec 模型实验 | 能按资料解释每个字段及不可用值，不把教学地址当成标准地址 |
| 7：IEC 60870-5-104 | 链路启动、I/S/U 帧、ASDU、传送原因、总召、遥测与遥控 | 模拟控制站和被控站，观察一次总召及控制流程 | 能说明连接建立与数据传输启动的区别，并解释序号、确认及控制结果 |
| 8：CAN 应用通信 | 帧 ID、数据区、周期报文、信号编码、应用协议 | 按明确的教学或厂商应用协议模拟电池状态上报 | 能区分 CAN 帧结构与应用数据定义，能检测报文过期；不把教学 CAN 模型称为通用 BMS 标准 |
| 9：MQTT | 消息代理、发布/订阅、主题、QoS、会话、保留消息、遗嘱 | 多个模拟设备上报到代理，实验断连与重复消息 | 能解释消息送达与业务执行的区别，并处理重复消息与状态过期 |
| 10：IEC 61850 | 标准族、逻辑节点、数据对象、SCL；选定服务与映射 | 先识读模型，再选择一条实际需要的服务链路做互操作 | 能解释信息模型与传输服务的关系，明确实验覆盖的具体部分 |

先完成 0—4，形成最小可用模拟工具；再扩展后续协议。后半段可根据实际设备资料调整顺序。IEC 61850 是一个标准族，需要拆成多个专题，不能用一次简单读写实验代表全面掌握。

## 每一课的固定流程

1. 解释一个概念，指出它解决的通信问题。
2. 给出一个小型储能场景和明确的数据约定。
3. 在编码前预测请求、响应与预期结果。
4. 实现足够支持本课实验的代码，并输出原始报文及字段解释。
5. 改一个参数或注入一个故障，比较预测与实际结果。
6. 用独立实现、参考工具或标准报文验证，避免两端犯同一个错误却互相通过。
7. 回答验证题，记录误解和排障过程，再进入下一课。

教学初期可以手写小范围的编解码来理解字段；随着功能扩大，再评估成熟协议库。代码需要讲清楚每个变化与协议规则的对应关系。

## 网络模拟的边界

应用层延迟、丢弃请求、丢弃响应、主动关闭连接，可以帮助理解超时与恢复，但它们不是 IP 层丢包的等价模拟。TCP 在连接有效时提供有序可靠的字节流，底层丢包通常先表现为重传和延迟。

因此实验记录必须注明注入层次。真实链路丢包、乱序、限速和总线仲裁等验证，应另外采用适合传输方式的网络、总线或硬件工具。分段读取和合并读取实验用于检验分帧逻辑，不是在模拟 TCP 向应用交付乱序字节。

## 官方参考资料

- [Modbus 规范入口](https://www.modbus.org/modbus-specifications)：应用协议、TCP 实现指南、串行线路规范。
- [SunSpec Modbus](https://sunspec.org/modbus/)：标准化 DER 数据模型及储能模型资源；实施时确认所选模型版本与状态。
- [IEC 60870-5-104](https://webstore.iec.ch/en/publication/3746)：远动通信标准的用途与范围。
- [CiA CAN 知识](https://www.can-cia.org/can-knowledge)：CAN 各层与上层协议。
- [OASIS MQTT 5.0 标准](https://docs.oasis-open.org/mqtt/mqtt/v5.0/os/mqtt-v5.0-os.html)：发布/订阅与交付规则。
- [IEC 61850-7-420](https://webstore.iec.ch/en/publication/34384)：涵盖储能等分布式能源的信息模型。

本路线是教学安排，不是认证或标准符合性声明。查阅到的标准目录与摘要不能代替完整规范，后续实施具体条款时应核对相应规范和设备资料。
